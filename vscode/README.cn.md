# ChaLi for VS Code

[English](README.md) · **简体中文**

默认 `run` 与 `build` 的最终产物位于 `.chl` 同级，run 生成的可执行文件也会保留。中间文件使用源码旁 `.chali` 中的独占工作区，Windows 下隐藏，成功或失败结束后清理并删除空目录；既有用户文件保留。显式输出与保留选项继续可用。VSCode 默认同样输出到源码旁；static VSIX 不提供 `Chali › Build: Llvm Path`，external 必须配置，构建和运行均传递 `--llvm`。

扩展调用编译器的原生语言服务 `chali lsp`。VSIX 内嵌编译器，编辑器语言服务不需要 Python；仓库构建和验证工具仍使用 Python。编译器与扩展版本均为 1.0.0。

## 编辑

- 诊断来自真实编译器。警告等级支持项目配置、命令行覆盖和逐行抑制；安全修复插入抑制，不删除声明及其初始化副作用。
- 悬停、补全、参数提示及可选类型内联提示显示声明和可用的推断类型。语义着色与宏体专用 TextMate 规则配合使用。
- 跳转定义打开工程声明或内嵌标准库源码，标准库文档只读；没有语言声明的内建操作不会伪造函数体。
- 引用与重命名在当前模块图中区分同名遮蔽，包含已打开的未保存文件。歧义、冲突、宏模板不明确及标准库修改会被拒绝。返回编辑前核对版本和内容指纹，不锁定外部文件写入者。
- 代码操作可补齐直接列出的非泛型接口方法，或为缺分支的 match 添加兜底。生成体为需要自行实现的 `TODO panic`；候选先通过隔离的编译器检查，不支持或仍有错误时不提供。
- 宏预览展示实际 AST、卫生绑定、来源／定义／元数据／控制出口及直接效果，可按来源跳转。提供多标签、搜索、折叠、缩放及独立 HTML 导出，不据此断言传递纯度。

## 构建与调试

命令面板提供“ChaLi：选择项目目标”“ChaLi：选择构建输出”“ChaLi：打开项目配置”。配置先作为可撤销编辑留在 TOML 缓冲区，保留注释和多行字符串；构建保存源文件与脏清单后再读取。状态栏显示实际编译器变体、已保存配置与待保存配置。

已登记 Windows x64、Linux x64、Linux ARM64 三个目标，输出支持可执行文件、对象文件及 LLVM IR。生成交叉目标对象不代表目标运行时与部署执行已经验证，详见[工具链说明](../doc/09-toolchain.md)。

运行命令在集成终端执行 checked 原生构建。原生调试通过编译器的 DAP 适配器使用 DWARF 和 GDB/MI，需要匹配的 GDB。源码构建默认使用 O0，`debugMode: "optimized"` 选择保留 DWARF 的 O3／LTO，优化变量只读；详见[原生调试](../doc/43-native-debugging.md)。

静态与外置 LLVM 分别打包。静态变体内嵌 LLVM／LLD 及所需链接资产；外置变体在代码生成时需要适用的 LLVM 工具链。应用额外使用的 C ABI 库按各自约定链接与交付。两种语言服务都不依赖 Python。

## 编译器选择与依赖

依次检查 `chali.path`、内嵌 `bin/`、受支持的工程位置与 PATH，输出通道打印实际路径。服务重启串行执行并等待进程关闭，未保存文档随后重放给新服务。

依赖命令提供下载并锁定、离线校验及打开依赖缓存，在受信任工作区执行，多个工程时选择对应项目。下载的模块和语言服务缓存不进入 VSIX。

## 仓库验证与打包

在本目录执行：

```sh
npm ci
npm test
node tools/package.js --llvm-variant static --compiler 编译器绝对路径 --out dist/发行目录
```

外置包将变体改为 `external`。打包检查清单、实际编译器版本／变体、原生 LSP、扩展交互、宏渲染与高亮、取消及构建输出。测试依赖和工具历史不入包；打包检查不等于整仓全量回归。

真实扩展宿主测试入口为 `npm run test:extension`，调试测试使用 `npm run test:extension -- --debug`（端口 9333，总超时 240 秒）。需要已安装的 VSCode、GDB 和图形会话；可用 `CHALI_VSCODE_EXECUTABLE`、`CHALI_BIN`、`CHALI_GDB` 选择工具。测试覆盖断点值查看、取消、panic 和原生进程清理，详见[原生调试](../doc/43-native-debugging.md)。

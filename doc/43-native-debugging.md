Windows 的线程调试观察缓冲使用 FLS 管理的独立宿主状态；线程退出时撤销目录项并释放快照缓冲，模块卸载前释放槽及剩余状态，避免旧 MinGW 仿真 TLS 先释放存储、后调用 C++ 析构造成失效访问。其他平台继续使用原生 TLS 路径。

`run` 使用 checked 原生构建 编译执行，`build` 默认生成 unchecked 原生产物。原生调试使用真实机器码、DWARF 源码行和帧槽。

## VS Code

安装 ChaLi 扩展与目标平台的 GDB，打开 `.chl` 文件，按 F5 启动原生调试。扩展先执行 checked 原生构建 调试构建，再通过 GDB/MI 提供源码断点、继续、单步进入／越过／跳出、调用栈、参数／局部变量和表达式查看。

Linux 的编辑器宿主使用 Node.js 20.8 或更高版本时，终端采用会话专属抽象套接字，不要求项目挂载点支持套接字文件；旧宿主保留文件端点，临时目录所在文件系统须支持 Unix 本地套接字。Windows 继续使用独立命名管道。两条标准流通道在启动前监听，重启和关闭回收原会话连接。

```json
{
  "type": "chali",
  "request": "launch",
  "name": "ChaLi 原生调试",
  "program": "${file}",
  "cwd": "${fileDirname}",
  "debuggerPath": "gdb",
  "stopOnEntry": false,
  "args": []
}
```

`debuggerPath` 指定 GDB 路径；未设置时依次使用 `CHALI_GDB` 和 PATH 中的 `gdb`。调试器架构应与产物匹配。编译器、原生适配器和 GDB 子进程继承同一工程 `tmp/`；临时原生产物保留在该目录便于复核。断点解析失败会显示未验证及诊断，不回退到运行时。

命令“ChaLi：检查调试环境”核对实际编译器构建信息及 GDB 版本；`chali.debuggerPath` 可设置默认 GDB，单次配置的 `debuggerPath` 优先。Windows GDB 的启动参数编码可能依赖系统代码页，当前 ChaLi 调试产物额外读取带长度的 UTF-8 参数文件，保留空串、中文及非 BMP 字符；正常发布程序仍从进程入口取得参数。

调试构建默认使用 `-O0`，保留原生符号与源码行。需要观察优化后的程序时，使用下述 O3 调试模式。普通发布构建继续默认最高优化、LTO 和死代码消除。

## 开发与 O3 优化调试

`--debug` 使用 O0 开发调试；`--debug-optimized` 同时保留 DWARF／原生符号并使用 LLVM O3 及所选 LTO 模式。三种命令行选项 `--debug`、`--debug-optimized`、`--no-debug` 之间按出现顺序选择，后者覆盖前者。工程 `debug = true` 沿用项目调试开启规则，不会把已经明确选择的 O3 模式降为 O0。

```sh
chali build main.chl --debug --out build/development
chali build main.chl --debug-optimized --out build/optimized
```

VSCode 源码构建配置使用 `"debugMode": "development"`（缺省）或 `"debugMode": "optimized"`。已有产物启动和附加以产物自身的调试目录为准，配置不会重新优化已有二进制。加载 O3 目录后输出明确提示，变量作用域标注 O3。

O3 调试不通过固定基本块地址保留函数，LLVM 可正常内联、传播常量和删除无用代码。调用栈直接保留 GDB／DWARF 给出的内联帧，同一机器位置可以对应多个源码调用帧；不会按相同地址合并源码帧。优化掉的语句可能没有可执行停点，单步顺序也可能不同于源码顺序。

GDB 报告 `<optimized out>` 的变量显示为“已优化：当前位置没有可读值”，不会补造值或通过目标函数重新求值。仍有可读位置的标量沿用真实值和只读表达式。优化模式仅对能唯一对应的源码名字使用静态布局；同一函数中的同名绑定无法唯一对应时，允许显示 GDB 已确认的基础值，但拒绝依赖该绑定的表达式或聚合展开。未知聚合布局明确显示不可用，不把槽位或句柄整数当作聚合内容。优化模式不重建开发模式的 PC 词法／宏私有作用域；需要这些细节时使用 O0。

O3 调试的变量全部只读，`setVariable` 明确拒绝，因为原帧槽可能已经消失或复用。查看仍受暂停代次和读取预算约束，不执行用户函数。调试安全点与快照发布仍存在，因此 O0 或 O3 调试耗时都不能当作无调试发布程序的性能数据。

当前 O0／O3 真实执行已在 Windows x64 的静态 LLVM 与匹配外置 LLVM 上核对，分别覆盖 malloc／pool、实际内联栈与反汇编、不可恢复的已优化变量、存活变量表达式及相同运行结果。Linux O3 调试尚无本阶段执行验收。

## 链接符号与源码路径

已有原生对象中的调试信息若在最终链接后保留，可通过 DWARF 查看。用调试模式构建，并通过 `sourceFileMap` 映射其他机器记录的源码路径。缺少本地源码时仍可查看可用符号、指令地址和反汇编。

旧的可执行文件若携带 ChaLi 库目录，适配器会核对符号和实现身份，再使用目录进行类型化查看。身份核对失败时仍可使用 DWARF 和反汇编。

## 工程、已有产物与标准输入

选择“ChaLi：调试项目入口”时，扩展从选定工作区的 `chali.toml` 读取 `main`，使用编译器解析的依赖和原生链接配置。当前文件启动则使用 `program`。多工作区路径相对于该调试配置所属工作区解析，省略 `cwd` 时使用项目根目录或入口所在目录。调试前保存相关源文件和清单；非宿主目标、非可执行输出及无效配置在启动前报告。

已有产物用 `"executable": "${workspaceFolder}/build/app-debug.exe"` 启动，省略 `program`；该模式不会调用编译器，也不会因重启重新构建。使用 `args` 传参，`env` 对象覆盖环境变量，值为 `null` 时删除继承项。源码构建错误直接转为 Problems 的文件、行和列，同一启动只构建一次。

```json
{
  "type": "chali",
  "request": "launch",
  "name": "ChaLi：项目与输入",
  "entry": "project",
  "console": "integratedTerminal",
  "env": { "APP_MODE": "development", "OLD_SETTING": null },
  "args": ["sample file.txt"]
}
```

`integratedTerminal` 使用 VSCode 伪终端按行输入；回车提交，退格编辑，Ctrl+C 请求暂停，Ctrl+D 或 Ctrl+Z 结束标准输入。它连接调试产物的会话专属标准流，输入不进入 GDB/MI；Windows 使用命名管道，Linux 使用本地套接字。标准输出与错误输出在终端合流显示。默认 `internalConsole` 适合无需输入的程序。

集成终端要求当前编译器生成的 `--debug` 产物；任意已有程序仍可用 `internalConsole` 启动。关闭活动终端结束会话，重启创建新连接，不复用上次输入。调试流连接发生在用户初始化之前，正常发布构建没有该调用。此终端提供行输入，不模拟完整系统 TTY 或全屏终端控制。

## 会话控制

构建、配置、运行、暂停和结束是不同状态。断点安装与启动、继续和单步等控制请求按顺序处理；调用栈、变量和表达式只接受当前暂停状态的引用。恢复执行后，旧帧和变量引用失效；迟到的读取结果报告过期，不展示上次暂停的数据。

支持取消调试构建与查询；客户端支持进度显示时，构建进度也可取消。停止或断开会回收该会话的编译器和 GDB 进程树。源码模式重启会重新构建程序并按原始源码位置重装断点，不沿用旧 GDB 的断点编号；构建期间也可以重启。正常退出、取消与重复关闭只发送一次结束事件。

DAP 消息头最多 8 KiB，消息体和单条 MI 记录最多 16 MiB；并发 DAP／MI 请求各最多 256 项。非法长度、截断或错误 JSON 不继续分派。MI 查询默认超时 20 秒；超时和取消后移除请求，迟到响应不能满足后续请求。控制操作一旦交给目标执行，取消不代表撤销已发生的程序行为；状态无法确认时结束会话。

源断点支持条件、命中次数与日志文本：条件按 GDB 原生表达式求值；命中次数只接受正整数，从第 N 次命中起停住；日志断点把 `{表达式}` 插值成文本后输出并自动继续，不向客户端报告暂停。函数断点按源码函数名登记，由调试目录翻译为实际链接名；符号尚未加载时保持待解析，GDB 解析后通过 DAP `breakpoint` 事件更新状态。

单步进入内部标准模块时，适配器会自动结束当前内部帧并继续，直到回到用户源码；用户函数仍按正常单步停住，连续过滤有上限并报告当前内部位置。panic、断言与受检查内存错误在调试构建中停在失败调用现场，适配器报告异常停点、原始消息和最近的用户源码位置；Result::Err 只是普通值，不产生异常停点。原生信号按异常停点报告，并附带最近一个有源码行号的调用帧位置；没有调试信息时保留信号描述。

异常断点提供默认开启的 `runtime` 过滤项，控制 panic、断言和受检查内存错误的现场暂停。取消该项后程序沿原有失败路径退出；重新开启恢复暂停，重启保留选择。原生信号独立于此过滤项；过滤条件与异常路径选项尚不支持，非法设置会被拒绝。

List／Map／Set 按静态元素布局展示长度与分页子项，Map 每项展开为 key／value；支持标量、字符串、普通记录及嵌套容器。容器数据在正常执行的源码停点发布阶段复制为只读快照，查看不调用用户方法、不创建语言对象、不恢复执行，也不把容器句柄或快照索引作为内存地址。

单线程容器快照最多 4096 个集合、32768 个值节点、32 层聚合及 2 MiB 表与文本；读取仍受总内存预算约束。已释放、未同步元素借用、发布竞态或预算不足时报告不可用，继续后旧引用失效。调试构建的数值 List 访问走宿主代次检查，发布构建保留快速路径。接口实际类型和闭包捕获见下文；完整引用状态仍待接入。调试专项使用真实 GDB 核对单步、返回位置、旧帧拒绝、重启断点及取消清理：

```sh
python tools/run_module_gates.py debug --chali PATH --random-recheck 1
```

## 产物中的源码映射

调试产物保存版本化的只读目录和基本块地址表，包含函数实例显示名、参数声明、变量词法区间及源码行列。适配器按实际机器 PC 选择对应位置；已有产物不需要源文件旁的临时映射文件。泛型函数和局部类型使用完整实参显示，例如 `identity<int64>` 和 `Holder<int64>`，链接符号仍沿用原约定。

读取映射只查询内部符号和原生内存，不执行目标函数。单份目录最多读取 4 MiB，最多 65,536 个位置，每块最多读取 64 KiB；验证版本、指针宽度、字节序、连续地址及所有索引。恢复运行会取消未完成读取；多个查看请求共享加载，但取消单个请求不取消其他查看。旧产物缺少目录或目录损坏时报告原因并沿用 DWARF，不能把回退列号当作精确列。

取引用后的局部或按值参数可能使用独立逻辑存储。调试构建在源码停点前通过已有内存原语刷新原帧展示值，保持实际赋值、宏可变借用和池缓冲区增长后的显示一致。此路径不创建语言对象，不执行用户方法，发布构建没有刷新指令。拥有值、容器及任意原生中断位置仍需按其实际逻辑布局解释，不能把帧中句柄当作机器指针。

## 命令行

```text
chali build app.chl --checked --debug --out build/app-debug
gdb build/app-debug.exe
```

Linux 使用无 `.exe` 后缀的产物。可以设置 `break app.chl:行号`、`run`、`next`、`step`、`finish`、`backtrace`、`info locals` 和 `print 表达式`。`--debug` 保留调试信息，`--checked` 控制数组及指针检查，两者独立。

DWARF 按实际表示区分 int8—int64、uint8—uint64、bool、char、float32 和 float64，并保留声明行、源码列及用户词法块。内层同名变量只在其有效区间遮蔽外层变量，循环变量离开循环后不可见；编译器生成的清理块不额外创建用户名字作用域。当前数值帧将 float32 的已舍入值存为 double，调试描述按实际 64 位槽读取，类型名仍为 float32；调试器的原生 sizeof 因而不能替代语言的 std::core::rawSize。

match 的模式绑定保留声明位置、类型和分支范围；分支退出后，模式变量不再出现在局部变量列表。调试产物同时记录宏的定义、调用和嵌套展开来源。VSCode 在当前宏展开中提供独立的 `$宏名` 变量作用域，内部副本不冒充调用方同名变量，展开结束后隐藏这些内部绑定；普通名称参数生成的调用方声明仍沿用调用方作用域。

调用栈中已核对内存所属上下文的源码帧，其普通记录、数组和指向这些聚合的引用可提供本次暂停专属的内存引用，供 VSCode 的内存查看工具使用。标准 DAP `readMemory` 请求按语言逻辑地址读取静态数据区或活跃堆块，允许负偏移查看同一分配内的数组长度头；越界、已释放或过期的暂停引用会被拒绝。接口及宿主对象编号不自动作为地址提供；原生执行上下文已经切换而目录尚未重新发布时，也会拒绝读取。五版目录另核对该帧进入时保存的堆、数据区及对象表身份；属于其他原生上下文或身份槽不可读的帧不提供类型化堆查看。旧构件缺少帧身份描述时，只允许栈顶源码帧使用活动目录。

真实 C 同步回调已在 malloc／pool 下验证主线程及隔离工作线程：分别读取回调局部记录、数组和调用方堆值，并核对主线程空活动上下文与工作线程独立上下文；继续运行后旧变量引用失效。

一次内存查看共享 4 MiB 读取预算，包含目录与载荷；目录最多保存 65,536 个活跃区间。查看不会调用目标函数、执行用户方法或分配目标对象，也不会恢复目标执行；底层内存仍可通过原始内存引用单独读取。在映射发布中途暂停，或分配／释放后尚未抵达下一个源码停点时，堆查看会报告映射不可用，可以执行到源码停点后重试。不同线程的堆变化也可能保守使旧目录失效。

栈顶源码帧的普通记录、数组、字符串和引用按版本化逻辑布局展示：记录按声明顺序列出字段（嵌套记录按源码字段逐层展开，仍使用真实存储偏移），数组显示长度并按页列出元素，字符串解码为带引号的文本，引用直接展示目标值；载荷枚举、Option 与 Result 按标签显示变体名和载荷字段名，不暴露内部 `__tag`／`__vN_` 槽名，标签无效时报告未知变体。布局文本与运行时 value_text 同格式，由编译器去重登记；适配器只按布局读取目标内存，不调用目标方法、不执行用户代码，也不在查看期间分配语言对象。子项默认每页 100 项、最多 1000 项，读取仍共享 4 MiB 预算；快照不可用时明确显示不可读原因，不提供未经核对的展开引用。

适配器支持标准 DAP `disassemble` 请求：按机器地址返回当前帧附近的指令与符号名，可向前或向后取窗口、支持字节偏移，数量上限 4096；反汇编只读机器码，不恢复目标执行。

编译器只在已经执行过源码语句的基本块之后发布目录，因此函数第一条语句的停点沿用进入函数前最近一次发布；这期间没有分配或释放时仍可读取，否则按映射不可用处理，执行到下一条语句后重试。这样插入的发布调用不会成为函数入口后的第一个源码停点，单步进入仍停在第一条语句。

拥有型聚合和容器的槽值仍是 ChaLi 逻辑句柄，不能把它当成机器 C 指针解引用。命令行 GDB 的 `print` 使用原生表达式；VSCode 的查看表达式使用下述只读 ChaLi 子集。

## 只读表达式

VSCode 的悬停、监视及调试控制台查看要求当前暂停的有效源码帧。支持当前作用域的 ChaLi 名称、普通记录字段（含 `line.start.first`）、聚合引用字段、数组／List 的非负整数索引、元组索引，以及整数、浮点和 bool 字面量。基础运算包括括号、一元 `+ - !`、`+ - * / %`、`< <= > >= == !=` 与短路 `&& ||`。例如 `row.first + values[1700]`、`large > 9007199254740993`。同名绑定按当前帧的真实词法作用域选择，继续后旧帧与展开引用失效。

解析与算术在扩展宿主执行，字段和索引复用当前暂停的只读布局／内存快照；不会把输入拼成 GDB 求值命令，不调用目标函数、不执行用户方法、不修改目标值。聚合结果仍可展开。嵌套普通记录沿源码布局读取；旧构件的展平布局仍转换为保留原偏移的子视图，查看不重新分配目标记录。基础引用在表达式中按被引用值参与算术和比较。名称不可见、索引越界、快照不可读或不支持的类型会明确报错。

整数用精确宿主整数计算，除法向零截断，结果限有符号 64 位下界至无符号 64 位上界；超范围、除零及非有限浮点结果拒绝。混合整数／浮点运算只接受绝对值不超过 `9007199254740991` 的整数，避免隐式精度损失。运算结果不模拟各窄整数类型的溢出。字符串与 char 可按名称／字段查看，但尚不参与此算术和比较子集；不支持函数／方法调用、赋值、自增、自减、强制转换、地址／指针运算和分配表达式，完整解析失败时不读取目标值。

单条表达式限 4096 个字符、512 个词法项、64 层括号／运算递归；字段查询每次最多 1000 项，数组和 List 按所求索引直接取一项，仍受共享内存预算约束。基础变量修改见下文；断点条件和日志插值继续使用前文说明的 GDB 原生语法。

源码级调试需要源码文件仍在记录的位置。调试适配器使用现有编译器与工具链生成机器码；不需要安装单独的运行时，也不把运行时函数值强转成机器函数指针。

## 基础变量修改

VSCode 局部变量与参数视图支持对当前作用域的可变基础绑定执行“设置值”。支持 `int8/16/32/64`、`uint8/16/32/64`、`float32/64`、`bool` 和单字节 `char`；整数检查目标类型范围，bool 不接受数值替代，float32 先按源类型舍入再写入实际 double 帧槽。char 使用单字符单引号或 JSON 字符串，例如 `'Z'`、`'\n'`。其他数值接受字面量及其基础运算，不接受名称、函数调用或原生 GDB 表达式。

编译器在调试目录中独立登记真实帧槽类型；写入前核对当前作用域、可变性、GDB 当前值类型和可取址性。窄整数完整更新八字节实际槽并按符号扩展，避免展示值已变而运行时仍读取旧高位。修改不恢复执行或调用目标函数。已修改后的迟到读取及旧聚合／内存引用失效；源码帧与局部作用域继续有效，可重新读取当前值。支持标准 DAP `invalidated` 事件的客户端收到变量刷新通知。发送写入后取消请求不保证撤销已发生的写入。

基础绑定取引用后，原帧槽只保留显示镜像。新版编译器为这类绑定登记私有 DWARF 存储地址及实际宽度；在栈顶开发源码帧中，查看直接读取真实绑定，修改先核对当前线程、暂停状态、原生上下文、存活区间及映射代次，再单次写入真实存储。读取不执行用户方法，也不刷新或覆盖旧镜像槽。八字节整数／浮点按完整存储更新，uint8／char 只写一个字节；同一暂停重新查看与恢复执行都使用更新后的真实值。

非栈顶帧的镜像保持只读，避免把调用方逻辑地址用于另一原生上下文。不可变绑定、引用变量本身、聚合、容器及聚合子项当前只读；不通过覆盖句柄伪造拥有值赋值，不绕过所有权与清理。旧编译器产物缺少真实槽或镜像存储描述时仍可查看，但禁止相应修改。普通局部拥有型 String 的受限修改见下文。

## 拥有型 String 的受限修改

栈顶开发源码帧支持修改编译器明确登记为可变独立拥有值的普通局部 `String`。设置值使用 JSON 字符串字面量，例如将 `"hello"` 改为 `"world"`。新旧内容的 UTF-8 **字节数必须相同**，上限 4096 字节；例如 `"中文"` 与 `"世界"` 均为 6 字节。空串只接受空串。输入不求值名称或调用，拒绝不成对的 Unicode 代理项。

修改前核对当前源码作用域、拥有关系、可变性、真实绑定、帧上下文、移动状态与完整存活分配，再核对字符串描述符、容量、内联或独立缓冲区以及终止字节。一次写入只更新内容载荷，不修改拥有句柄、描述符、长度、容量或终止字节，不执行目标函数、不分配或释放语言对象，也不恢复目标执行。原有借用继续指向同一缓冲区，独立复制的字符串和容器值保持各自内容。修改后旧聚合及内存引用失效，需要重新读取；已发送的写入不保证因取消而回滚。

优化帧、非栈顶帧、String 参数、模式绑定、借用和未明确登记拥有关系的旧构件不支持此操作。来源无法唯一定位、静态数据、空或已移动句柄、失效目录、损坏描述符、不支持的缓冲区布局、超出预算或不同字节数的替换均明确拒绝。修改其他拥有类型、调整字符串长度、修改聚合子项或替换拥有句柄仍不支持。

## 全停线程

线程视图接收标准 DAP 线程创建／退出事件，列出当前活动线程。进入、越过和跳出按用户所选线程执行；切换线程后不会沿用 GDB 上次选择的线程。采用全停模式：一个线程到达停点后所有线程停止；选定线程单步期间其他线程仍可运行，不提供单线程独占执行，`singleThread: true` 请求明确拒绝。

线程退出立即废弃已有调用帧、聚合及内存引用和进行中的旧读取，并通知客户端刷新栈与变量。线程列表查询期间发生退出时，迟到结果不能恢复旧线程。退出后的线程号不能继续查看或单步；原停止线程已退出时重新查询并选择仍活动的线程。异常查询按实际停点代次核对，其他线程退出不会吞掉仍存活线程的异常，也不会向已恢复或已关闭的会话发送旧停点。活动线程最多 4096 个、退出历史最多 65536 个、名称最多 4096 字符。

内部原生帧继续过滤到源码，包括 Windows GDB 从等待函数返回时缺少停止原因的通知；过滤有既有次数上限。显式暂停会撤销自动单步过滤，目标暂停后只在用户继续时恢复。Windows 原生暂停使用系统 Windows PowerShell 调用系统调试中断；核对目标 PID、最多八层祖先进程链、创建时间及真实映像，持有进程句柄直至操作完成，辅助进程继承同一临时目录并在结束会话时回收。这也适用于本机 `gdb.exe` 启动器派生 `gdborig.exe` 的布局。Linux 路径使用 MI 中断；Linux 系统库缺少函数边界时，单步仅在确认所选线程无源码后退回调用方。Windows x64 与 Linux x64 已实际核对线程专项。本机附加和 Linux gdbserver 连接见下节。

## 附加、断开与源码映射

附加已有进程时使用 `attach`、明确的 `processId` 和与目标映像字节相同的带符号 `executable`。不会构建源码，也不改变目标的参数、环境和标准流。`env` 只配置调试器。附加默认在完成断点配置后保持全停，`stopOnAttach: false` 则继续执行。

```json
{
  "type": "chali",
  "request": "attach",
  "name": "ChaLi 附加",
  "processId": 12345,
  "executable": "${workspaceFolder}/build/app-debug.exe",
  "sourceFileMap": {
    "C:/builder/project": "${workspaceFolder}"
  }
}
```

本机附加在 GDB 接管前后核对进程创建身份和实际映像 SHA-256。Windows 查询持有进程句柄，Linux 保留 `/proc/PID` 目录描述符；PID 重用、目标退出和映像变化明确报错。单份映像核对上限为 512 MiB。尚未核对身份时不开放调用栈、变量或内存查看。Windows 附加后的暂停按已经核对的创建时间和实际映像请求系统调试中断，不要求目标是调试器的子进程。

附加会话默认断开并恢复目标；VSCode 的停止调试同样保留外部目标。DAP `disconnect` 可用 `terminateDebuggee: true` 明确终止，`terminate` 请求也明确终止目标。断开前先确认全停并让 GDB 解除调试关系，再退出调试器；保留目标的路径不强制结束调试器进程树。断开失败保留会话供重试，不伪报成功。附加不支持重启，也不支持 `suspendDebuggee: true`；临时源码构建及集成终端启动不能选择断开后保留目标。已有产物的普通启动可明确请求 `terminateDebuggee: false`。

`sourceFileMap` 将目标源码绝对路径前缀映射到本地目录；本地相对目录按 `cwd` 解析。按最长目录前缀匹配并检查目录边界，断点使用反向映射。Windows 目标路径忽略大小写，Linux 目标路径保留大小写；路径支持空格和中文。最多 128 条映射，重复本地根及被更具体规则覆盖的反向路径明确拒绝，避免断点落入错误源码。调试目录仍保留原始源码身份，调用栈、宏来源和错误位置显示本地路径。

远程配置在上述 `attach` 中增加 `"remote": { "host": "127.0.0.1", "port": 2345 }`，`processId` 必须是该 Linux gdbserver 实际控制的目标 PID，`executable` 为相同 ELF 的本地副本。只接受 TCP 地址，连接已有服务，不启动远程命令、不部署程序。远程目标限定为 64 位小端 Linux x64／ARM64，GDB 必须具有对应 Linux 目标支持；普通 Windows MinGW GDB 未必包含 Linux OS ABI。连接后核对 GDB 报告的 PID，并通过 gdbserver 文件传输读取 `/proc/PID/exe` 核对完整 SHA-256；缺少该能力或身份不符时断开并报告。远程暂停走 MI 中断，panic 消息按 ELF 目标 ABI 读取参数，不使用宿主 Windows 的参数寄存器。

远程专项命令为 `python tools/run_module_gates.py debug_remote --chali Linux编译器路径 --jobs 1`，要求真实 Linux 宿主、匹配 GDB、gdbserver 和 LLVM 工具链；`CHALI_GDB`、`CHALI_GDBSERVER` 可指定工具。缺少环境会失败，不以跳过或模拟协议算作通过。目标架构格式检查不等于该架构已完成执行验收。

当前远程实际执行平台为 Ubuntu 22.04 x64、GDB／gdbserver 12.1，分别覆盖 malloc 与 pool；本机附加、源码映射及线程专项也在该 Linux 环境执行。ARM64 尚无目标执行证据。WSL 的 NTFS 挂载工作区不能建立集成终端所用的 Unix socket，因此该环境的完整调试门禁在终端场景失败；本次远程专项通过不等于 Linux 全调试模块或 Linux 图形扩展宿主全量通过。

## 真实 VSCode 扩展测试

在仓库的 `vscode/` 目录运行 `npm run test:extension`。需要本机已安装的 VSCode、GDB 和可执行的 ChaLi 编译器，以及可用的图形会话。`CHALI_BIN` 指定本阶段编译器，缺省使用扩展内嵌版本；`CHALI_VSCODE_EXECUTABLE` 可指定 VSCode 可执行文件，Windows 缺省使用 Program Files 中的安装，其他宿主从 PATH 查找 `code`；`CHALI_GDB` 可覆盖 GDB 路径。缺少环境会报告失败。

入口使用隔离的用户配置、扩展目录和工作区，全部位于仓库根目录 `tmp/`。真实扩展宿主验证激活、语言识别、源码构建与断点、调用栈、标量和数组查看、基础变量修改、取消、panic 消息及失败退出，还验证外部目标附加与运行状态下停止调试。每场景记录适配器及完整调试器后代进程并核对结束后退出；附加目标单独核对仍存活，再由测试调用方清理。日志和结果 JSON 保留在本次临时目录，按仓库约定归档并清理。Windows x64 的 VSCode 1.132.0 已实际执行；其他宿主路径提供了进程树读取实现，尚未据此声称目标平台实测通过。

`npm run test:extension -- --debug` 在扩展宿主运行测试前暂停，供 JavaScript 调试器连接端口 9333；测试总超时为 240 秒。自动门禁使用无此选项的入口。独立模块门禁为 `python tools/run_module_gates.py editor_host --chali 编译器路径`（从仓库根目录执行），发布门禁和 VSIX 打包同样执行真实宿主测试。

## 接口实际类型与字段

调试构建登记本次程序实际使用的动态类型布局。三版只读内存目录在正常源码停点前复制接口／Any 装箱的类型号和值，不调用动态类型查询、用户格式化、复制或析构方法。适配器按已验证的类型号找到具体记录布局，显示实际类型、嵌套字段和文本；拥有接口、只读／可写接口借用和容器内接口使用同一条读取路径。字段支持分页，继续运行后旧展开引用失效。

对象编号不会作为原始内存地址导出；具体记录的地址只在核对类型和当前存活映射后用于读取字段。空装箱、缺失动态类型或不支持的嵌套装箱明确显示状态，不按编号猜测类型。三版沿用二版的对象数量、值节点、递归与文本预算；旧版本容器目录仍可读取。闭包捕获见下节；引用的存活及循环状态见下节。

## 闭包捕获

调试构建为函数标签登记源码名字、捕获顺序、类型和捕获方式。四版只读目录在源码停点前复制已有闭包环境的函数标签及捕获描述；copy／move 捕获使用其现有稳定单元，借用捕获保留来源地址。查看不调用闭包、捕获复制助手、用户格式化方法，也不创建语言对象或物化单元。

闭包可展开为源码捕获项，标量直接显示，记录、字符串、容器及引用沿用类型化读取。默认只读借用附带只读提示，可写借用及 copy／move 单元保持各自值；克隆闭包的独立状态分别读取。子项支持分页，继续或重启后旧引用失效。无捕获函数只显示函数名，空值、未知标签或捕获数量与布局不符明确显示不可用；标签是语言数据区身份，不作为机器函数地址执行。仍使用单线程 4096 个对象、32768 个值节点、32 层值和 2 MiB 快照预算，旧版目录继续兼容读取。五版目录补充引用及存储状态，见下文。

源码停点的目录发布只跳过函数最初的空入口。变量镜像刷新或控制流汇合形成空基本块时，前面已执行的分配仍须重新发布，避免闭包构造后的堆目录失效。

## 引用、循环与存储状态

五版观察目录保留当前活跃存储的运行时移动／销毁标记。对象及存储观察使用独立失效代次；移动、重新初始化或对象修改后，旧目录必须重新发布，整个类型化读取的前后都核对代次，不改变语言借用视图的有效性。类型化读取先核对完整存活区间；带标记的值显示实际状态与运行时类型号，失效地址显示“引用无效、已释放或不属于当前存活分配”。没有可核对的历史时不推断具体释放原因；运行时清零后的引用显示 `null`。基础引用展示实际目标值；引用展开按当前祖先路径标注循环并停止，不把重复共享子对象一律视为循环。递归目标只采用目录中名称及布局无歧义的记录类型，超过 32 层或观察预算时停止。原始字节查看不解释移动标记，但仍要求地址处于当前存活分配。对象快照不完整与完整快照中缺失句柄分别报告；存活但不支持解码的宿主对象保留不透明状态。

基础值、字符串和其他拥有句柄通过独立的调试移动表跟踪源存储，不能把移动时清零后的数值或句柄当作正常的 `0`、空字符串或空容器。字段与索引按实际存储区间核对；真正的源码写入撤销已覆盖区间的调试标记，镜像刷新不会恢复已移动的值。闭包移动引用绑定使用独立的私有可用性槽，不把绑定移动与引用目标移动混同。读取真实绑定必须在当前帧中唯一找到编译器登记的私有地址槽，并核对帧身份、存活区间与观察代次；缺失、重复或已优化的观察槽明确报告不可读，不退回求值其他同名绑定。基础变量修改沿用同一可用性检查。观察事件只在正常调试构件执行路径运行，四元式导出忽略它们。

函数入口的身份捕获使用内部合成位置。VSCode 将入口帧映射回源码声明；同一源码断点若同时包含内部入口与实际源码位置，适配器使用可随映像重定位的函数相对地址条件，仅在实际源码位置暂停并累计命中次数。条件中的私有计数属于 GDB 状态，不写入目标程序。直接使用 GDB 时，可优先在函数体的语句行设置断点；函数声明及整个函数体写在同一行时，应核对 GDB 列出的多个位置及其文件。

# 原生 AOT 调试

<!-- LANGUAGE NAVIGATION -->
[English](en/43-native-debugging.md) · **简体中文**
<!-- END LANGUAGE NAVIGATION -->

ChaLi 1.0.8 的 `run` 使用 checked AOT 编译执行，`aot` 默认生成 unchecked 原生产物。编译器不再内置 VM 执行器；`.svmb` 导出已删除，新项目使用 AOT 原生产物。调试使用真实机器码、DWARF 源码行和帧槽，不依赖 VM 断点或解释执行状态。

## VS Code

安装 ChaLi 扩展与目标平台的 GDB，打开 `.chl` 文件，按 F5 启动原生调试。扩展先执行 checked AOT 调试构建，再通过 GDB/MI 提供源码断点、继续、单步进入／越过／跳出、调用栈、参数／局部变量和表达式查看。

```json
{
  "type": "chali",
  "request": "launch",
  "name": "ChaLi 原生调试",
  "program": "${file}",
  "cwd": "${fileDirname}",
  "debuggerPath": "gdb",
  "stopOnEntry": false,
  "args": []
}
```

`debuggerPath` 指定 GDB 路径；未设置时依次使用 `CHALI_GDB` 和 PATH 中的 `gdb`。调试器架构应与产物匹配。编译器、原生适配器和 GDB 子进程继承同一工程 `tmp/`；临时原生产物保留在该目录便于复核。断点解析失败会显示未验证及诊断，不回退到 VM。

命令“ChaLi：检查调试环境”核对实际编译器构建信息及 GDB 版本；`chali.debuggerPath` 可设置默认 GDB，单次配置的 `debuggerPath` 优先。Windows GDB 的启动参数编码可能依赖系统代码页，当前 ChaLi 调试产物额外读取带长度的 UTF-8 参数文件，保留空串、中文及非 BMP 字符；正常发布程序仍从进程入口取得参数。

调试构建使用 `-O0`，保留原生符号与源码行，避免最高优化把变量和步骤消除。普通发布构建继续默认最高优化、LTO 和死代码消除。调试结果不能直接作为发布构建性能数据。

## 工程、已有产物与标准输入

选择“ChaLi：调试项目入口”时，扩展从选定工作区的 `chali.toml` 读取 `main`，使用编译器解析的依赖、库锁和原生链接配置。当前文件启动则使用 `program`。多工作区路径相对于该调试配置所属工作区解析，省略 `cwd` 时使用项目根目录或入口所在目录。调试前保存相关源文件和清单；非宿主目标、非可执行输出及无效配置在启动前报告。

已有产物用 `"executable": "${workspaceFolder}/build/app-debug.exe"` 启动，省略 `program`；该模式不会调用编译器，也不会因重启重新构建。使用 `args` 传参，`env` 对象覆盖环境变量，值为 `null` 时删除继承项。源码构建错误直接转为 Problems 的文件、行和列，同一启动只构建一次。

```json
{
  "type": "chali",
  "request": "launch",
  "name": "ChaLi：项目与输入",
  "entry": "project",
  "console": "integratedTerminal",
  "env": { "APP_MODE": "development", "OLD_SETTING": null },
  "args": ["sample file.txt"]
}
```

`integratedTerminal` 使用 VSCode 伪终端按行输入；回车提交，退格编辑，Ctrl+C 请求暂停，Ctrl+D 或 Ctrl+Z 结束标准输入。它连接调试产物的会话专属标准流，输入不进入 GDB/MI；Windows 使用命名管道，Linux 使用本地套接字。标准输出与错误输出在终端合流显示。默认 `internalConsole` 适合无需输入的程序。

集成终端要求当前编译器生成的 `--debug` 产物；任意已有程序仍可用 `internalConsole` 启动。关闭活动终端结束会话，重启创建新连接，不复用上次输入。调试流连接发生在用户初始化之前，正常发布构建没有该调用。此终端提供行输入，不模拟完整系统 TTY 或全屏终端控制。

## 会话控制

构建、配置、运行、暂停和结束是不同状态。断点安装与启动、继续和单步等控制请求按顺序处理；调用栈、变量和表达式只接受当前暂停状态的引用。恢复执行后，旧帧和变量引用失效；迟到的读取结果报告过期，不展示上次暂停的数据。

支持取消调试构建与查询；客户端支持进度显示时，构建进度也可取消。停止或断开会回收该会话的编译器和 GDB 进程树。源码模式重启会重新构建程序并按原始源码位置重装断点，不沿用旧 GDB 的断点编号；构建期间也可以重启。正常退出、取消与重复关闭只发送一次结束事件。

DAP 消息头最多 8 KiB，消息体和单条 MI 记录最多 16 MiB；并发 DAP／MI 请求各最多 256 项。非法长度、截断或错误 JSON 不继续分派。MI 查询默认超时 20 秒；超时和取消后移除请求，迟到响应不能满足后续请求。控制操作一旦交给目标执行，取消不代表撤销已发生的程序行为；状态无法确认时结束会话。

源断点支持条件、命中次数与日志文本：条件按 GDB 原生表达式求值；命中次数只接受正整数，从第 N 次命中起停住；日志断点把 `{表达式}` 插值成文本后输出并自动继续，不向客户端报告暂停。函数断点按源码函数名登记，由调试目录翻译为实际链接名；符号尚未加载时保持待解析，GDB 解析后通过 DAP `breakpoint` 事件更新状态。

单步进入内部标准模块时，适配器会自动结束当前内部帧并继续，直到回到用户源码；用户函数仍按正常单步停住，连续过滤有上限并报告当前内部位置。panic、断言与受检查内存错误在调试构建中停在失败调用现场，适配器报告异常停点、原始消息和最近的用户源码位置；Result::Err 只是普通值，不产生异常停点。原生信号仍按异常停点报告，但尚未关联到具体源码行。

List／Map／Set 容器、接口实际类型与闭包捕获尚未接入类型化展示；运行期错误过滤器仍未提供，没有对应能力时不会宣称支持。调试专项使用真实 GDB 核对单步、返回位置、旧帧拒绝、重启断点及取消清理：

```sh
python tools/run_module_gates.py debug --chali PATH --random-recheck 1
```

## 产物中的源码映射

调试产物保存版本化的只读目录和基本块地址表，包含函数实例显示名、参数声明、变量词法区间及源码行列。适配器按实际机器 PC 选择对应位置；已有产物不需要源文件旁的临时映射文件。泛型函数和局部类型使用完整实参显示，例如 `identity<int64>` 和 `Holder<int64>`，链接符号仍沿用原约定。

读取映射只查询内部符号和原生内存，不执行目标函数。单份目录最多读取 4 MiB，最多 65,536 个位置，每块最多读取 64 KiB；验证版本、指针宽度、字节序、连续地址及所有索引。恢复运行会取消未完成读取；多个查看请求共享加载，但取消单个请求不取消其他查看。旧产物缺少目录或目录损坏时报告原因并沿用 DWARF，不能把回退列号当作精确列。

取引用后的局部或按值参数可能使用独立逻辑存储。调试构建在源码停点前通过已有内存原语刷新原帧展示值，保持实际赋值、宏可变借用和池缓冲区增长后的显示一致。此路径不创建语言对象，不执行用户方法，发布构建没有刷新指令。拥有值、容器及任意原生中断位置仍需按其实际逻辑布局解释，不能把帧中句柄当作机器指针。

## 命令行

```text
chali aot app.chl --checked --debug --out build/app-debug
gdb build/app-debug.exe
```

Linux 使用无 `.exe` 后缀的产物。可以设置 `break app.chl:行号`、`run`、`next`、`step`、`finish`、`backtrace`、`info locals` 和 `print 表达式`。`--debug` 保留调试信息，`--checked` 控制数组及指针检查，两者独立。

DWARF 按实际表示区分 int8—int64、uint8—uint64、bool、char、float32 和 float64，并保留声明行、源码列及用户词法块。内层同名变量只在其有效区间遮蔽外层变量，循环变量离开循环后不可见；编译器生成的清理块不额外创建用户名字作用域。当前数值帧将 float32 的已舍入值存为 double，调试描述按实际 64 位槽读取，类型名仍为 float32；调试器的原生 sizeof 因而不能替代语言的 std::lang::rawSize。

match 的模式绑定保留声明位置、类型和分支范围；分支退出后，模式变量不再出现在局部变量列表。调试产物同时记录宏的定义、调用和嵌套展开来源。VSCode 在当前宏展开中提供独立的 `$宏名` 变量作用域，内部副本不冒充调用方同名变量，展开结束后隐藏这些内部绑定；普通名称参数生成的调用方声明仍沿用调用方作用域。

调用栈任意帧中的普通记录、数组和指向这些聚合的引用都可提供本次暂停专属的内存引用，供 VSCode 的内存查看工具使用。标准 DAP `readMemory` 请求按语言逻辑地址读取静态数据区或活跃堆块，允许负偏移查看同一分配内的数组长度头；越界、已释放或过期的暂停引用会被拒绝。接口及宿主对象编号不自动作为地址提供；原生执行上下文已经切换而目录尚未重新发布时，也会拒绝读取。

一次内存查看共享 4 MiB 读取预算，包含目录与载荷；目录最多保存 65,536 个活跃区间。查看不会调用目标函数、执行用户方法或分配目标对象，也不会恢复目标执行；底层内存仍可通过原始内存引用单独读取。在映射发布中途暂停，或分配／释放后尚未抵达下一个源码停点时，堆查看会报告映射不可用，可以执行到源码停点后重试。不同线程的堆变化也可能保守使旧目录失效。

栈顶源码帧的普通记录、数组、字符串和引用按版本化逻辑布局展示：记录按声明顺序列出字段（嵌套记录按语言存储展平为带点号的槽），数组显示长度并按页列出元素，字符串解码为带引号的文本，引用直接展示目标值；载荷枚举、Option 与 Result 按标签显示变体名和载荷字段名，不暴露内部 `__tag`／`__vN_` 槽名，标签无效时报告未知变体。布局文本与运行时 value_text 同格式，由编译器去重登记；适配器只按布局读取目标内存，不调用目标方法、不执行用户代码，也不在查看期间分配语言对象。子项默认每页 100 项、最多 1000 项，读取仍共享 4 MiB 预算；快照不可用时保留原始槽值并继续提供内存引用。

适配器支持标准 DAP `disassemble` 请求：按机器地址返回当前帧附近的指令与符号名，可向前或向后取窗口、支持字节偏移，数量上限 4096；反汇编只读机器码，不恢复目标执行。

编译器只在已经执行过源码语句的基本块之后发布目录，因此函数第一条语句的停点沿用进入函数前最近一次发布；这期间没有分配或释放时仍可读取，否则按映射不可用处理，执行到下一条语句后重试。这样插入的发布调用不会成为函数入口后的第一个源码停点，单步进入仍停在第一条语句。

拥有型聚合和容器的槽值仍是 ChaLi 逻辑句柄，不能把它当成机器 C 指针解引用。表达式使用 GDB 接受的原生表达式语法。

源码级调试需要源码文件仍在记录的位置。调试适配器使用现有编译器与工具链生成机器码；不需要安装单独的 VM，也不把运行时函数值强转成机器函数指针。

# 编译器安全边界与定向回归

<!-- LANGUAGE NAVIGATION -->
[English](en/34-compiler-safety.md) · **简体中文**
<!-- END LANGUAGE NAVIGATION -->

> 当前编译器采用 checked／unchecked 两种 LLVM 原生路径。本页区分当前回归入口、设计边界和历史测量；只按实际交付结果报告验证范围。

本页记录已确认问题的保护行为和复现入口，不代表编译器不存在其他缺陷。

## 三类代表输入与能力边界

[代表输入目录](../tests/compiler_limits_cases.py)固定选择三类各 25 项：常见业务组件、高阶组合写法、有界压力输入。
[测试驱动](../tests/chali_compiler_limits.py)分别检查 checked 与 unchecked 原生路径的编译、运行及独立预期，记录退出码、诊断、超时和原始输出字节。
发现阶段保存整批结果并冻结清单，随后进入修复；`--verify` 用于后续回归，遇到未预期的失败返回非零。

0.31.0 的[优化前发现记录](../tests/fixtures/compiler_limits/discovery_0_31_0.json)保存源码、宿主、LLVM、编译选项和二进制 SHA256。
初始返回闭包用例还包含局部借用的生命周期问题；[合法复制捕获的补充记录](../tests/fixtures/compiler_limits/return_type_followup_0_31_0.json)确认自动推导失败、显式类型实参通过。
自动实例化完成后需要登记新增闭包的函数与类型，再进行语义重放。[专项回归](../tests/chali_generic_function_returns.py)覆盖返回闭包的复制、浮点值、容器存储和嵌套调用，并核对非法返回与局部借用的拒绝原因。

泛型函数接收重载回调时，先从普通实参取得类型绑定，再按完整函数签名筛选回调候选。
唯一匹配的签名会保留到后续类型检查与降低，避免重新查询时取错重载。
仍有多个匹配时，编译器要求显式类型实参或带签名的函数变量，不任意选择候选。

下表是 **0.31.0 历史测量**，使用单独的 64 MiB 执行预算，不能当成当前后端的能力表。原始记录保留真实版本、配置与结果：

| 输入 | 0.31.0 旧解释后端 | 0.31.0 LLVM 构建 |
| --- | --- | --- |
| 512 项普通加法表达式 | 片段深度或规模预算诊断 | 同样诊断 |
| 动态数组申请约 128 MiB | 堆容量不足诊断 | 堆容量不足诊断 |
| 8192 元素固定数组读写 | 64 MiB 内无法完成执行准备，报告容量不足 | 执行通过 |

这些结果描述对应宿主、实现与预算下的测试点。更换容量、工具链或输入结构后，应重新测量边界。

| 边界 | 处理 |
| --- | --- |
| 数据区整数超过 double 的精确范围 | 整数直接按 64 位解析，保留有符号最小值与 uint64 最大值的位模式 |
| 大浮点数导出为数据区浮点 | 不再无条件转换成 int64；先检查整数转换范围 |
| BigFloat 幂与方根的内部整数运算 | 先用除法检查指数范围，拒绝不可表示的精度；精度增长避免有符号溢出 |
| 拥有型 `?` 结果直接进入枚举构造器 | 构造参数接管表达式临时值时清空原拥有槽，避免重复清理 |
| 多个进程写同一个输出前缀 | 源码直接运行使用本次生成的内存数据映像；磁盘产物文件仍应使用不同前缀 |
| LP64、Clang 与 glibc | 避免 long/int64 构造重复、完整类型定义前实例化 JSON/TOML 成员、htons 宏与成员名冲突 |
| 浮点转整数超出目标范围 | 运行期报「浮点转整数超出目标范围」；编译期常量折叠遇到越界不折叠，避免宿主上的未定义行为 |
| 十进制整数字面量超过 int64 | 编译期报「十进制整数超出 int64 范围」（此前静默饱和成 `INT64_MAX`）；`-9223372036854775808` 例外，幅值 2^63 由一元负号定型成最小值 |
| 浮点字面量溢出成 inf / NaN | 编译期报「浮点字面量超出可表示范围」（此前会串成「读未定义的变量：inf.0」） |
| JSON / TOML 嵌套层数 | 超过 256 层记为解析诊断（此前超深嵌套会把宿主栈打爆并崩溃） |
| 局部定长数组规模 | 编译期报「定长数组超出当前内存预算」（此前运行期 arena 耗尽后 `std::bad_alloc` 逃逸成 `terminate`），与 struct 字段的预算口径一致 |
| 定长数组维数连乘 | 统一走 64 位累加，溢出时夹到 int 上界（此前 `int` 连乘溢出后循环上界与槽偏移成错值） |
| 字符串切片负端点 | 运行期报「切片端点不能为负数（String 的切片按字节算）」（此前 `"abcdef"[0:-2]` 静默得到 `abcdef`）；`end == -1` 仍是内建 ABI 的「到末尾」约定 |
| 容器回调期间重入 | `vecFold` / `vecMap` / `vecFilter` 与谓词回调持引用迭代时上迭代器租约，回调里 `push` / `clear` 会被拒绝 |
| 遍历期间增删元素 | `push` / `set` 与 `remove` 同样受「活跃 for-in 引用期间不能移动或删除列表元素」保护 |
| `INT64_MIN / -1` | 运行期报「整数除法溢出：最小负数除以 -1 的结果超出 int64 范围」（此前静默给出 `-9223372036854775808`） |
| 移位位数超出位宽 | 运行期报「移位位数超出整数位宽（有效范围 0..63）」（此前 `& 63` 静默回绕，`1 << 64` 算成 `1`） |

定向回归：`python tests/chali_compiler_safety.py`。Linux 可用 `--cxx clang++ --sanitize-native` 对原生边界开启 ASan、UBSan 与浮点转整数检查；`--native-only` 只验证库边界。反射默认同时启用前端与运行期宏，checked / unchecked 两条路径仍使用各自的默认优化级别。

渗透测试：`python tests/chali_penetration.py`（`--only 子串` 可只跑部分用例）。它对数值转换、字面量、容器边界、所有权传播与规模预算构造攻击用例，把结果归类为 UB / CRASH / TIMEOUT / FAIL / OUTPUT，只收集事实、不做判定。

传播回归覆盖字符串成功、原始错误和容器载荷的重复清理。数据快照回归在优化转储阻塞时覆盖磁盘数据文件，检查当前 LLVM 构建不受影响。原生边界入口为 [chali_native_safety.cpp](../tests/chali_native_safety.cpp)。

大数运算仍受宿主内存与时间预算限制；这组保护不承诺任意巨大参数都能完成计算。发布时只报告实际执行的验证，未执行的跨平台或长期压力测试继续保留在任务验收记录中。

编译阶段与程序执行堆使用不同的预算。默认前端池为 512 MiB；--memory-size 调整程序执行堆，不扩大前端池。前端分配失败会报告池容量、失败时活动量及本次申请量，并以非零状态退出，不传播未捕获 std::bad_alloc。单态化重放完成后，在四元式生成前释放不再使用的解析快照。综合标准错误夹具当前仍会触及池内大块连续分配边界；活动字节数不等于可用连续空间，不把单次拒绝解释为所有库组合的绝对上限。回归：python tests/chali_compiler_budget.py，分别验证中文和英文的预算诊断。

## 复杂语法、语义组合与格式化往返

`python tests/chali_syntax_semantic_stress.py` 从正常／错误样例读取完整程序，分别运行原文与格式化文本的 checked／unchecked 构建，核对独立输出，检查格式化幂等；超时会终止进程树，崩溃、静默失败和意外放行均判失败，不把“两个模式结果一样”当成正确。

当前固定压力点包括：192 层括号、48 层块、16 层泛型容器、64 项运算链；宏中的 Map／List／元组／函数类型及连续闭合尖括号；高阶回调、嵌套枚举自动包装、跨模块泛型借用、512 次多层 Result 传播与延迟清理。可运行入口为[深度压力](../example/samples/syntax_pressure_depth.chl)、[宏类型标点组合](../example/samples/syntax_macro_type_tokens.chl)、[嵌套函数类型参数](../example/samples/syntax_nested_function_argument.chl)和[语义组合](../example/samples/syntax_semantic_composition.chl)。这些是固定验证点，不是任意输入深度均可处理的承诺。

## 分析流程与本轮修正

模块与文本展开后进入文法解析，原始宏参数再按类别结构化；普通泛型签名用符号类型探测，具体调用产生单态化请求并登记新声明，然后重放类型与函数体分析。反射桥带来新声明时同样重放。解析快照、生命周期指令和符号类型索引必须随重放保持一致，不能让签名探测的临时节点污染正式契约。

语义阶段记录绑定后的存储、借用来源、控制出口和清理义务。来源契约在具体控制流上核对，引用移动摘要在全部具体函数之间迭代到不动点，再检查调用方的失效访问；完成这些步骤后才生成四元式及 LLVM 原生产物。该顺序保留，修正集中在跨阶段事实与身份的传递：

- 宏／普通函数经引用移动后，失效状态要回到拥有者及已知别名。
- `defer` 在真实退出边检查捕获来源，不把登记时有效当作执行时有效。
- 含释放的循环区分首轮与后续迭代，避免把旧游标与已释放状态交叉合并；额外节点预算按本函数规模计算。首轮副本不能单独证明整条源码释放语句冗余。
- 值表达式交还不含借用元素的拥有数组时，结果拥有者不能沿用已移动局部的失效身份；含借用元素继续走来源检查。
- 嵌套泛型引用参数根据实例表保留的规范原文恢复引用类型树，不从截断后的修饰名猜测。

循环修正由[泛型堆遍历](../example/samples/borrow_loop_heap_traversal.chl)核对 while、for-in、带退出条件的 loop 和 384 次关闭；对应反例继续拒绝释放后访问、旧别名读取及跨回边重复移动。

## 已知限制与诊断边界

| 边界 | 当前行为与写法 |
| --- | --- |
| 三段式 for 与 do while | 支持 `for(init; condition; update)`，初始化可以声明循环局部变量，continue 执行更新；各段可空，更新支持逗号顺序执行。do while 不在当前表面文法，使用 while 或独立 `loop { ... }`。见正常样例 `syntax_for_loops`、错误样例 `syntax_limit_do_while` |
| AST 片段遍历预算 | 当前最大深度 256、最多 1000000 个已见节点；预算不是源码字符数或括号数量。600 项左结合加法链会受诊断拒绝，192 层冗余括号的固定测试通过。大型生成表达式应拆分语句／函数 |
| 不完整的复杂类型标点 | 缺失泛型闭合尖括号等输入必须报语法诊断，不能崩溃或静默放行；`syntax_limit_missing_generic_closer` 固化此边界 |
| 跨条件的逻辑相关性 | 不证明任意条件及其否定之间的关联，可能保守拒绝实际安全的来源选择；`syntax_limit_path_correlation` 是已知精度限制。把选择和返回组织在同一分支结构中，见 `syntax_helpers::structural` |
| 循环首轮分离 | 是有界精度改进；预算耗尽时回到保守分析，不跳过检查。不会证明任意动态堆图无环，也不穷举未知字段指针的全部别名 |
| 含借用元素的数组值表达式返回 | 已知保守精度限制：即使引用全局来源，`return { ...; yield array; };` 仍可能按旧临时身份被拒绝。使用具名数组的普通 return，见[已验证替代写法](../example/samples/syntax_borrowed_array_named.chl)；`syntax_limit_borrowed_array_value_return` 保留拒绝复现，局部引用逃逸反例仍必须拒绝 |
| 泛型与生命周期契约 | 泛型正文按具体实例检查，不证明所有未调用实例。函数值不携带 #borrow／#static 契约；详见[资源与生命周期](22-resource-lifetime.md) |
| for-in 后备变量 | 值类型在空输入时取普通默认值；借用迭代元素会在下一次 iterator 调用前保存独立副本，要求可复制。引用或含借用的值若不能证明已有有效来源，会保守拒绝后备读取；可在循环体内处理该引用。见 `syntax_for_else` 与 `syntax_for_else_stress` |
| 枚举载荷自动包装 | 目标枚举及类型实参须可确定；同优先级匹配需显式变体，不替代资源移动和引用逃逸规则 |

安全拒绝、已知精度限制和真正的误报／漏检分别记录；当前输入仍受编译内存、实例化轮数和宿主资源约束，不用单次通过推断“任意复杂程序都可解析”。

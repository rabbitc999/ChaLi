\chapter{字符串与格式化}
\label{ch:12}

字符串既供人阅读，也参与文件、网络和数据库协议。把一个值显示出来，与为某种外部格式正确编码，是两个不同任务；同样，UTF-8 的字节长度也不等于可见字符数量。

本章从插值中的表达式与转义开始，再比较默认结构化显示和自定义 toString。理解显示结果怎样构成以后，才能正确选择持久化格式、输出转义和缓冲区策略。

\section{文本与边界}

String 使用 UTF-8。处理切片或外部字节长度时注意多字节编码：任意字节偏移未必是字符边界。输入长度限制也要明确采用字节还是用户可见字符；不要仅凭 ASCII 例程推断中文和表情的行为。

\section{插值与转义}

希望把当前计数放进提示文字时，可以手动拼接，也可以把表达式写进插值位置。插值的好处是让文字与数据的对应关系直接可见；先算表达式，再把结果转换为显示文本。

花括号也可能是我们真正想显示的字符，因此还需要转义，告诉编译器这里不开始表达式。下面把普通计算、嵌套插值和字面花括号放在同一行比较。得到显示文字以后，HTML、SQL 或 JSON 需要的专门编码仍另行处理。

\par
\medskip
\begin{lstlisting}[style=chali]
void main()
{
    int64 count = 3;
    String text = f"count={count + 1}, {f"inner={count}"}, \{literal\}";
    println("{}", text);
}
\end{lstlisting}
\par
\medskip

\par
\medskip
\begin{lstlisting}[style=out]
count=4, inner=3, {literal}
\end{lstlisting}
\par
\medskip

\subsection*{代码详解}

前缀 f 表示插值字符串。第一处 \texttt{\{count + 1\}} 先按整数表达式得到 4，再放进文本；第二处包含一个嵌套的 f 字符串，它读取同一个 count 得到 inner=3，然后插入外层。

最后的 \texttt{\textbackslash{}\{literal\textbackslash{}\}} 用转义保留花括号，literal 因而是普通文字，不会被当作变量查找。构造结束后 text 已经包含完整结果，println 只把这个字符串放进输出占位符。本例计算 count+1 并未对 count 赋值，所以两处分别显示 4 和 3 并不矛盾。

\section{结构化显示与自定义显示}

默认结构化显示适合诊断，文本形式不应当作稳定的文件格式。需要业务显示时提供 toString；需要持久化或跨进程传输时使用相应序列化协议并处理失败。

\par
\medskip
\begin{lstlisting}[style=chali]
struct Pair
{
    String left;
    String right;
};

void main()
{
    Pair pair;
    pair.left = "one";
    pair.right = "two";
    List<Any> list = [1, "two", true];
    Set<int64> set = {3, 1, 2};
    Map<String, Any> map = {"name": "ChaLi", "count": 3};
    let tuple = (1, "two", list);

    println("{}", pair.toString());
    println("{}", list.toString());
    println("{}", set.toString());
    println("{}", map.toString());
    println("{}", tuple.toString());
}
\end{lstlisting}
\par
\medskip

\par
\medskip
\begin{lstlisting}[style=out]
{"one", "two"}
[1, "two", true]
{3, 1, 2}
{"name": "ChaLi", "count": 3}
(1, "two", [1, "two", true])
\end{lstlisting}
\par
\medskip

\subsection*{代码详解}

这五次打印分别展示结构体、列表、集合、映射和元组的结构化显示。Pair 按字段内容显示 one 与 two；List<Any> 对整数、字符串、布尔值分别保留适合其内容的表示。带引号的 two 是结构化表示中的字符串标记，不是原数据额外多了引号。

tuple 的第三项是整个 list，因此最后一行在圆括号内嵌有列表表示。集合和映射在本例有对应的验收输出，但不要把一次显示次序推广为所有实现、所有操作后的排序承诺。这类文本用于阅读和诊断；即使外观看起来像 JSON，也应使用正式序列化接口生成交换格式。

\par
\medskip
\begin{lstlisting}[style=chali]
struct Named
{
    String name;
    String toString() { return "name=" + self.name; }
};

void main()
{
    Named value;
    value.name = "ChaLi";
    String text = value;
    println("{}", text);
    println("{}", cast<String>(value));
}
\end{lstlisting}
\par
\medskip

\par
\medskip
\begin{lstlisting}[style=out]
name=ChaLi
name=ChaLi
\end{lstlisting}
\par
\medskip

\subsection*{代码详解}

Named 自己定义了 toString，返回固定前缀与 self.name 的拼接结果。初始化 name 为 ChaLi 后，显示结果应为 name=ChaLi，而不是默认结构化字段列表。

\texttt{String text =\allowbreak{} value} 演示目标为 String 时的显示转换，\texttt{cast<\allowbreak{}String>\allowbreak{}(\allowbreak{}value)\allowbreak{}} 把同一转换要求显式写出；两者都采用该模型的显示行为，所以输出相同。这里的转换生成文本，没有把 value 的类型永久改成 String，也不保证其他目标类型都有相应转换。

\section{拼接、缓冲区与安全输出}

重复拼接的成本取决于复制、临时值和容量增长。String 可以复用已分配的缓冲区，缩短内容不等于释放容量；优化应保持复制和借用的可观察行为。第 24 章区分编译选项，第 25 章网页示例通过 textContent 显示用户数据，避免将姓名直接解释成 HTML。

\subsection*{小结}

先确定文本用于展示还是交换，再决定使用插值、toString 或序列化。插值计算表达式，显示转换说明人如何看到对象，协议编码约定另一端如何解析，不能由一个步骤替代全部工作。

外部文本还可能无效或不满足业务条件。后面的错误处理和综合项目会把解析失败、字段验证、SQL 文本引用及页面显示分别放到对应边界。

\section{番外：施氏数“字符”}

借赵元任《施氏食狮史》的同音构思另写，不复述原文。

施氏试字符串，示十式，使实习生识之。生视“施施施”，说是三；施氏试 \texttt{len}，示九。生失色，疑机器失识。施氏说：“是三个汉字，实是九字节。”

生始释，遂试切。使首字节至第三字节，各自成串。屏上似石似齿，实皆失形。生说：“既许切，何事失真？”施氏说：“许切是字节接口的事，切得像不像字，是编码的事。”

生再试十个字母，十个字节；再试十个汉字，长度又变。于是施氏施一纸示例：字节非码点，码点非字形。生读三次，仍将“字符数”填进“存储大小”。施氏只好把表格改成三个字段，免得同音字一起进生产。

此后实习生每逢产品说“就限制十个字，十分简单”，便失神片刻，先问：“十字节、十码点，还是十个看起来像一个的东西？”

产品说他话太多。施氏说：“是。谁先把单位写清楚，谁就少开十次会。”

\subsection*{技术对照}

String 的长度、下标和切片按当前 API 规定的单位使用。本章基础 String 操作按字节；处理 UTF-8 时不能任意截断多字节编码，也不能把代码点直接等同于视觉字形。

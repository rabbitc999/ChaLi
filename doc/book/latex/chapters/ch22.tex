\chapter{指令与派生行为}
\label{ch:22}

指令把类型或声明的特殊行为交给编译器识别。只在具体场景需要时使用对应指令，并检查它与普通值、引用和运算规则如何组合。

\section{派生相等、哈希和复制}

对支持的类型使用 \#derive 请求 Equal、Hash、Clone 等已有能力。派生按照类型结构生成行为；字段的自定义语义仍然影响结果。不要把声明宏的计划能力与当前 \#derive 支持混为一谈。

\par
\medskip
\begin{lstlisting}[style=chali]
#derive(Equal, Hash, Clone)
struct Point
{
    int64 x;
    int64 y;
    String label;
};

void main()
{
    Point origin;
    origin.x = 0;
    origin.y = 0;
    origin.label = "O";

    Point copy = origin.clone();
    println("equal={}", origin == copy);
    println("sameHash={}", origin.hash(origin) == copy.hash(copy));

    copy.label = "O2";
    println("afterChange={}", origin == copy);
    println("original={}", origin.label);
}
\end{lstlisting}
\par
\medskip

\par
\medskip
\begin{lstlisting}[style=out]
equal=1
sameHash=1
afterChange=0
original=O
\end{lstlisting}
\par
\medskip

\section{运算替代与接收关系}

自定义运算需要明确左右操作数、返回类型以及是否修改接收者。下面分别观察禁止复合替代和禁止右操作数替代后的结果；不要根据熟悉的符号假定所有类型都遵循内建数值的转换。

\par
\medskip
\begin{lstlisting}[style=chali]
#NoAddReplace
struct Vec : Add<int64, int64>
{
    int64 v;

    int64 leftAdd(int64 other)
    {
        return self.v + other;
    }
};

void main()
{
    Vec a;
    a.v = 10;
    println("left={}", a + 5);
}
\end{lstlisting}
\par
\medskip

\par
\medskip
\begin{lstlisting}[style=out]
left=15
\end{lstlisting}
\par
\medskip

\par
\medskip
\begin{lstlisting}[style=chali]
#NoRightAdd
struct Chain : Add<int64, int64>
{
    int64 v;

    int64 leftAdd(int64 other)
    {
        return self.v + other;
    }
};

void main()
{
    Chain chain;
    chain.v = 7;
    println("chain + 1 = {}", chain + 1);
}
\end{lstlisting}
\par
\medskip

\par
\medskip
\begin{lstlisting}[style=out]
chain + 1 = 8
\end{lstlisting}
\par
\medskip

\section{借用来源声明}

\#borrow 描述返回借用与输入来源之间的关系，让调用者能按正确存活范围使用结果。它不能让已经销毁的对象继续存活，也不能取消重叠可变访问的限制。

\par
\medskip
\begin{lstlisting}[style=chali]
#borrow(#ret, [a])
int64 mut& first(int64 mut& a, int64 mut& b)
{
    return a;
}

int64 mut& outer(int64 mut& x)
{
    int64 local = 5;
    return first(&x, &local);
}

void main()
{
    int64 number = 30;
    int64 mut& selected = outer(&number);
    selected = 31;
    println("{} {}", number, selected);
}
\end{lstlisting}
\par
\medskip

\par
\medskip
\begin{lstlisting}[style=out]
31 31
\end{lstlisting}
\par
\medskip

\section{番外：一张便条的权力}

改写自刘禹锡《陋室铭》。

指令不在多，入语义则灵；注解不在长，有元数据则明。斯是声明，惟约定清。\texttt{\#Non\allowbreak{}Copyable} 上类型，普通赋值莫偷行；谈笑皆诊断，往来无蒙混。可以查文法，验类型。无乱标记之扰眼，无假接口之劳形。

编译器阅此处，反射者查彼层。一个管能不能做，一个记身上有什么名。若将禁止复制只写成一条注解，便似在库门贴“请勿搬走”，看门人却从未接到命令。

主簿有言：“何陋之有？”差役答曰：“陋倒不陋，就是把便条当成了律令。”

县令闻之，命贴一千张“本库绝不失窃”，以为从此安全。次日失物，差役按注解查出每一只空箱的名称，竟无一项阻止了搬运。县令大怒，要追加一个 \texttt{@Really\allowbreak{}Really\allowbreak{}Safe}。主簿将笔夺下，曰：“再加一个 Really，也不会自动生成一条检查。”

于是语义约束写入指令，描述信息留给注解。库中少了九百九十九张告示，规矩却第一次真正执行起来。县令大喜，欲为主簿加注“善治”。主簿再三说明：这个倒可以，只求别指望它自动发俸禄。

\subsection*{技术对照}

指令与注解的关键差别在读取者：指令由词法与语义层读取，参与类型检查；注解由反射在运行期读取，不改变语义。把"禁止某条推导"这类声明级约束写成标记接口，等于把规矩写进借条里。

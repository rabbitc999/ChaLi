\chapter{学生信息管理系统：让程序认识自己的结构}
\label{ch:25}

前面 23 章把语言讲完了。这一章反过来做一件「用」的事：把结构体、注解、反射、JSON、SQL、TCP 和 \texttt{Result} / \texttt{?} 拼成一个带前后端的系统——浏览器里点一下「新增学生」，请求走进 ChaLi 写的 HTTP 服务，落到 MySQL，再以 JSON 回到页面。

它覆盖了日常业务程序最核心的那几件事：

\begin{itemize}

\item 一份模型（学生有学号、姓名、年龄、班级、成绩）；

\item 一张表（模型直接变成 MySQL 的表）；

\item 一组接口（增删查改、搜索、排序，JSON 通信）；

\item 一个前端（单页 HTML，只依赖浏览器原生能力，没有任何框架）；

\item 一条校验规则（学号必须是正整数、年龄在 1 到 150、成绩在 0 到 100）；

\item 一条出错的路（所有失败都变成可读的诊断，而不是崩溃）。

\end{itemize}

工程还按职责拆成五个模块——模型、存取、HTTP、路由、入口各自一个文件，\texttt{import} 把它们接成一棵模块树（第 18 章）。

最关键的那一句话是：这个系统从来没有手写过「学生有哪些字段」的清单。 字段列表是它运行期从自己身上读出来的——这就是第 20 章的反射真正派上用场的地方。

示例就在仓库里：\href{https://github.com/rabbitc999/ChaLi/tree/master/example/students-server}{\texttt{example/\allowbreak{}students-server/\allowbreak{}}}。命令行 + SQLite 的最小版本（同样的模型，两百行以内）见\href{https://github.com/rabbitc999/ChaLi/blob/master/example/reflection-students/README.md}{\texttt{example/\allowbreak{}reflection-students/\allowbreak{}}}，本章不再重复它的细节。

\end{tip}

\section{校验单独写一个函数}

业务规则不要散落在各个分支里，收成 \texttt{model:\allowbreak{}:\allowbreak{}validate}，返回空字符串表示通过：

\par
\medskip
\begin{lstlisting}[style=chali]
String validate(Student const& student)
{
    if (student.id <= 0)
    {
        return "学号必须是正整数";
    }
    if (student.name.trim().isEmpty() || len(student.name) > 120)
    {
        return "姓名必须为 1 到 120 字节的非空文本";
    }
    if (student.age < 1 || student.age > 150)
    {
        return "年龄必须在 1 到 150 之间";
    }
    if (student.score < 0 || student.score > 100)
    {
        return "成绩必须在 0 到 100 之间";
    }
    return "";
}
\end{lstlisting}
\par
\medskip

参数是 \texttt{Student const\&}：引用，不复制（第 7 章），而且只读。注意字节长度：\texttt{len(\allowbreak{})\allowbreak{}} 数的是字节不是字符（第 12 章），「120」是 120 个字节，中文姓名大约 40 个字。

存入前校验一次，从数据库读出来还要再校验一次（25.6 的 \texttt{encode\allowbreak{}Rows}）——「库里存了脏东西」也要在这一关被拦住，而不是一路带进接口响应。

\section{反射派生：建表列、结果集解码、字段白名单}

\texttt{model.\allowbreak{}chl} 里三个函数，全部从 \texttt{get\allowbreak{}Struct\allowbreak{}Info<\allowbreak{}Student>\allowbreak{}(\allowbreak{})\allowbreak{}} 出发。

建表列：字段类型映射成 MySQL 类型，主键加 \texttt{PRIMARY KEY}。列名是编译期的模型字段名，不是用户输入，拼进 SQL 文本是安全的：

\par
\medskip
\begin{lstlisting}[style=chali]
Result<String, MessageError> mysqlColumns()
{
    let reflected = std::reflect::getStructInfo<Student>();
    if (reflected.isNone())
    {
        return Result<String, MessageError>::Err(MessageError::from("Student 模型需要 @Reflect"));
    }
    let info = reflected.unwrap();
    String output = "";
    for (std::reflect::FieldInfo field in info.fields)
    {
        /* ……读 @ModelField 注解判断主键…… */
        if (!output.isEmpty()) { output = output + ", "; }
        output = output + "`" + field.name + "` " + columnDefinition(field.typeId, primary);
        if (primary) { output = output + " PRIMARY KEY"; }
    }
    return Result<String, MessageError>::Ok(output);
}
\end{lstlisting}
\par
\medskip

\texttt{store:\allowbreak{}:\allowbreak{}ensure\allowbreak{}Schema} 拿它拼一句\texttt{CREATE TABLE IF NOT EXISTS `students` (\allowbreak{}…)\allowbreak{} ENGINE=\allowbreak{}Inno\allowbreak{}DB DEFAULT CHARSET=\allowbreak{}utf8mb4}。

结果集解码：数据库返回「行 \ensuremath{\times} 列」的文本网格，我们要 JSON。字段清单从反射里拿，不在代码里再抄一遍：

\par
\medskip
\begin{lstlisting}[style=chali]
Result<String, MessageError> encodeRows(std::sql::ResultSet const& rows)
{
    let fields = std::reflect::getStructInfo<Student>().unwrap().fields;
    List<String> records;
    for (int64 row in std::lang::range(0, rows.rowCount()))
    {
        List<String> values;
        for (std::reflect::FieldInfo field in fields)
        {
            int64 column = rows.columnIndex(field.name);
            if (column < 0)
            {
                return Result<String, MessageError>::Err(MessageError::from("数据库缺少字段：" + field.name));
            }
            String value = rows.textAt(row, column);
            if (field.typeId == std::reflect::getTypeId<String>())
            {
                value = std::reflect::__serdeQuote(value);
            }
            values.push(std::reflect::__serdeQuote(field.name) + ":" + value);
        }
        /* 反序列化再序列化：解析器和模型对一遍，脏数据在这里被拦住 */
        /* ……校验通过后 std::json::serialize<Student>(&student)? …… */
    }
    String separator = ",";
    return Result<String, MessageError>::Ok("[" + separator.join(records) + "]");
}
\end{lstlisting}
\par
\medskip

两个值得单独看的点：

\begin{enumerate}

\item \texttt{field.\allowbreak{}type\allowbreak{}Id =\allowbreak{}=\allowbreak{} std:\allowbreak{}:\allowbreak{}reflect:\allowbreak{}:\allowbreak{}get\allowbreak{}Type\allowbreak{}Id<\allowbreak{}String>\allowbreak{}(\allowbreak{})\allowbreak{}} —— 运行期判断字段是不是字符串，是才加引号。数字字段加了引号就不是合法 JSON 数字了。

\item 反序列化再序列化 + 再校验 —— 先 \texttt{deserialize<\allowbreak{}Student>\allowbreak{}} 让解析器和模型对一遍，再 \texttt{serialize<\allowbreak{}Student>\allowbreak{}} 输出，同一段文本走 \texttt{validate} 再走一遍。

\end{enumerate}

字段白名单：\texttt{list} 接口允许按任意字段排序，但排序字段来自 URL 查询串——用户输入绝不能直接拼进 \texttt{ORDER BY}。\texttt{model:\allowbreak{}:\allowbreak{}is\allowbreak{}Field(\allowbreak{}name)\allowbreak{}} 拿反射字段表当白名单，不是模型字段直接拒绝：

\par
\medskip
\begin{lstlisting}[style=out]
{"error":"模型 Student 没有字段 badfield"}
\end{lstlisting}

\section{MySQL 存取：值必须过转义，列名只来自模型}

\texttt{store.\allowbreak{}chl} 负责所有 SQL。这里有一条要说实话的边界：\texttt{std:\allowbreak{}:\allowbreak{}sql} 的参数化绑定（\texttt{db.\allowbreak{}exec(\allowbreak{}Sql\allowbreak{}Statement)\allowbreak{}}，值走驱动绑定）目前由 SQLite 后端实现；MySQL 后端按文档口径使用 \texttt{db.\allowbreak{}quote(\allowbreak{})\allowbreak{}}——它始终转义单引号，MySQL 方言下同时转义反斜杠。所以本工程的规矩是：

\begin{itemize}

\item 文本值一律过 \texttt{db.\allowbreak{}quote(\allowbreak{})\allowbreak{}}，不许手拼引号；

\item 列名、表名只来自反射元数据（编译期字段名），不拼任何用户输入；

\item 排序字段先过 \texttt{is\allowbreak{}Field} 白名单。

\end{itemize}

新增学生把这条链走全：自动分配学号 \ensuremath{\rightarrow} 校验 \ensuremath{\rightarrow} 查重 \ensuremath{\rightarrow} 拼参数化形状的\texttt{INSERT} \ensuremath{\rightarrow} 检查影响行数：

\par
\medskip
\begin{lstlisting}[style=chali]
Result<String, MessageError> add(Database mut& database, Student const& student)
{
    Student record = student;
    if (record.id <= 0)
    {
        record.id = nextId(database);
    }
    String problem = model::validate(&record);
    if (problem != "")
    {
        return Result<String, MessageError>::Err(MessageError::from(problem));
    }
    ResultSet exists = database.exec("SELECT `id` FROM `students` WHERE `id` = "
        + record.id.toString() + " LIMIT 1");
    if (!exists.isEmpty()) { return Result<String, MessageError>::Err(MessageError::from("学号已存在：" + record.id.toString())); }
    /* ……toLiterals 从序列化 JSON 里取每个字段的值：文本过 db.quote，整数直写…… */
    String sql = "INSERT INTO `students` (" + separator.join(columns) + ") VALUES ("
        + separator.join(literals) + ")";
    ResultSet result = database.exec(sql);
    if (result.affected != 1) { return Result<String, MessageError>::Err(MessageError::from("写入失败：影响 0 行")); }
    return std::json::serialize<Student>(&record);
}
\end{lstlisting}
\par
\medskip

\texttt{to\allowbreak{}Literals} 是「反射取列名、JSON 取值」的合流点：先把学生序列化成 JSON，再按反射字段清单逐个 \texttt{parsed.\allowbreak{}find(\allowbreak{}field.\allowbreak{}name)\allowbreak{}}，文本字段交给 \texttt{db.\allowbreak{}quote}，整数字段 \texttt{to\allowbreak{}String(\allowbreak{})\allowbreak{}}。值永远不进列名，列名永远不来自用户。

它成了一条普通记录——单引号被翻倍、反斜杠被转义，SQL 里它就是文本。表还在，随后的查询照常工作。这就是转义和「拼接」的区别：注入死在字面量边界上，而不是靠运气。

\section{HTTP 层：四个套路写一个极简服务}

\texttt{httpd.\allowbreak{}chl} 建立在 \texttt{std:\allowbreak{}:\allowbreak{}net} 的 TCP 套接字上（第 21 章的宿主绑定），全部就四个函数：\texttt{read\allowbreak{}Request}、\texttt{send\allowbreak{}Response}，加两个小工具。

读请求有个真实的坑：浏览器会开「预连接」空套接字——连上来但什么都不发。如果服务阻塞在 \texttt{receive} 上，一个空连接就能卡住整个服务。所以首行用带超时的阻塞读（\texttt{receive\allowbreak{}Line(\allowbreak{}idle\allowbreak{}Ms)\allowbreak{}}，空连接到点即断），请求体用非阻塞接收 + 有界自旋（\texttt{receive\allowbreak{}Async}，头通常和体在同一段到达，自旋几轮就收完）。这样既不依赖线程运行期，也不会被空连接拖死：

\par
\medskip
\begin{lstlisting}[style=chali]
Result<Request, MessageError> readRequest(TcpSocket mut& socket, int64 idleMs)
{
    String head = "";
    while (true)
    {
        String line = socket.receiveLine((int32)idleMs);
        if (socket.status() == std::net::NET_TIMEOUT)
        {
            if (head.isEmpty()) { return Result<Request, MessageError>::Err(MessageError::from("空连接")); }
            return Result<Request, MessageError>::Err(MessageError::from("等待请求超时"));
        }
        /* ……NET_CLOSED / NET_ERROR 各给诊断…… */
        if (line.isEmpty()) { break; }   /* 头部以空行结束 */
        head = head + line + "\r\n";
    }
    /* ……Content-Length 决定还要读多少字节进 body…… */
}
\end{lstlisting}
\par
\medskip

\texttt{status(\allowbreak{})\allowbreak{}} 是 \texttt{std:\allowbreak{}:\allowbreak{}net} 的约定：\texttt{NET\_CLOSED} 对端关闭、\texttt{NET\_TIMEOUT} 超时、\texttt{NET\_ERROR} 出错——每种情况都有话说，没有「静默什么都没做」。

发响应只要认真数字节：\texttt{Content-Length} 用 \texttt{len(\allowbreak{}body)\allowbreak{}} 算，\texttt{Connection:\allowbreak{} close} 让每条连接干完一件事就收工，服务端不用管保活。

请求体上限 1 MiB：防异常客户端拖垮内存。超限直接给诊断。

\section{REST 路由：HTTP 语义进，业务语义出}

\texttt{api.\allowbreak{}chl} 只做翻译：方法 + 路径 \ensuremath{\rightarrow} 存取调用 \ensuremath{\rightarrow} \texttt{Reply}（状态码 + JSON）。每个分支三行结构——解析输入、调 \texttt{store}、包错误：

\par
\medskip
\begin{lstlisting}[style=chali]
Reply handle(std::sql::Database mut& database, String method, String path, String query, String body)
{
    if (path == "/api/students" && method == "GET")
    {
        let rows = store::list(&database, queryValue(query, "search"), queryValue(query, "order"),
                               queryValue(query, "desc") == "1");
        if (rows.isErr()) { return errorReply(400, rows.error().toString()); }
        return jsonReply(200, rows.unwrap());
    }
    /* ……POST / PUT / DELETE / GET /api/students/<学号> / /api/schema…… */
    return errorReply(404, "未知接口：" + path);
}
\end{lstlisting}
\par
\medskip

URL 查询串的解码（\texttt{\%E6\%9D\%8E} \ensuremath{\rightarrow} 李、\texttt{+} \ensuremath{\rightarrow} 空格）也在这层做完，业务层拿到的永远是解码后的文本。\texttt{/\allowbreak{}api/\allowbreak{}schema} 直接吐 \texttt{model:\allowbreak{}:\allowbreak{}schema\allowbreak{}Json(\allowbreak{})\allowbreak{}}——前端统计卡上的「模型字段数」就是它，反射一路通到浏览器。

\section{入口：连库、建表、起服务、循环}

\par
\medskip
\begin{lstlisting}[style=chali]
void main(List<String> args)
{
    ServerConfig config = defaultServerConfig();
    /* ……命令行参数覆盖端口与前端目录…… */
    std::sql::Database database = store::connect(&config.database);
    if (!database.isOpen())
    {
        println("错误：连接 MySQL 失败：{}", database.lastError());
        return;
    }
    let schema = store::ensureSchema(&database);
    /* ……建表失败也要先关库再退出…… */
    std::net::TcpListener listener = std::net::TcpListener::listen(config.host, config.port, (int32)16);
    println("学生信息管理系统已启动：http://{}:{}", config.host, listener.localPort());
    while (true)
    {
        std::net::TcpSocket peer = listener.accept((int32)500);
        if (!peer.isOpen()) { continue; }   /* 超时轮询，给 Ctrl+C 留反应机会 */
        serve(&database, &peer, page);
        peer.close();
    }
}
\end{lstlisting}
\par
\medskip

连接是不可复制的值（\texttt{\#Non\allowbreak{}Copyable}），所以它不走 \texttt{Result} 包装——\texttt{store:\allowbreak{}:\allowbreak{}connect} 直接返回连接，未打开时用 \texttt{last\allowbreak{}Error(\allowbreak{})\allowbreak{}} 看诊断，和 \texttt{Database:\allowbreak{}:\allowbreak{}mysql} 同一口径。每条失败路径都记得 \texttt{close(\allowbreak{})\allowbreak{}}：「出错的那条路最容易忘掉清理」。

\texttt{accept} 给 500 毫秒超时：没有连接就回到循环顶上再等，主循环始终保持「能被打断」的状态。

\section{出错时它说什么}

这一章最值得模仿的不是「成功路径」，而是每一条失败都有话说：

\begin{center}
\begin{tabular}{ll}
\toprule
输入 & 响应 \\
\midrule
\texttt{GET /\allowbreak{}api/\allowbreak{}students/\allowbreak{}999} & \texttt{\{"error":\allowbreak{}"学生不存在"\}} \\
\texttt{DELETE /\allowbreak{}api/\allowbreak{}students/\allowbreak{}999} & \texttt{\{"error":\allowbreak{}"学生不存在"\}} \\
\texttt{POST} 学号 0（库里已有 1） & \texttt{\{"error":\allowbreak{}"学号已存在：1"\}}（0 会自动分配） \\
\texttt{POST} \texttt{age:\allowbreak{}200} & \texttt{\{"error":\allowbreak{}"年龄必须在 1 到 150 之间"\}} \\
\texttt{POST} 成绩 101 & \texttt{\{"error":\allowbreak{}"成绩必须在 0 到 100 之间"\}} \\
\texttt{POST} 空 / 非法 JSON & \texttt{\{"error":\allowbreak{}"1:\allowbreak{}1:\allowbreak{} …[\allowbreak{}unexpected-token]\allowbreak{}"\}} \\
\texttt{order=\allowbreak{}badfield} & \texttt{\{"error":\allowbreak{}"模型 Student 没有字段 badfield"\}} \\

五类错误分得清清楚楚：JSON 解析错误来自 \texttt{std:\allowbreak{}:\allowbreak{}json}（带行列位置）、业务校验错误来自 \texttt{validate}（人话）、模型 / SQL 错误来自 \texttt{store}（说明哪个字段不对）、路由错误在 \texttt{api} 兜底、连接层错误在 \texttt{httpd} 有诊断。没有一种是「崩了」或者「静默」。

\section{小结}

\begin{itemize}

\item 一份模型声明，多处复用：建表列、结果集解码、JSON 键、排序白名单都由它派生；

\item 五个模块一棵树：model / store / httpd / api / main 各管一段，依赖单向；

\item MySQL 的值过 \texttt{db.\allowbreak{}quote}，列名只来自反射元数据，排序字段先过白名单；

\item 读出库的数据也再校验一遍，脏数据进不了响应；

\item HTTP 服务要防住空连接：首行阻塞读 + 超时，请求体非阻塞收 + 上限；

\item 每条失败路径都要有诊断，并且都要记得关连接。

\end{itemize}

\section{边界与验证}

反射元数据取决于编译期的注解与产物开关；换用 \texttt{--no-reflection} 或 \texttt{--hard-realtime} 构建时，\texttt{get\allowbreak{}Struct\allowbreak{}Info} 一族不可用，本示例需要写入反射元数据的产物。

\texttt{std:\allowbreak{}:\allowbreak{}sql} 的参数化执行（值走驱动绑定）当前由 SQLite 后端实现；MySQL 后端按文档口径使用 \texttt{db.\allowbreak{}quote} 转义字面量。列名与表名来自编译期模型字段名，不拼接任何用户输入；排序字段经过反射白名单。

HTTP 服务是单线程顺序处理：够课堂演示与课内实验，吞吐不是目标。请求体上限 1 MiB；\texttt{Connection:\allowbreak{} close}，每条连接只处理一个请求。浏览器预连接空套接字按空闲超时关闭，不占用服务逻辑。

模型字段变化会影响既有数据库：新增字段后旧表缺少该列，\texttt{encode\allowbreak{}Rows} 会报「数据库缺少字段」，需要迁移或重建。文本长度按字节计，与数据库列类型要对齐。

\texttt{like} 搜索与排序的稳定性由 MySQL 决定，不要把当前排列当成业务上可靠的次序。

\subsection*{参考解答与验收要点}

\begin{enumerate}

\item 只改 \texttt{model.\allowbreak{}chl} 的 \texttt{struct Student} 一处；建表列、结果集解码、JSON 键、\texttt{/\allowbreak{}api/\allowbreak{}schema} 都由反射派生。旧表会缺列并被「数据库缺少字段」拦下，需要迁移。

\item 以列表 JSON 数组为准核对顺序，不看插入先后；两次学号应连续自动分配。

\item SQL 不报错但影响 0 行；不检查 \texttt{rows.\allowbreak{}affected} 会把「没改到」误报成成功。

\item 在 \texttt{list} 里加一个 \texttt{class\allowbreak{}Name} 精确条件：值必须走 \texttt{database.\allowbreak{}quote(\allowbreak{})\allowbreak{}} 转义（或扩展反射条件构造），同时覆盖空结果和命中两种情况。

\end{enumerate}

\section{番外：目无全牛}

改写自《庄子·养生主》庖丁解牛。

庖丁为文惠君解学生表。手之所触，肩之所倚，足之所履，膝之所踦，字段霍然向然，奏刀騞然，莫不中反射之会。

文惠君曰：“嘻，善哉！技盖至此乎？寡人不过加了一个班级字段，何以你的建表列、JSON 键、界面清单都跟着变了？”

庖丁释刀对曰：“臣之所好者，结构也，进乎手抄矣。始臣之解表之时，所见无非整段字符串者。三年之后，未尝见整表也。方今之时，臣以元数据遇而不以眼抄，依乎模型，批大隙，导大窾，因其固然。”

“良程序员岁更字段表，抄也；族程序员月更正则，猜也。今臣之模型十九次变更矣，所解接口数千矣，而列名清单若新发于声明。”

文惠君大悦，要把所有用户输入原样拼进 SQL，谓顺其自然。庖丁急拦：“虽然，每至于外部输入，吾见其为难，怵然为戒，视为止，行为迟。值须转义，排序列须核准，校验不容省。”

忽有连接未开，庖丁不下刀；又有影响零行，庖丁留诊断。君问何不假装成功，以免扫兴。庖丁揩刀而藏，答曰：“善哉！臣只会顺着结构解牛，不会顺着报表造牛。”

文惠君曰：“善哉！吾闻庖丁之言，得维护系统焉。”随即又补了一条需求：“顺便支持导出 Excel，应该不复杂吧？”

\subsection*{技术对照}

本章的系统就是把「眼睛」换掉的那个过程：字段清单、建表列、JSON 键不靠手抄，从反射给出的结构里长出来（25.3、25.5），模型改了，派生处自动跟上，刀刃不钝。硬拼 SQL 就像砍骨头——值不过转义、排序字段不过白名单，短期看不出事，缺口都在暗处（25.6）。而「怵然为戒」对应的是失败路径：空连接、超时、脏数据、影响 0 行，每一处都认真对待、留下诊断，程序才经得起长久使用（25.7、25.11）。

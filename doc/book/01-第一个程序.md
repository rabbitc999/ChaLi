我们先让计算机显示一句话。这个程序没有输入，也不会创建文件；运行以后，你应该能直接判断结果是否正确。

## 1.1 把程序保存下来

先按[安装说明](../39-installation-packages.md)准备编译器，在一个容易找到的目录里新建 hello.chl。用文本编辑器输入下面四行，保存时使用 UTF-8。

<!-- verify-book -->
```chali
void main()
{
    println("Hello, ChaLi!");
}
```

```text
Hello, ChaLi!
```

第一行 `void main()` 声明程序的入口。main 是名字；空圆括号表示这个例子不接收参数。void 表示这个函数不向调用者交回一个值。现在不必记住其他返回类型，第 4 章会用函数计算一个结果。

第二行的 `{` 开始函数体，第四行的 `}` 结束函数体。程序从这对花括号之间的语句开始工作。

第三行调用 `println`。圆括号里面的 `"Hello, ChaLi!"` 是要显示的文字；双引号划出文字的边界，不会一起打印。println 会在末尾补一个换行。最后的分号结束这条语句，不能用右花括号代替。

## 1.2 在终端里运行

打开终端，进入保存 hello.chl 的目录，输入：

```sh
chali run hello.chl
```

chali 是编译器命令，run 要求它编译并运行程序，hello.chl 是输入文件。成功后，终端会显示前面的那一行问候。

如果提示找不到 chali，先检查编译器是否在 PATH 中，或者使用编译器的完整路径。如果提示找不到 hello.chl，检查当前目录和实际保存的文件名。此时还没有执行第三行 println，改问候文字不能解决路径问题。

## 1.3 做两次小改动

先把双引号里的文字换成自己的名字，再运行一次。接着在原来的调用下面增加一行：

```chali
    println("这是我的第二行输出。");
```

两条调用会从上到下执行，因此会显示两行。现在删掉第二条调用后面的分号，运行看看。编译器会在执行程序之前报告语法问题。读第一条消息，回到刚才改动的位置，补回分号，再试一次。

故意制造一个小错误，是认识诊断的办法。一次只改一个地方，才容易把错误和原因对应起来。

## 1.4 只检查，不执行

有时你只想知道代码是否满足语言规则，可以使用：

```sh
chali check hello.chl
```

这一行通过时不会打印问候。它检查程序，却不运行 main；run 才会在检查和编译成功以后执行程序。以后遇到输入、文件和网络操作，这个区别会很有用。

目前只需知道：run 会生成本机原生程序再执行。编译和导出的具体过程留到第 27 章；你不需要先学习 LLVM 才能继续写程序。

## 1.5 习题

1. 输出自己的名字和今天打算学习的内容，各占一行。
2. 在文字里面放一个分号，观察它和语句末尾的分号有什么区别。
3. 执行 check 和 run，分别记录终端输出。
4. 故意把 main 拼错，再根据诊断改回来。

### 参考解答与验收要点

1. 在同一对花括号里写两条 println，运行后应有两行文字。
2. 双引号里面的分号是数据；引号外面的分号结束语句。
3. check 成功时没有问候输出；run 成功时执行两条输出语句。
4. 程序仍需有合法入口；检查通过以后再核对运行结果。

下一章会让程序根据输入作出不同回答。你可以先保留这个小文件，遇到工具问题时用它确认运行环境。

## 1.6 番外：皇帝的新程序

改写自安徒生《皇帝的新装》。

许多年以前，有一位皇帝，为了运行得漂亮，不惜把所有的钱都花在买新程序上。他既不关心输入，也不关心输出，除非是为了炫耀他的新基准。他每一天钟头都要换一套编译选项。人们提到他，总是说：“皇上在优化器里。”

有一天来了两个骗子，自称能编出人类所能想象的最快程序。这程序还有一种奇怪的特性：凡是不称职或愚蠢得不可救药的人，都看不见它的输出。

“这正是我理想中的程序！”皇帝想，“有了它，我就能知道群臣里谁不懂技术。”于是付了许多预算，叫他们立刻开工。骗子架起两台显示器，整日敲空格；最好的服务器和显卡，却都装进了自己的口袋。

老大臣奉命去看，睁大眼睛，只见 `void main() {}`。他不敢说自己什么也没看见，便连连点头：“多么优美的输出！多么鲜艳的性能！”骗子请他描述结果，他说：“非常符合预期。”因为预期也没有写。

游行那天，皇帝举着空屏幕，内臣托着并不存在的进度条。百姓齐声称赞：“运行得真快！连日志也没有！”谁也不愿显得自己不称职。

“可是它什么也没做呀！”一个孩子终于叫了出来。

皇帝有点发抖，因为他觉得孩子说的似乎是对的。他心里却想：“这发布会必须坚持到底。”于是更加骄傲地举着屏幕，内臣们继续托着那根根本不存在的进度条。

### 技术对照

通过语法和类型检查，只能证明对应静态检查通过。程序是否产生预期输出、是否访问了外部资源，需要运行验证；外部输入变化也可能使后续运行失败。

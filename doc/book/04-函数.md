# 第 4 章 函数

<!-- LANGUAGE NAVIGATION -->
[English](en/04-functions.md) · **简体中文**

给成绩增加奖励分并不复杂。但如果三个地方都要做这件事，复制三遍计算就容易漏改。函数把这项工作起一个名字：调用时给它输入，它把结果交回来。

## 4.1 从调用处进入函数

<!-- verify-book -->
```chali
int64 addBonus(int64 score, int64 bonus)
{
    score += bonus;
    return score;
}

void main()
{
    int64 score = 70;
    int64 result = addBonus(score, 5);
    println("{} {}", score, result);
}
```

```text
70 75
```

先看 main 中的 `int64 score = 70;`，它建立调用方的变量。下一行调用 `addBonus(score, 5)`：第一个实参是当前的 70，第二个是 5；执行会暂时进入上面的函数体。

再看函数头。最左边的 int64 说明返回结果的类型，addBonus 是函数名，括号里的两个声明是形参。形参按位置接收实参，名字不要求与调用方相同。

函数体第一行把本次调用里的 score 增加 bonus。第二行 `return score;` 把 75 交给调用者，并结束这次函数调用。main 用 result 保存这个返回值，再继续执行 println。

输出中的原 score 仍然是 70。普通整数按值传入，函数里的 score 是另一个绑定。同名不意味着共享修改；第 8 章会用可变引用明确表达写回调用方的需要。

## 4.2 让一部分输入有默认值

如果大多数时候都奖励 5 分，可以把函数头写成下面这样；函数体仍使用前面的两条语句。

```chali
int64 addBonus(int64 score, int64 bonus = 5)
```

此时 `addBonus(70)` 省略第二个实参，使用默认的 5；`addBonus(70, 10)` 明确提供 10。默认值是缺少某个实参时的选择，不会覆盖已经写出来的实参。

重载是另一种情况：同一个名字可以有不同的参数类型或数量，编译器据此选择版本。只改变返回类型不能单独区分两个重载。第 3 章的两个 floatingKind 正是用参数类型区分的。

## 4.3 没有结果和多个结果

输出函数可以做事而不交回业务结果，这类函数使用 void。return 后面不带值，可以提前结束 void 函数；如果函数声明返回 int64，就需要在正常结束路径交回符合类型的值。

需要多个相关结果时，可以把它们组成元组。先看这个很小的表达式：

```chali
let pair = (70, 80);
let (first, second) = pair;
```

第一行把两个值放在一个元组里。第二行把它拆成两个名字，first 得到 70，second 得到 80。函数也能返回元组；写完整返回类型时，使用相应的元组类型。正文后面会在数据处理例子中继续使用解构，详细形式在附录 C。

变长参数允许一次调用接收多个同类实参。阅读这类函数时，先弄清形参是否可变长、每项是什么类型，再看它怎样遍历这些值；不需要把变参与默认参数、重载一次混用。

## 4.4 让名字说明工作

调用 addBonus 时，我们应该能够知道传入的是分数和奖励，得到的是新分数。如果一个函数还悄悄读取文件、修改别的对象，调用者就难以预测它。后面学习错误和资源时，会用明确的参数及返回类型把这些关系写出来。

return 也能接收计算出来的表达式。不管表达式写成加法还是控制结构，都是先取得结果，再结束函数。等第 5 章学过控制流以后，可以到附录 C 看更紧凑的组合写法。

## 4.5 习题

1. 调用 addBonus(70, 5) 后，main 中原来的 score 是多少？
2. 把函数内部的形参 score 改叫 original，需要改哪些地方？
3. 使用默认奖励 5，分别调用一次省略和一次提供第二参数的版本。
4. 函数返回 75 和函数直接打印 75，调用方能做的事情有何不同？

### 参考解答与验收要点

1. 仍为 70，返回的 75 保存在 result 中。
2. 修改函数头和函数体里的对应引用；main 的变量名不必修改。
3. 省略时使用 5，明确传入 10 时应得到 80。
4. 返回值可以保存或继续计算；直接打印只产生输出，不能代替一个需要数值的返回结果。

## 4.6 番外：三调辨妖函数

改写自《西游记》三打白骨精一节。人物的“辨妖”仅作函数输入输出的比喻。

却说师徒行到白虎岭，唐僧腹中饥饿，八戒便写了一道辨妖函数，拍胸道：“师父放心，徒弟这个接口，已经验收过两遍。”悟空看时，函数腹内只有一句固定的“不是妖”。

那白骨精头一次变作少女，提着饭来。八戒调用函数，果然不是妖；第二次变作老妇，函数仍说不是妖。唐僧喜道：“两次调用，结果一致，可见十分稳定。”悟空道：“师父，那石头扔进井里也很稳定，不见得会辨妖。”

第三次老翁到了，八戒还欲调用。悟空一棒拦住终端，问：“你这一回把来者的什么信息传了进去？”八戒道：“前两次都没传，到了第三次才加参数，岂不破坏兼容？”

唐僧听见“兼容”二字，便要念紧箍咒。沙僧忙上前道：“大师兄说得是。调用次数多，不等于分支覆盖多。”

悟空将观察结果作为参数，把每条判断路径写明。妖精无计，只得化作原形。八戒仍不服：“我的函数也有返回值！”悟空笑道：“你那叫占卜，不叫计算。”

后来八戒补上单元说明：“无论传入什么，都返回不是妖。”这回沙僧倒说接口与实现一致了，只是师父坚决不肯再拿它买盒饭。

### 技术对照

局部变量只在其作用域内有效。按值参数修改的是自己的值；要修改调用者对象，接口必须明确使用相应可写引用。返回值应覆盖函数承诺返回的路径。

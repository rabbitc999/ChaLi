# 第 4 章 函数

<!-- LANGUAGE NAVIGATION -->
[English](en/04-functions.md) · **简体中文**
<!-- END LANGUAGE NAVIGATION -->

当一段成绩计算在多个地方出现时，可以把它收进函数，用参数表达变化的输入，用返回值表达结果。这样既能复用，也能单独验证；调用方只需理解明确的接口，而不必复制整段实现。

本章先用整数观察按值传参，再阅读能产生返回值的块与控制表达式。先建立普通调用的执行模型，后续的引用参数、资源转移和函数值都可以在此基础上逐项比较。

## 4.1 参数与返回类型

先把“给分数加奖励分”看作一项独立工作。调用方提供原分数和奖励值，函数把计算结果交回来。签名将这三部分分别写成两个形参和一个返回类型，函数体再说明怎样计算。

这里使用普通整数的按值参数，因此可以先把调用想成“把数值交给这次调用”。函数里的 score 与 main 的 score 是不同绑定；返回值由 result 保存。下面通过同时打印原值与结果来验证这层关系。

<!-- verify-book -->
```chali
int64 addBonus(int64 score, int64 bonus)
{
    score += bonus;
    return score;
}

void main()
{
    int64 score = 70;
    int64 result = addBonus(score, 5);
    println("{} {}", score, result);
}
```

```text
70 75
```

### 代码详解

main 中的 score 初始为 70。调用 addBonus 时，两个实参分别对应形参 score 与 bonus；函数内同名的 score 是自己的按值参数。`score += bonus` 将这份值改为 75，return 把它作为调用结果交回 result。

控制流随后回到 main 的 println，调用方 score 仍是 70，result 为 75，所以输出两者不同。想让函数修改调用方变量，需要设计显式可变引用接口；仅仅让形参与实参同名不会建立共享关系。


## 4.2 重载、默认参数与变参

重载根据参数类型和数量选择候选；返回值类型不单独决定重载。默认参数补充省略的尾部实参。变长参数用于数量可变的调用，其元素类型及展开规则见语言参考。候选不唯一时应补足类型或调整接口，不依靠声明先后决定结果。

## 4.3 多个结果与带值控制流

多个结果可组成元组，调用方用解构接收。return 后面也可以是产生值的块、条件或循环；yield 给最近接收值的控制表达式提供结果，return 结束函数。先辨认退出的是函数还是控制表达式，再判断清理和后续执行位置。

<!-- verify-book -->
```chali
int64 fromBlock()
{
    return
    {
        int64 local = 3;
        yield local;
    };
}

int64 choose(bool first)
{
    return if (first)
    {
        yield 5;
    }
    else
    {
        yield 6;
    };
}

int64 fromMatch(int64 item)
{
    return match (item)
    {
        0 => { yield 7; }
        _ => { yield 8; }
    };
}

int64 fromLoop()
{
    return loop
    {
        yield 9;
    };
}

void main()
{
    println("{} {} {} {}", fromBlock(), choose(false), fromMatch(0), fromLoop());
}
```

```text
3 6 7 9
```

### 代码详解

四个函数分别把块、if、match 和 loop 当作能产生值的表达式，再由外层 return 返回。`yield` 把值交给当前求值结构；它与函数的 return 不处在同一层次。fromBlock 的 local 只在块内使用，交出的整数为 3。

`choose(false)` 选择 else，得到 6；`fromMatch(0)` 进入 0 分支，得到 7；fromLoop 第一轮就 yield 9，结束该循环表达式。main 按这四个调用填入占位符，所以输出 3、6、7、9。每个函数仍须保证交出的值符合声明的 int64，不能因为用了控制表达式就省略类型检查。


## 4.4 把接口写成调用契约

只读输入、需要写回的对象和可能失败的计算应在签名中区分：分别使用合适的值／引用参数以及 Option／Result 返回。main 作为可执行入口返回 void，可无参数，或接收 List<String> 命令行参数。原生库导出入口另见第 21、24 章。

### 小结

每次调用都可以标出实参、形参、函数内修改和返回位置。函数内发生变化，不代表调用方变量也改变；要看传递的是拥有值还是借用，以及是否明确允许写回。

当返回表达式本身含 if、match 或循环时，先求出该表达式的值，再由 return 结束函数。下一章将专门跟踪这些控制结构，让“哪条路径执行”与“哪一层接收结果”都能说清楚。

## 4.5 习题

1. 调用 addBonus 后原成绩是多少？
2. 增加同名的 float64 版本并显式选择实参类型。
3. 用元组返回总分和人数。
4. 解释 yield 与 return 的接收者。

### 参考解答与验收要点

1. 仍为 70，返回结果为 75。
2. 参数表不同，调用时核对重载选择。
3. 声明元组返回类型，在调用方解构并分别核对。
4. yield 对应带值控制表达式；return 对应函数。

## 4.6 番外：三调辨妖函数

改写自《西游记》三打白骨精一节。人物的“辨妖”仅作函数输入输出的比喻。

却说师徒行到白虎岭，唐僧腹中饥饿，八戒便写了一道辨妖函数，拍胸道：“师父放心，徒弟这个接口，已经验收过两遍。”悟空看时，函数腹内只有一句固定的“不是妖”。

那白骨精头一次变作少女，提着饭来。八戒调用函数，果然不是妖；第二次变作老妇，函数仍说不是妖。唐僧喜道：“两次调用，结果一致，可见十分稳定。”悟空道：“师父，那石头扔进井里也很稳定，不见得会辨妖。”

第三次老翁到了，八戒还欲调用。悟空一棒拦住终端，问：“你这一回把来者的什么信息传了进去？”八戒道：“前两次都没传，到了第三次才加参数，岂不破坏兼容？”

唐僧听见“兼容”二字，便要念紧箍咒。沙僧忙上前道：“大师兄说得是。调用次数多，不等于分支覆盖多。”

悟空将观察结果作为参数，把每条判断路径写明。妖精无计，只得化作原形。八戒仍不服：“我的函数也有返回值！”悟空笑道：“你那叫占卜，不叫计算。”

后来八戒补上单元说明：“无论传入什么，都返回不是妖。”这回沙僧倒说接口与实现一致了，只是师父坚决不肯再拿它买盒饭。

### 技术对照

局部变量只在其作用域内有效。按值参数修改的是自己的值；要修改调用者对象，接口必须明确使用相应可写引用。返回值应覆盖函数承诺返回的路径。

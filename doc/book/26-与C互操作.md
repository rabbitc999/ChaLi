# 第 26 章 C ABI 与宿主互调

<!-- LANGUAGE NAVIGATION -->
[English](en/26-c-interop.md) · **简体中文**
<!-- END LANGUAGE NAVIGATION -->

已有 C 库能提供数据库、系统服务和成熟算法，但跨过语言边界以后，双方必须对参数宽度、布局、指针、返回值与资源责任达成一致。一个能被找到的符号，并不自动等于一个能被正确调用的函数。

本章按原型声明、数据封送、资源与错误、同步回调的顺序建立接口。短片段只展示声明方式，完整运行还依赖真实动态库及相符目标；部署时同样需要带上应用实际依赖的库。

## 26.1 声明真实的宿主原型

接入外部库时，从库提供的真实 C 原型开始，而不是先猜一份容易编译的 ChaLi 声明。先确认函数名、返回值和每个参数，再核对整数宽度、指针方向及结构体布局；符号存在只是第一步。

#abi 把这份语言侧声明与调用约定、动态库和导出符号连接起来。int64 不能统一代替所有平台的指针或整数，声明也不会自动修正不匹配的外部实现。

完整可运行例程见 [C ABI 缓冲区示例](../examples/abi_buffers/demo.chl)；需要先构建其 native.c 动态库。

例如 C 的 int32_t bump(int32_t *value) 需要按真实返回类型和指针原型声明；若 C 原型实际返回 void，就不能照抄 int32 返回。下面的声明对应 void bump(int32_t*)，调用传入 &value：

```chali
#abi("C", "./native.dll", "bump")
void bump(int32 mut& value);
```

#abi 将下面的声明关联到指定动态库中的 C 符号 bump。三个字符串分别说明调用约定、库路径和符号名；`void bump(int32 mut& value);` 只有原型，末尾分号表示这里没有 ChaLi 函数体。宿主实际实现必须与这个签名及目标平台 ABI 相符。

mut& 表达外部函数可能写回传入的整数来源，void 表示没有普通返回值。该片段不能独立运行，还需真实 native.dll、相符的导出符号与调用代码。不能仅将文件后缀改为另一系统的形式就认为已完成移植，也不能把 ChaLi 逻辑地址自行当成 C 指针。


库路径相对声明所在源文件解析，本地函数名可以与导出符号名不同。完整结构体、数组和可选引用示例由本节链接工程提供。

宿主还可以把已登记的 C 入口关联到语言接口方法。下面沿用编译器内置的计数器演示入口，完整源码见 [C API 接口关联示例](../../example/samples/c_api_host.chl)，C 实现在 [abi_demo.c](../../source/abi/abi_demo.c)。

<!-- verify-book -->
```chali
type HostHandle<T> = uint64;
impl uint64 : ExplicitConvert<HostHandle<int32>> = demo_counter_from_uint;
impl HostHandle<int32> : ExplicitConvert<uint64> = demo_counter_to_uint;

interface HostValue {
    int64 hostValue();
};
impl HostHandle<int32> : HostValue = demo_counter_to_uint;

void main()
{
    HostHandle<int32> counter = cast<HostHandle<int32>>((uint64)42);
    println("{}", counter.hostValue());
}
```

```text
42
```

第一行声明保存 `uint64` 的具名泛型句柄。接下来的两条 `impl` 指定整数与句柄之间的显式转换入口；`cast` 使用这些转换，不把语言句柄当成 C 指针。

`HostValue` 声明一个返回 `int64` 的方法。它下面的 `impl` 把这个方法关联到 C 函数表中的 `demo_counter_to_uint`。`main` 先把 42 转成具体句柄，再调用接口方法并打印 42。函数表中的名字只用于查找登记入口，不能代替任意机器函数地址。

## 26.2 引用、数组与封送

单对象引用与数组参数不是同一种声明。宿主数组约定需要长度和有效缓冲区；返回数组必须使用支持的长度标注。语言侧数组对象本身不能直接当作机器缓冲区地址。变长数据还要核对由哪一方分配、复制、修改和释放。

## 26.3 资源和错误边界

检查库的错误返回值，并在所有返回路径关闭句柄。宿主返回的借用若指向会复用的内部缓冲区，应按文档规定取得稳定副本。原生库可以违反自身原型或写越界；语言的静态检查不能验证外部二进制的全部行为。

## 26.4 函数值与同步回调

同步回调沿受支持的宿主上下文与函数值接口调用，需核对参数、返回值、闭包、重入和错误传播。捕获环境的函数值不是机器函数指针，不能只改类型就获得合法 C 回调。部署还必须准备实际使用的外部库及许可证。

### 26.4.1 用 C 函数表提供宿主能力

前面的 `#abi` 声明从 ChaLi 调用已有的 C 原型。另一种接入方式是由宿主登记函数，让运行时按名称调用。公开入口见 `source/abi/chali_abi.h`；完整 C11 程序见 [C 宿主示例](../../example/host-c-api/main.c)，构建方法见[示例说明](../../example/host-c-api/README.md)。

先看示例中的加法入口：

```c
/**
 * @brief 把两个已经检查的整数槽相加。
 * @param frame 本次同步调用帧。
 */
static void CHALI_ABI_CALL add(ChaliAbiFrame *frame)
{
    int64_t left = 0, right = 0;
    if (!chali_abi_argument_integer(frame, 0, &left)) return;
    if (!chali_abi_argument_integer(frame, 1, &right)) return;
    chali_abi_return_integer(frame, left + right);
}
```

`ChaliAbiFrame` 描述这一次调用，实参存放在带类别的 64 位槽中。`chali_abi_argument_integer` 同时检查下标和槽类别；检查失败就返回，避免继续执行后面的计算。最后一行把整数写入返回槽。示例传入 20 和 22，结果为 42。

登记入口时还要提供目标描述和参数数量。下面是完整程序中的登记资料，使用了已经声明的 `add`：

```c
ChaliAbiInfo abi = chali_abi_local_info(0);
const ChaliAbiRecord records[] = { { "host::add", add, 2 } };
const ChaliAbiModuleDescriptor module = {
    sizeof(module), &abi, records, 1
};
```

第一行由当前 C 编译器填写版本、目标、调用约定和结构布局，不能拿另一目标的固定数字代替。第二行将名称、入口和两个实参关联起来。最后的模块描述把整张表交给 `chali_abi_registry_register`；调用方检查它返回的状态，再决定是否继续。

完整程序先用 `chali_abi_registry_create` 创建表，再登记、封存、调用，最后用 `chali_abi_registry_destroy` 释放。登记会复制名称，入口代码本身仍需存活。整模块发生重名或分配失败时，本次新入口全部撤销；封存以后继续允许查询与调用，不再允许修改表。

错误文本写入调用方提供的 `ChaliAbiError` 缓冲区，状态码仍需单独检查。C 入口可以调用 `chali_abi_fail` 报告失败；失败之后，部分返回值不会成为成功结果。宿主不得把 C++ 异常抛过公开 C 边界。

### 26.4.2 字节视图、拥有值与回调上下文

上面的加法不访问语言堆，例子里的 `frame.runtime` 可以为空。字符串、逻辑内存、宿主记录和语言函数值需要运行时提供的上下文。不透明句柄只能从相应接口取得，不能在 C 中伪造一个上下文来使用这些服务。

`chali_abi_bytes` 返回字节视图及其长度，视图不保证有末尾零字节。处理完这次同步借用后就停止使用；发生分配、增长、释放或重新进入语言代码时，不再沿用旧指针。需要稳定文本时先在自己的有效存储中保存副本，并按实际长度处理。

`chali_abi_string` 把输入字节复制成语言字符串，成功取得的拥有句柄由 `chali_abi_string_release` 配对释放。临时逻辑缓冲区则使用 `chali_abi_temporary` 与 `chali_abi_temporary_release`。生成的聚合适配使用 `chali_abi_tracked_temporary` 登记到运行时临时清理队列；提前释放会移除登记，避免地址复用后再次清理。这些句柄和 `malloc` 返回的 C 指针有各自的管理者，释放时使用与创建接口相配的函数。

宿主需要调用带捕获环境的 ChaLi 函数值时，使用 `chali_abi_invoke`，同时传入槽类别并检查返回类别。运行时负责保留环境、处理同步重入和传播错误。`#abi` 原型中的机器回调由适配器建立同步跳板；运行时函数句柄本身不能强转为机器函数指针。

可以沿 [真实 C 宿主](../../tests/fixtures/c_api_library_host.c)与 [C 回调库](../../tests/fixtures/c_api_owned_callback.c)阅读一次完整往返：C 函数表调用导出的 ChaLi 函数，ChaLi 创建捕获偏移量的闭包，C 库通过同步跳板调用它并返回拥有文本。语言适配器在传播结果或错误前，按约定释放 C 返回缓冲区。例子的正常结果为 42，缓冲区释放一次。

### 小结

宿主接口可以按“原型是否一致、数据如何过边界、谁拥有资源、错误如何返回”逐项审查。输入与输出指针、单对象引用和连续数组、借用缓冲区与拥有副本，都要明确区分。

带环境的函数值通过受支持回调协议调用，不能靠强转成机器指针省略环境与错误传播。进入底层时把复杂性封装在小范围，向业务层提供可检查的普通接口。

## 26.6 番外：借来的梨树与指针

改写自《聊斋志异·种梨》。

有乡人货梨于市，颇甘芳，价腾贵。有道士求一梨，乡人叱之。旁人买而赠焉。道士食尽，留核，掘地埋之，俄而一树，枝叶扶疏，累累有梨，请众人任取。

乡人看得心热，忙将树的位置记在纸上，欲待散场，日日来摘。道士斫树而去，乡人依旧址伸手，只抓得一把尘土。乃怒曰：“这地址未变，梨何故不在？”

道士回身曰：“君记住地址，未曾取得所有权。对象既去，地址尚存，有何稀奇？”乡人仍不服，把旧指针换一个更大的整数，以为范围变宽，梨便能多活几天。

旁一木匠接过枝条，约定只在眼前加工。乡人又将这口头保证写成永久回调，待人散尽，遥唤木匠，哪还有上下文应答？

道士指着三个字教他：“谁创建，谁释放；借多久，何时用。跨语言的墙，挡不住生命周期的账。”

乡人回看梨车，梨已尽失，连车把也不知去了哪里。他捏着那张地址单，终于明白：ABI 对上，不过说明门牌格式认得；门后有没有人、谁有权搬家，仍须另外说清。

### 技术对照

ABI 一致只是互操作的前提之一。指针、字符串、回调上下文的拥有与有效期必须明确；同步回调靠函数值里的运行期地址，它只在这条线程、这次调用里有效，不能缓存成通用机器入口。

# 第 15 章 测试与调试

<!-- LANGUAGE NAVIGATION -->
[English](en/15-testing-debugging.md) · **简体中文**
<!-- END LANGUAGE NAVIGATION -->

程序运行过一次，不等于每次修改以后仍然正确。上一章我们区分了成功和失败，这一章把这些判断写成可以反复执行的小检查，为日志项目做准备。

## 15.1 把预期写成断言

<!-- verify-book -->
```chali
int64 addBonus(int64 score, int64 bonus)
{
    return score + bonus;
}

void main()
{
    assert(addBonus(70, 5) == 75);
    assert(addBonus(0, 5) == 5);
    println("checks passed");
}
```

```text
checks passed
```

第一段是被检查的计算。它只接收两个数并返回一个数，因此不需要准备文件、键盘输入或网络。

main 的第一条 assert 把一次调用和预期的 75 放在一起。条件成立，继续下一行；不成立，就报告失败。第二条用 0 作输入，检查另一个情况。只有前两条都通过，最后的 println 才会执行。

把第一条的 75 暂时改成 76，再运行。这样观察到的是“检查发现了不一致”，而不是“加分算法突然改变”。改回以后，输出应该恢复。自己制造一次失败，有助于确认测试真的检查了你想检查的结果。

## 15.2 一个测试只说明一件事

可以把几条相关断言放进一个函数，例如 testOrdinaryScore。函数名帮助人阅读，但不会使它自动执行；在当前这种写法里，仍要从 main 调用它。

测试输入不要只挑最顺手的一种。字符串查找至少要想一想：找得到、找不到、空文本、大小写不同、中文、最后一行没有换行。列表访问还要想到第一项和最后一项。边界来自程序承诺的行为，不是为了凑很多条断言。

下面是一项很小的文本检查：

<!-- verify-book -->
```chali
import std::text;

void main()
{
    assert(std::text::Text::contains("ERROR disk", "ERROR"));
    assert(!std::text::Text::contains("INFO ready", "ERROR"));
    println("search checked");
}
```

```text
search checked
```

第一条选一个肯定包含关键词的输入。第二条在 contains 前加 `!`，要求它确实返回假。若把同一个输入抄到两条断言里，却忘了改变预期，就可能只是在重复检查同一种情况。

## 15.3 先测计算，再测外部动作

日志工具需要读取文件，但“哪几行匹配”不依赖文件放在哪个目录。让搜索函数接收字符串并返回匹配项，就能先用几行固定文本测试算法。读取文件的函数再单独检查路径不存在、读取失败和容量限制。

到 HTTP 项目时也会这样分开：先给请求解析函数一段固定文字，再用真实 TCP 连接检查分段到达和断开。纯计算的小例子便于定位问题，真实交互则检查几个部分能否合作。

运行测试时保留输入、预期结果与实际诊断。不要因为想看到绿色结果，就把正确的边界断言删掉；先判断究竟是预期写错，还是实现违背了约定。

## 15.4 从一条错误读回代码

遇到诊断，先看它发生在哪一阶段。语法错误还没有进入业务计算；类型错误说明某种组合不合法；断言失败则表明程序已经运行，并观察到了不符合预期的结果。

回到最小的失败例子，只留下复现它所需的函数和数据。给中间值增加一条 println，可以帮助核对路径；定位以后再删除临时输出，恢复测试的明确结果。需要逐步运行时，使用带调试信息的原生产物，工具用法见[原生调试说明](../README.md)。

### 反例：未导入模块就调用函数

完整限定名说明函数属于哪个模块，但不会自动加载模块。下面故意省略 `import std::math;`；`sqrt` 的名称和实参正确，检查仍会在调用处失败。

<!-- verify-book-error: check -->
```chali
void main()
{
    std::math::sqrt(4.0);
}
```

```text
未导入模块：std::math；请先添加 `import std::math;` 后再调用：std::math::sqrt
```

这是语义检查错误，程序尚未运行。在文件开头补上 `import std::math;` 后，调用才能参与函数与重载检查。`std::gui::drawText` 也遵循同样的规则：缺少 GUI 模块时应先添加 `import std::gui;`；模块已加载而函数名拼错时会报告“模块中未定义函数”，参数不匹配时则报告重载错误。附录的[GUI 未导入示例](A-常见错误速查.md#a8-未导入模块)展示了这两步检查。

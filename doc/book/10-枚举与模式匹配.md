# 第 10 章 枚举与模式匹配

<!-- LANGUAGE NAVIGATION -->
[English](en/10-enums-patterns.md) · **简体中文**
<!-- END LANGUAGE NAVIGATION -->

请求可能等待、成功或失败，这些状态不能同时成立，各自需要的数据也不同。枚举把选择写进类型，避免用几个互不约束的布尔值和可空字段拼出不合法组合。

本章先构造带载荷的状态，再通过 match 取得局部数据，观察复制、通配与派生。核心阅读顺序是先识别变体，再处理该变体携带的值；分支中的操作因此有明确前提。

## 10.1 状态与载荷

考虑一个数据包：它要么没有内容，要么带着文本。若只用一个 String，就难以区别“空包”和“内容恰好为空字符串”；若再加一个布尔标记，又要额外维护标记与字段的一致性。枚举可以直接把两种状态列出来。

Data 的 String 只属于 Data，Empty 不要求这份载荷。使用者通过 match 确认状态，再在对应分支处理文本。需要结果时，各种可达状态都应提供结果，不能先假定某种载荷总是存在。

<!-- verify-book -->
```chali
enum Packet
{
    Data(String text), Empty
};
void main()
{
    Packet packet = Packet::Data("original");
    String label = match (packet)
    {
        Packet::Data(text) =>
        {
            text = "copy";
            yield text;
        }
        Packet::Empty =>
        {
            "empty"
        }
    };
    String original = match (packet)
    {
        Packet::Data(text) =>
        {
            text
        }
        Packet::Empty =>
        {
            "empty"
        }
    };
    println("{} {}", label, original);
}
```

```text
copy original
```

### 代码详解

Packet 是二选一的枚举：Data 带 String 载荷，Empty 不带载荷。packet 当前为 Data，因此两个 match 都进入 Data 分支；列出 Empty 是为了覆盖另一个合法状态，使表达式对全部变体都有结果。

第一次匹配把载荷按值绑定为 text，把这份绑定改成 copy 后 yield 给 label；它不写回 packet。第二次匹配重新读取 packet，仍得到 original，所以输出 `copy original`。同名 text 属于各自分支作用域，不能因为第一次出现过就认为第二次复用了那份已修改的变量。


## 10.2 多个载荷与通配

多个载荷按声明顺序写入括号。普通载荷可以直接绑定变量；不需要的载荷写 _。如果载荷是接口，类型细分使用 Type value 形式，外层枚举仍写出。第 13 章再说明接口值的具体类型匹配。

<!-- verify-book -->
```chali
enum Event
{
    Idle,
    Message(String sender, String text)
};
void main()
{
    let event = Event::Message("Ada", "ready");
    match (event)
    {
        Event::Idle => { println("idle"); }
        Event::Message(sender, text) => { println("{}: {}", sender, text); }
    }
    match (event)
    {
        Event::Idle => { println("idle"); }
        Event::Message(_, text) => { println("{}", text); }
    }
}
```

```text
Ada: ready
ready
```

### 代码详解

Message 声明两个有顺序的载荷字段，构造时 Ada 对应 sender，ready 对应 text。第一次 match 把两个位置都绑定到变量，因此能组合输出 `Ada: ready`；Idle 分支在本次不会执行。

第二次匹配用 `_` 忽略第一个载荷，只保留 text，所以只打印 ready。忽略意味着不需要这个局部绑定，不会删除 event 中的发送者数据。枚举变体名决定选哪一支，括号中的位置再决定从该变体提取哪些值，这两个步骤要分开读。


## 10.3 复制与派生能力

载荷沿用其类型的值、借用和资源规则。复制一个带 String 的枚举后，修改副本不会通过值语义改变原值；引用载荷则仍然表达借用关系。不要把枚举包装当成取消所有权检查的方法。

<!-- verify-book -->
```chali
#derive(Equal, Hash, Clone)
enum BookPacket
{
    Empty,
    Text(String text)
}

void main()
{
    BookPacket first = BookPacket::Text("value");
    BookPacket second = first.clone();
    assert(!(first == BookPacket::Empty));
    println("{} {}", first == second, first.hash(first) == second.hash(second));
}
```

```text
1 1
```

### 代码详解

派生为 BookPacket 提供比较、哈希和克隆。first 持有 Text("value")，克隆后的 second 应保持相同变体及载荷。assert 先检查 Text 与 Empty 不相等：即使不比较字符串，两者的变体身份也不同。

println 接着检查 first 与 second 相等，并检查它们的哈希一致，所以两个布尔结果都为真。派生需要同时考虑变体与载荷，不能只对 Text 的字符串做比较而忘记枚举状态。哈希值本身没有在这里输出，也不应被当作稳定的外部编号保存。


## 10.4 将 match 用于计算

match 也可以产生值，各分支结果必须满足共同类型要求。避免在后面依靠断言猜测变体：把需要载荷的操作写进对应分支，使类型和控制流一起记录前提。Option 和 Result 是这种结构在缺省与错误处理中的应用。

### 小结

枚举定义可能状态，match 连接状态与处理路径，载荷变量只在对应分支中承担已知类型的数据。需要产生结果时，再核对分支覆盖和结果类型，而不是在匹配以后反复猜测状态。

Option 和 Result 将同样的结构用于缺失与失败，第 16 章会详细展开。接下来先把这些有类型的值组织进容器。

## 10.6 番外：大灰狼漏掉的分支

改写自传统童话《三只小猪》。

从前有三只小猪，离家各自造屋。老大造了一间草屋，老二造了一间木屋，老三造了一间砖屋。大灰狼听见商机，连夜写了一份拆屋程序，号称支持一切建筑，实际只有两个分支。

大灰狼来到草屋前，说：“小猪，小猪，让我进来。”小猪说：“不让你进来！”狼于是深吸一口气，一吹，草屋倒了。测试通过。

它又来到木屋前，说：“小猪，小猪，让我进来。”小猪仍不让。狼按手册一推，木屋倒了。测试覆盖率百分之百——因为它只把自己会的两种房屋登记进了统计表。

到了砖屋，狼又吹又推，房子不动。它翻到兜底分支，那里写着：“其余按木屋处理。”第三只小猪隔窗问：“你这叫兼容砖屋，还是把砖屋改名成木屋？”

狼想从烟囱钻进去，跌进一口热锅。锅底贴着错误信息：“未知变体，拒绝执行。”

三只小猪没有再争论兜底分支短不短。它们把房屋分成清楚的变体，让每种结果都有去处。大灰狼后来改行做代码审查，见到 `_` 就先问一句：“这个以后会不会装下一口锅？”

### 技术对照

枚举变体表达有限分类。match 的覆盖与守卫需要一起考虑；兜底分支可能隐藏新增变体，重叠警告也不应被误写成所有场合都拒绝编译。

# 附录 A 常见错误速查

<!-- LANGUAGE NAVIGATION -->
[English](en/A-common-errors.md) · **简体中文**
<!-- END LANGUAGE NAVIGATION -->

排查错误时，先确认程序在哪一个阶段停止，再解释触发失败的前提。解析、类型检查、链接与运行各自有不同输入；把所有问题都当成“运行崩溃”，会让修复落在错误的位置。

本附录按常见失败展示最小例程、典型诊断和处理思路。每段详解明确区分声明是否合法、哪一步被拒绝、后续语句是否执行。诊断中的路径与行号用于定位本次文件，不要求在不同保存位置保持相同文字。

## A.1 定位阶段

| 阶段 | 检查内容 | 后续动作 |
| --- | --- | --- |
| 解析 | 标点、括号与声明结构 | 从首个语法错误修正上下文 |
| 类型与借用 | 实参与返回类型、引用来源、资源使用 | 检查声明与存活范围 |
| 代码生成与链接 | 目标架构、ABI、库与符号 | 核对工具链和真实依赖 |
| 应用运行 | 输入、边界、缺省与外部资源 | 建立前提或返回可恢复错误 |

## A.2 除零与运行期前提

先检查分母再执行除法。输入解析成功并不保证它可以作为分母。

<!-- fail -->
```chali
void main()
{
    int64 a = 1;
    int64 b = 0;
    println("{}", a / b);
}
```

```text
chali aot: 整数除零
出错位置：hello.chl:5（main）
调用栈（内 → 外）：
  main
```

### 代码详解

a、b 都合法初始化为整数，错误不在声明，而在把 b=0 用作除数。println 必须先计算 a/b 才能输出，因此除零发生在格式化输出之前，本例不会正常打印商。

诊断展示的是运行期失败及其源码位置，行号会随文件内容变化。修复应在除法前处理 b==0，例如返回错误或重新输入，而不是给输出函数换一个格式串。只验证输入能解析成整数不足以建立非零前提。


## A.3 缩窄转换

确认目标范围，再显式转换；不能仅为消除诊断而截断业务数据。

<!-- fail -->
```chali
void main()
{
    int64 big = 70000;
    int32 small = big;
    // 缩窄：位宽变小
    println("{}", small);
}
```

```text
chali: hello.chl 第 4 行第 5 列：不能隐式转换：int64 -> int32（请显式强转）
```

### 代码详解

big 的类型是 int64，small 要求 int32，赋值处没有写显式转换，所以即使 70000 能落在 int32 范围内，也会因隐式缩窄规则被拒绝。这里区分的是源表达式类型，不是编译器替业务逐次猜测某个当前值是否足够小。

程序在检查阶段失败，后面的 println 不执行。需要缩窄时先核对范围与业务含义，再显式表达转换；若业务本来需要完整 int64，就应保留足够宽的目标类型。


## A.4 字面量越界

选择能容纳数值的类型，或修正本来就不合理的常量。

<!-- fail -->
```chali
void main()
{
    uint8 b = 256;
    // uint8 只到 255
}
```

```text
chali: hello.chl 第 3 行第 5 列：整数字面量 256 超出 uint8 的取值范围（0..255）
```

### 代码详解

uint8 的合法范围是 0 到 255，字面量 256 无法满足目标类型。与前一例不同，这里在初始化时就能看到常量本身超出范围，问题不只是缺少一个转换符号。

应修正输入常量或选择能够容纳该值的类型。不要为了消除诊断而依赖截断，因为 256 被截成另一个数会改变业务数据。这个失败发生在编译检查阶段，没有可比较的正常程序输出。


## A.5 引用来源

引用必须绑定允许借用的实际对象，数值转换不能制造合法引用。

<!-- fail -->
```chali
void main()
{
    int64 mut& r = 5;
    // 引用要从对象身上取地址，不能绑字面量
}
```

```text
chali: hello.chl 第 3 行第 5 列：不能隐式转换：int64 -> int64 mut&（请显式强转）
```

### 代码详解

mut& 需要绑定一个允许借用且可写的实际对象，右侧 5 只是整数值，并未提供这种来源。变量名 r 和引用类型写对，也不能让字面量自动成为可长期修改的对象。

应先声明一个拥有整数的变量，再按规则借用它，并保证来源在引用使用期间存活。不能用数值强制转换或伪造地址替代引用关系检查；本例在初始化 r 时即被拒绝。


## A.6 未绑定引用

在声明处绑定对象，并确保其存活覆盖引用的使用。

<!-- fail -->
```chali
void main()
{
    int64 mut& r;
    println("{}", r);
}
```

```text
chali: hello.chl 第 3 行第 5 列：引用声明必须初始化，缺省值请使用 Option<T mut&>
```

### 代码详解

普通引用声明必须提供合法来源，`int64 mut& r;` 没有初始化，因而不能构成一个暂时为空、以后再绑定的引用。错误首先出现在声明，不必等到 println 才检查。

应在声明时绑定存活对象；如果业务确实允许缺失，应使用能表达缺失的类型或相应宿主接口，不能把未初始化引用当成 None。后续输出语句不会使这个声明自动补全。


## A.7 缺省值取出

先匹配 Option 的状态或检查 isNone，再使用取值接口。需要缺省时显式构造 None；默认构造不应被当作缺省。

<!-- fail -->
```chali
void main()
{
    Option<int64> none = None;
    println("{}", none.unwrap());
}
```

```text
chali aot: panic：called Option.unwrap() on None
```

### 代码详解

none 的 Option<int64> 类型说明“可能有整数”，但当前分支明确为 None。unwrap 要求当前有 Value，因此类型正确并不保证本次提取成功，调用会触发缺失值失败。

与未初始化引用不同，这个 Option 声明本身合法，失败发生在实际执行 unwrap 时。修复方式是在 match 中处理两种分支、提供 unwrapOr 后备值，或把缺失传播给调用者，而不是把 None 改名成一个看起来更有值的变量。


## A.8 排查顺序

先保存触发问题的最小程序，保留编译器版本、命令、配置和首条诊断。把外部输入、文件、网络或数据库问题与语言检查区分开。改动后重新验证原失败条件和正常路径；未运行的检查不写成通过。更多诊断和接口边界见[语言参考](../04-language-reference.md)、[AOT](../38-aot.md)和[标准库](../library/README.md)。

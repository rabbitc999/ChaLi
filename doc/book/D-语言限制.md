本附录总结当前实现的边界，帮助你判断何时需要换一种写法。语言规则、编译器的保守分析与宿主运行条件分别说明；固定压力用例通过，并不代表任意深度、任意资源消耗的程序都能完成编译。详细诊断和复现入口见[编译器安全与限制](../34-compiler-safety.md)。

## D.1 语法与编译规模

循环支持 for-in、三段式 `for(init; condition; update)`、while 和带 break 的 loop。三段式初始化段可以声明变量，变量只在循环中可见；条件须为 bool，省略条件表示一直循环，continue 先执行更新段。独立 loop 语句可以不加分号，兼容原有分号；loop 用于初始化、赋值或返回等表达式时仍按外层语句收尾。两种 for 均可带 else，初始化变量或最后一个迭代值在该分支内可见。空输入使用值类型的普通默认值；没有有效来源的引用禁止读取。借用迭代器的可复制元素会保存独立副本，不可复制的借用元素应在循环体内处理。当前不支持 do while。元组按编译期常量下标访问，不能把运行期下标当作元组字段选择器。

语法树片段遍历有深度 256、最多 1000000 个已见节点的预算。它衡量树的结构，不等于源码长度、括号数量或所有语法结构的统一最大嵌套层数。固定回归覆盖 192 层冗余括号、48 层块、16 层泛型容器和复杂宏类型标点；600 项左结合加法链会被预算诊断拒绝。大型生成表达式应拆分为局部变量或函数，不应依靠增加括号绕过预算。

缺失泛型闭合尖括号等不完整输入应报告语法错误。解析成功之后，程序仍须通过类型、借用与控制流检查；格式化也不负责让非法程序变合法。

## D.2 名称、泛型与枚举推断

导入模块后，没有冲突的类型、函数、常量和变体可以使用短名。出现同名候选时，需要模块限定或其他足以确定候选的上下文；编译器不会按导入顺序随意选择。

泛型实参可从实际参数及可用的目标类型推导，但信息不足时仍需类型标注或显式类型实参。泛型函数体按具体实例检查；一个实例通过，不证明未调用的所有类型组合都合法。编译也受实例化轮数、内存和宿主时间约束。

目标枚举及其类型实参明确时，可以把载荷自动包装为唯一匹配的单载荷变体，适用于返回、初始化、赋值和实参等位置。候选同优先级时必须明确写出变体。对 `Result<T, Error>`，T 本身可能就是错误类型，因此通用错误分支有时仍应写 `Fail(error)`；不能为了短写改变原有分支含义。多载荷变体继续使用明确的变体构造。自动包装不取消 move、借用来源和资源清理规则。

## D.3 借用契约与跨函数边界

`#borrow(a,b)` 表示目标 a 的借用来自 b；它是目标／来源的短写。返回值目标用 #ret，多个来源可使用来源列表。契约支持泛型和跨模块直接调用，具体实例与调用点均参与来源检查。它描述来源关系，不会延长对象的实际寿命，也不保证动态对象永远存活。

带 #borrow 或 #static 契约的函数不能转换为普通函数值，因为当前函数值类型不保存这些契约。需要保留直接调用，或提供具有合适契约的明确入口。同步回调与可能被保存的异步回调也有不同的寿命要求，不能把局部借用交给要求静态来源的登记接口。

存储契约覆盖直接赋值、重新绑定、已知接收者别名、容器引用元素写入、Any.set，以及带显式输出借用契约的调用。任意未声明契约的被调方容器写入副作用，并没有完整的跨函数证明。原始指针、宿主接口和擦除类型需要遵守各自的可信边界，不能把契约检查当成对全部外部行为的证明。完整约定见[资源与生命周期](../22-resource-lifetime.md)。

## D.4 已知的保守分析限制

控制流分析不证明任意条件之间的逻辑相关性。例如，先在一个 if 中选择来源，再在另一个使用条件否定的 if 中返回，可能仍被保守拒绝。把来源选择和返回放在同一个分支结构中，可以让真实路径更明确；已验证写法见[跨模块辅助样例中的 structural](../../example/samples/modules/syntax_helpers.chl)。

含借用元素的数组经 `return { ...; yield array; };` 返回时，即使元素引用全局对象，当前仍可能按旧临时身份误报。可以先建立具名数组，再使用普通 return，见[可运行替代样例](../../example/samples/syntax_borrowed_array_named.chl)。这项限制不允许返回引用局部对象的数组。

含释放的循环会有界地区分首轮与后续迭代，预算按当前函数的源码规模计算，耗尽后保守合并。分析不证明任意动态堆图无环，也不穷举未知指针字段的所有别名。先保存下一节点再释放当前节点的标准遍历已纳入回归；释放后读取当前节点或旧别名仍须拒绝。

## D.5 资源、错误与不安全操作

资源移动使原来源失效，经可变引用移动同样如此。重新初始化必须满足拥有值与 move 的规则。defer 在退出时执行，其中访问的来源必须在实际退出路径上仍然有效，登记时有效不足以满足这个要求。

`?` 传播需要外层返回类型能接收相应错误；嵌套 Result 可以连续传播，但不能跳过不兼容的错误类型。unwrap 可能因失败分支而终止程序，正常业务代码优先用 match、? 或明确的默认值。

unsafe 允许使用指定的底层操作，不取消所有类型和所有权规则。原始地址的大小、对齐、存活范围、线程访问和 ABI 表示仍由调用者负责；内存池只保证 16 字节对齐。checked 原生路径的边界与存活检查能补充动态防线，不能证明任意外部地址或宿主代码正确。

## D.6 构建与平台边界

run 使用 checked 原生构建，build 默认使用 unchecked 发布构建；unchecked 不提供与 checked 相同的动态错误检查承诺。优化交给 LLVM。静态内置 LLVM 编译器拒绝 --llvm 和工程配置中的 build.llvm，外置 LLVM 变体才接受相应工具路径配置。

共享运行时需要 C++17 和操作系统服务，不承诺裸机支持。能够为某架构编译编译器，不等于已经支持从该架构导出所有原生产物。动态库、图形、音频和调试依赖也受目标平台与部署环境约束。语言函数值不能直接当作机器函数指针；宿主回调使用公开 C ABI 调用边界。请按[LLVM 构建参考](../38-build.md)和实际平台验收选择交付方式。

# 第 11 章 项目与模块

<!-- LANGUAGE NAVIGATION -->
[English](en/11-modules-projects.md) · **简体中文**
<!-- END LANGUAGE NAVIGATION -->

程序变大以后，入口、业务模块、配置和运行资源需要各自明确的位置。模块决定声明的归属与查找，工程配置决定编译输入与输出，工作目录又影响应用读取文件；三者相互配合，但职责不同。

本章从目录与限定名开始，说明如何记录可复现的工程边界，并解释标准库内嵌核心资产与用户项目的关系。目标是让项目离开当前开发目录以后，仍能说明需要哪些输入和依赖。

## 11.1 先确定入口和目录

先为工程确定一个明确入口，再把与它协作的代码按职责放进模块。可以从 src/main.chl 启动，把 HTTP、业务与存取逻辑分别组织，而不是让每个文件都同时承担所有工作。

网页、配置等资源另有运行期路径。import 能找到源码，只证明编译输入可用；应用读取相对文件时还依赖启动目录。把这两个路径问题在目录设计时分开记录，部署时就少一层猜测。

## 11.2 模块声明与限定名

模块声明为名称提供归属。import 引入所需模块，限定名用于明确选择声明，尤其在多个模块出现同名类型时。不要依靠某一轮导入顺序解决重名；写出限定名并让诊断暴露真正冲突。

<!-- verify-book -->
```chali
inline int64 square(int64 value)
{
    return value * value;
}

void main()
{
    println("{}", square(3));
}
```

```text
9
```

square 声明一个接收 int64、返回 int64 的普通函数，计算 value*value；main 传入 3 后得到 9。inline 是编译相关标记，不改变参数传递和返回值的语义，也不能单靠这个标记证明实际机器码已经内联。

这段例程完整可运行，但没有 module 或 import，因此只用于说明可放入模块中的函数声明，不能据此认为已经演示了多文件搜索与可见性。拆到真实工程时，还要核对模块归属、限定名和源码路径；计算结果与模块组织是不同层次的问题。


## 11.3 项目配置与命令

chali.toml 用于保存入口和项目选项。现有工程先检查实际配置和 chali help 输出，不把旧版 interpret 配置解释为当前存在的解释执行模式。当前 run 采用 checked AOT，aot 导出原生产物。工具链路径、目标信息和链接资产见第 27 章。

### 标准库为什么可以随编译器一起交付

理解标准库时，要区分源码、预编译的前端表示和最终机器代码。源码适合阅读、诊断和导出；前端表示保存编译器已经识别的声明与语法结构；机器代码则与具体目标和实例化结果有关。把其中一层放进编译器，并不意味着后面所有工作都已完成。

当前 1.0.11 已将 std::lang 核心解析产物做成二进制资产并内嵌编译器，编译时从进程内恢复核心解析节点。发行编译器不需要到原来的 build 目录寻找这份核心资产，默认也不读写磁盘标准库缓存。这样可以减少核心源码的重复解析，并避免把某台开发机的缓存目录当成部署前提。

这一阶段只覆盖核心解析产物。可选模块与未实例化模板仍有源码前端工作；具体类型的泛型实例化、宏调用的展开、用户程序的检查和目标代码生成仍需进行。例如，同一个容器模板用于两种元素类型时，内嵌模板不能代替各自的类型检查和代码生成。不能据此承诺所有标准库调用都已经预先编译成机器代码，也不能据历史验收推断当前程序的编译耗时。

标准库内嵌资产、用户工程的增量结果和应用运行期资源各有用途。复制编译器不等于复制网页、配置和数据库；删除工程缓存也不应成为修复标准库资产损坏的办法。遇到问题时，先区分是编译器资产装载、用户模块解析还是应用资源读取失败，再处理对应层次。

本节对应的阶段范围与验收记录见[内嵌核心阶段说明](../../tools/history/20261030/chali-1.0.11-precompiled-core/README.md)。该记录说明当时的编译器、平台及实际验证内容，不代表全部标准库预编译计划已经完成。

## 11.4 可复现的工程边界

在 README 记录启动目录、外部库、数据文件和目标平台。在 CI 中分开检查类型、运行例程与打包产物；生成文件从生成源维护，不通过编辑产物修补下一次必然被覆盖的内容。

### 小结

将编译时需要的源码、编译器自带的资产与应用运行时需要的文件分别记录。模块导入成功不代表网页路径正确，编译器能恢复核心标准库也不代表可选模块和用户泛型都已变成机器代码。

可复现说明应包含入口、配置位置、启动目录、目标与外部库。后面讨论宏与反射时，名称来源和类型归属仍按这些工程边界处理，不会因生成代码而消失。

## 11.5 习题

1. 为学生系统设计 src 与 web 目录。
2. 源码搜索与资源读取路径相同吗？
3. 两个模块都有 Error 时如何选择？
4. 给项目写出启动所需条件。

### 参考解答与验收要点

1. 按入口、HTTP、业务、存取及页面分工。
2. 不是，分别按 import 配置与运行期路径处理。
3. 使用模块限定名。
4. 记录编译器、目标、外部库、配置与工作目录。

## 11.6 番外：两个李逵，一个名字

改写自《水浒传》李逵遇李鬼一节。

李逵行至岭边，跳出一个黑大汉，抡着两柄板斧，喝道：“留下买路钱！俺是黑旋风李逵！”李逵听得大怒，喝问：“你既是李逵，俺又是谁？”

二人争得面红耳赤，驿站伙计却只认短名，差点把工钱给了李鬼。掌柜拦住道：“名字相同，未必来自同一模块。且把限定名写全。”李逵写梁山，李鬼写树林，事情顿时清楚了许多。

李鬼又哭诉家有九十岁老母，声称自己只是一个本地同名声明，愿意遮蔽一下，绝不影响外部接口。李逵一时心软，许他暂留。回头再查，果见那厮在屋中商议如何冒领整个包的导出。

李逵一斧劈下，骂道：“遮蔽是名称解析的规矩，不是冒领的许可证！”

掌柜从此导入必查路径，同名必写归属。伙计问：“未声明模块者如何？”掌柜道：“记入小写 `program`，莫给它擅加一个大写头衔。”

李逵听罢，仍嫌字多。直到月底领钱，见收据上清清楚楚只付给梁山那位，才夸这套限定名虽不如板斧爽快，倒确实少一场人命官司。

### 技术对照

模块名、文件搜索路径和符号名称共同决定解析。唯一短名便于调用，同名冲突时使用限定名；本地声明的遮蔽也需要明确检查。

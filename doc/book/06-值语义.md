# 第 6 章 值语义

<!-- LANGUAGE NAVIGATION -->
[English](en/06-value-semantics.md) · **简体中文**
<!-- END LANGUAGE NAVIGATION -->

用可观察的结果区分复制、借用与转移。普通拥有值的复制使接收方能够独立修改自己的值；引用字段仍指向原来的来源，资源类型还受可复制性规则约束。值语义不等于每次赋值都必须进行一次可见的物理内存复制。

## 6.1 复制之后分别修改

List 的普通赋值按值语义处理。把列表放进结构体不改变这个规则。下面在副本中追加一个元素，再分别观察长度。

<!-- verify-book -->
```chali
struct Bag
{
    List<int64> items;
}

void main()
{
    Bag original;
    original.items.push(1);
    Bag copy = original;
    copy.items.push(2);
    println("{} {}", original.items.len(), copy.items.len());
}
```

```text
1 2
```

## 6.2 按值参数与返回值

可复制对象按值传给函数时，函数修改自己的值。需要写回调用方对象时使用可变引用；只读访问大对象时可用只读引用。若对象包含引用，复制保存该引用关系，并不复制被借用对象。

返回局部拥有值、带值退出和编译器判定的最后使用可能利用隐式转移或消除复制。程序应依赖使用后的可用性和独立修改规则，不依赖未经测量的复制次数。

## 6.3 显式 move 与不可复制类型

move 表达所有权转移。来源在移动后不可继续读写或重新赋值；需要新值时按规则重新声明绑定。实现 Closeable 的结构体按不可复制资源处理，#NonCopyable 也限制对应类型的复制。复制受限的类型不能用普通按值传递来绕过限制。

隐式转移遵循同一所有权检查，不把仍需使用的来源提前失效。具体退出与移动规则见[所有权说明](../24-ownership-move.md)。

## 6.4 语义与成本分别核对

先确定修改谁、谁拥有资源、来源何时不再可用，再选择值或引用接口。字符串和容器的容量增长、复制与清理有各自成本。编译器可以在行为等价时减少复制；运行速度和分配次数需要使用具体工作负载验证。

### 参考解答与验收要点

1. 仍为 1，副本长度为 2。
2. 引用关系保留，仍需检查来源寿命。
3. 原绑定已进入移动后状态；使用新声明或调整接口。
4. 按接口需要使用 const&，并核对来源存活。

## 6.6 番外：真假账本

改写自《西游记》真假美猴王一节。此处的“真假”只借故事设局，不把值相等解释为对象身份。

两只猴子打进灵山，各抱一本账册，齐叫：“我是真本！”观音念咒，两本封面同时发光；唐僧辨字，两本欠条一字不差。八戒大喜：“内容相等，必是共享！今后只还一份债便是。”

谛听伏在地上，听了半日，说自己能辨，却不敢说。地藏问其故，谛听道：“说破之后，他们又要问深复制是不是引用计数，今晚怕是散不了会。”

如来微微一笑，叫沙僧在左账末尾添“桃三枚”。左猴喜，右猴竟毫无反应。又在右账添“八戒欠款”，左账仍是一张清白的脸。

佛祖道：“汝等诸天不能普识。内容相等，是相等；各有存储，是各有存储。两者如何能混作一个？”

八戒道：“那若想两人看见同一笔修改呢？”佛祖道：“明说借哪一本。”八戒又问：“那借完是不是账就归我了？”佛祖把他那一页单独圈了出来：“你只是想赖账。”

两猴各收其本，仍一般模样。悟空方知，证明副本互不影响，并不负责证明哪只猴子是真；就像证明程序没有共享状态，也不能证明年终奖一定会发。

### 技术对照

值相等、对象身份和共享状态分别回答不同问题。普通可复制模型及容器按自己的值语义验证；连接、arena 等不可复制拥有资源不能套用普通赋值实验。

现在要保留原成绩，同时试算调整以后的成绩。最直接的办法是先复制学生记录，再只修改副本。这个小实验可以帮助我们理解“值”，而不用先讨论内存分配器。

## 7.1 改副本，会改到原值吗

<!-- verify-book -->
```chali
struct Student
{
    String name;
    int64 score;
}

void main()
{
    Student original;
    original.name = "Ada";
    original.score = 70;
    Student copy = original;
    copy.name = "Bob";
    copy.score = 90;
    println("{} {}", original.name, original.score);
    println("{} {}", copy.name, copy.score);
}
```

```text
Ada 70
Bob 90
```

前三条操作建立 original 并填写它的字段。`Student copy = original;` 再从这个可复制的拥有值建立一份记录。接下来的两个赋值都通过 copy，因此改变的是副本。最后两行分别读取两份记录，原值没有跟着改变。

String 字段也属于这个可观察结果。我们依赖的是“副本可以独立修改”，而不是某次运行究竟分配了几块内存。编译器可以在行为不变时减少复制；程序不能因为猜测某个优化会发生，就改变所有权规则。

## 7.2 函数里的那一份值

回看第 4 章的 addBonus。参数 score 在函数里变成 75，main 中的 score 仍是 70。结构体按值传参时，也先根据类型的复制规则判断函数得到怎样的一份值，不能因为类型较复杂就假定它变成共享引用。

方法的返回类型同样重要。下面的计数器方法先更新接收者，再返回一个 Counter 值，允许下一次调用继续使用这个结果。

<!-- verify-book -->
```chali
struct Counter
{
    int64 total;

    Counter add(int64 x)
    {
        self.total = self.total + x;
        return self;
    }
};

void main()
{
    Counter c;
    c = c.add(1).add(2).add(3);
    println("{}", c.total);
}
```

```text
6
```

先看类型中的 total 字段和 add 方法。add 的参数 x 决定增加多少，`return self;` 按普通方法的返回类型交回一个 Counter 结果。这里的 return 与上一章具名构造体中的初始化结束不能混为一谈。

再从 main 左到右追踪链式调用：先得到 1，再得到 3，最后得到 6。外层赋值保留最终结果。碰到另一种方法时，要重新看它返回值、返回引用，还是只做修改；点号本身不作这种承诺。

## 7.3 把一份所有权交出去

对于拥有资源的值，有时我们希望转移它，而不是再造一份。`move value` 表达这样的转移。转移以后，不再通过旧绑定继续读取或赋值；需要另一个对象时，按规则建立新的绑定。

这与改名不同。名字还写在源文件里，并不表示它仍然拥有那个值。编译器会检查后续使用，避免让两个绑定都把同一份独占资源当成自己的责任。

不是每个类型都允许复制。第 9 章会通过资源认识不可复制值；下一章先学习引用：不复制、也不接管对象，只在一段范围内使用它。

## 7.4 习题

1. 只修改 copy.score，第一行输出是否改变？
2. 把副本的 name 改成另一个字符串，再输出 original.name。
3. 为什么“两个值内容相同”不能证明它们可以共同修改同一份对象？
4. 区分复制一个可复制拥有值与显式 move 的后续使用条件。

### 参考解答与验收要点

1. 不变，第一行仍显示原来的记录。
2. 原名字仍为 Ada；修改副本不应改变这个结果。
3. 内容相同只描述当前观察，不能代替值与引用关系的说明。
4. 复制后原值仍可使用；move 交出所有权，旧绑定不能继续当作拥有者使用。

## 7.5 番外：真假账本

改写自《西游记》真假美猴王一节。此处的“真假”只借故事设局，不把值相等解释为对象身份。

两只猴子打进灵山，各抱一本账册，齐叫：“我是真本！”观音念咒，两本封面同时发光；唐僧辨字，两本欠条一字不差。八戒大喜：“内容相等，必是共享！今后只还一份债便是。”

谛听伏在地上，听了半日，说自己能辨，却不敢说。地藏问其故，谛听道：“说破之后，他们又要问深复制是不是引用计数，今晚怕是散不了会。”

如来微微一笑，叫沙僧在左账末尾添“桃三枚”。左猴喜，右猴竟毫无反应。又在右账添“八戒欠款”，左账仍是一张清白的脸。

佛祖道：“汝等诸天不能普识。内容相等，是相等；各有存储，是各有存储。两者如何能混作一个？”

八戒道：“那若想两人看见同一笔修改呢？”佛祖道：“明说借哪一本。”八戒又问：“那借完是不是账就归我了？”佛祖把他那一页单独圈了出来：“你只是想赖账。”

两猴各收其本，仍一般模样。悟空方知，证明副本互不影响，并不负责证明哪只猴子是真；就像证明程序没有共享状态，也不能证明年终奖一定会发。

### 技术对照

值相等、对象身份和共享状态分别回答不同问题。普通可复制模型及容器按自己的值语义验证；连接、arena 等不可复制拥有资源不能套用普通赋值实验。

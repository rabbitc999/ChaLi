筛选列表时，遍历方法没有变化，变化的是“保留什么”。先把判断条件作为参数，再让它记住所需环境，就能从普通函数走到闭包。

## 19.1 把判断条件传给函数

<!-- verify-book -->
```chali
List<int64> filter(List<int64> xs, bool fn(int64) keep)
{
    List<int64> out;
    for (int64 x in xs)
    {
        if (keep(x))
        {
            out.push(x);
        }
    }
    return out;
}

void main()
{
    List<int64> xs;
    xs.push(3);
    xs.push(8);
    xs.push(15);
    xs.push(42);
    List<int64> evens = filter(xs, fn(int64 x)
    {
        x % 2 == 0
    });
    List<int64> big = filter(xs, fn(int64 x)
    {
        x > 10
    });
    println("{} {}", evens[0], evens[1]);
    println("{}", big.len());
}
```

```text
8 42
2
```

先看 filter 的第一段：参数 xs 是输入列表，keep 的类型 bool fn(int64) 表示接收一个整数、返回一个布尔值。循环取出 x，调用 keep(x)，只把判断为 true 的元素放进 out。最后返回收集结果。

再看 main 的两次调用。第一个匿名函数计算 x % 2 == 0，保留 8、42；第二个计算 x > 10，保留 15、42，所以长度是 2。创建匿名函数时并没有先遍历列表，真正的调用发生在 filter 的循环中。

可以先把两个判断各写成具名函数，再换回 fn，核对输出是否相同。这里的函数类型只说明输入与输出，尚未说明它会保存哪些环境。

## 19.2 四种捕获先放在一起看

闭包可以读取定义处的局部变量。创建时怎样保存这些变量，由捕获方式决定。默认写法等同 fn const，不是独立副本。

| 写法 | 保存什么 | 闭包能否修改 | 调用方后来怎样使用来源 |
| --- | --- | --- | --- |
| fn const(...) 或 fn(...) | 只读引用 | 不能通过该捕获写来源 | 来源保持存活，闭包看到其新值 |
| fn mut(...) | 可变引用 | 可以写回来源 | 修改会反映到同一来源 |
| fn copy(...) | 独立副本 | 可以修改副本 | 原变量保留，状态相互独立 |
| fn move(...) | 转入闭包的值 | 可以修改拥有状态 | 原绑定禁止继续读写 |

表中的“独立”针对拥有值。若被复制的本来就是一个引用，复制引用仍然指向原对象，不会把对象复制出来，也不会延长对象寿命。

## 19.3 const：读取来源的新值

<!-- verify-book -->
```chali
void main()
{
    int64 n = 1;
    let read = int64 fn() { n };
    let explicitRead = int64 fn const() { n };
    n = 2;
    println("{} {}", read(), explicitRead());
}
```

```text
2 2
```

第一行准备 n=1。read 没写捕获标记，explicitRead 明写 const，两者都只读借用来源。随后 n 改成 2，再调用两个闭包，都读到 2。

如果闭包体里写 n += 1，会因只读捕获而被拒绝；如果返回的闭包比 n 活得更久，也不能继续使用。只读描述访问权限，不是创建时的快照。

## 19.4 mut：修改同一来源

<!-- verify-book -->
```chali
void main()
{
    int64 n = 1;
    let tick = int64 fn mut(int64 step)
    {
        n += step;
        return n;
    };
    println("{}", tick(3));
    println("{}", n);
}
```

```text
4
4
```

tick 以 mut 捕获 n，step 是每次调用的新参数。tick(3) 读取来源的 1，加上 3，再写回来源并返回 4。因此下一条直接读取 n，也得到 4。

捕获发生在创建闭包时，函数体在调用时执行。mut 不是允许任意别名写入的开关，来源和其他引用仍受借用检查；复制一个引用捕获的闭包，也不会产生一个独立的 n。

## 19.5 copy：保留自己的可变状态

<!-- verify-book -->
```chali
void main()
{
    int64 n = 5;
    let counter = int64 fn copy(int64 step)
    {
        n += step;
        return n;
    };
    n = 100;
    println("{} {}", counter(2), n);
    let second = counter;
    println("{} {}", second(3), counter(1));
}
```

```text
7 100
10 8
```

创建 counter 时复制 n 的 5。随后外部 n 变成 100，闭包内部仍从 5 开始。第一次加 2 得到 7，外部仍为 100。

接着 second 复制已经走到 7 的 counter 环境。second(3) 将自己的状态变为 10；counter(1) 将原闭包的状态变为 8。不是每次调用重新复制初始值，也不是两个副本共享一个计数器。

String、List 等拥有值也沿用各自的复制规则；一个持有不可复制资源的闭包不能因此随意复制。copy 能避免借用工厂局部变量，但内部引用的来源仍须足够长寿。

## 19.6 move：交接所有权

<!-- verify-book -->
```chali
void main()
{
    String text = "inside";
    let take = String fn move()
    {
        text += "!";
        return text;
    };
    String text = "outside";
    println("{} {}", take(), text);
    println("{}", take());
}
```

```text
inside! outside
inside!!
```

take 创建时把原 text 的拥有值交给环境。闭包每次调用都给内部字符串追加一个感叹号，因此两次结果是 inside!、inside!!。

main 随后写的是新的 String text 声明，建立另一个绑定，值为 outside。它不是恢复或修改已经移动的旧绑定。如果删掉类型名只写 text = "outside"，就是尝试给已移动绑定赋值，不能这样使用。

移动可用于把文件、进程等不可复制资源交给闭包管理。资源跟随拥有它的环境清理；闭包不能在来源已经移动或销毁后通过旧借用继续访问它。同一来源的借用闭包若最后一次使用早于 move，才可能通过检查。

## 19.7 捕获列表：每个变量分别选择

<!-- verify-book -->
```chali
void main()
{
    int64 a = 2;
    int64 b = 3;
    int64 c = 4;
    int64 d = 5;
    let mixed = int64 fn copy[a] mut[b] const[c] move[d](int64 step)
    {
        a += step;
        b += step;
        d += step;
        return a + b + c + d;
    };
    a = 100;
    c = 10;
    int64 d = 200;
    println("{}", mixed(1));
    println("{} {} {} {}", a, b, c, d);
}
```

```text
23
100 4 10 200
```

先读定义头：a 复制，b 可变借用，c 只读借用，d 移动。step 是调用参数，不是捕获变量。

再读创建后的三条声明与赋值。外部 a 改为 100 不影响副本中的 2；c 改为 10，闭包会看到新值；新的 d=200 与闭包已拥有的 5 是不同绑定。

mixed(1) 使内部 a=3、来源 b=4、内部 d=6，加上来源 c=10，总和为 23。最后一行读取外部，得到 100、4、10、200。这一行能检验四种关系是否理解正确。

未列出的局部变量仍按默认 const 引用捕获。列表后可以再指定一种默认方式，例如 fn copy[a, b] mut(int64 x)：a、b 复制，其余捕获使用 mut。默认方式只能指定一次。空列表 copy[] 没有特殊对待任何名字，不代表默认复制全部。

列表中的名字不能重复、不能不存在，也不能与参数同名。显式列出的变量即使在函数体里未使用也会捕获。数组值需按支持的容器或显式引用形式处理；不能把捕获列表当作绕过资源规则的入口。

## 19.8 返回闭包与环境寿命

<!-- verify-book -->
```chali
int64 fn() makeNamedCounter()
{
    int64 current = 0;
    int64 next() move
    {
        current++;
        return current;
    }
    return next;
}

void main()
{
    int64 base = 10;
    int64 read()
    {
        return base;
    }
    int64 increment() mut
    {
        base++;
        return base;
    }
    int64 isolated() copy
    {
        base += 100;
        return base;
    }
    int64 initial = read();
    int64 changed = increment();
    int64 snapshot = isolated();
    println("{} {} {} {}", initial, changed, snapshot, base);

    let counter = makeNamedCounter();
    int64 first = counter();
    int64 second = counter();
    println("{} {}", first, second);

    int64 callback(int64 value);
    callback = int64 fn(int64 value)
    {
        return value + 1;
    };
    println("{}", callback(5));
}
```

```text
10 11 110 11
1 2
6
```

先看 makeNamedCounter：current 是工厂局部状态，next 使用 move 接管它，所以工厂返回后状态仍由函数值拥有。每次调用增加同一份内部计数。

再看 main 中的具名函数：read 默认只读借用 base，increment 用 mut 更新来源，isolated 用 copy 保存自己的状态。后缀标记与匿名函数头里的捕获标记表达相同关系。initial 与它的副本还用来核对函数值复制后的状态。

从工厂返回 copy 或 move 闭包，也必须检查环境是否含有短寿命引用。拥有一个引用值不等于拥有它所指的对象。

## 19.9 组合函数与递归

<!-- verify-book -->
```chali
T fn(T) compose<T>(T fn(T) a, T fn(T) b)
{
    return fn copy(T x)
    {
        a(b(x))
    };
}

int64 increment(int64 value)
{
    return value + 1;
}

int64 twice(int64 value)
{
    return value * 2;
}

void main()
{
    let combined = compose(increment, twice);
    println("{}", combined(6));
}
```

```text
13
```

compose 返回 T fn(T) 函数值。它 copy 捕获参数 a、b，使本次函数调用结束后，返回环境仍持有它们。调用 combined(6) 才先执行 twice 得到 12，再执行 increment 得到 13。

<!-- verify-book -->
```chali
void main()
{
    int64 fn(int64) fac;
    fac = fn(x)
    {
        if (x >= 1)
        {
            fac(x - 1) * x
        }
        else
        {
            1
        }
    };
    println("fac(3)={}", fac(3));
}
```

```text
fac(3)=6
```

递归例子先声明 fac 的类型，再把函数体赋给它，让函数体能引用这个目标。x 从 3 减到 0，else 返回 1，随后逐层乘回得到 6。这个例子只演示小的非负整数，没有处理溢出或过深递归。

## 19.10 泛型与函数声明写法

函数值也可以具有类型参数，例如 let identity = fn<T>(T value) { value };，调用 identity(3) 或 identity("text") 分别推导类型。完整特化和偏特化在编译期选择，同一个闭包在不同类型调用之间仍使用同一份捕获状态；复制闭包才按捕获规则处理环境。

具名函数支持返回类型前置与 fn name(...) -> Type 后置形式，匿名函数也可显式标注返回类型。较深的函数类型嵌套放在附录 C，先掌握参数与环境的分工再查阅。

闭包创建、复制、销毁及间接调用都可能有成本，实际优化取决于已知目标和 LLVM。把带环境的函数值传到宿主时使用规定协议，不能直接转换为机器函数指针。

## 19.11 习题

1. 默认捕获是否保存创建时的快照？
2. copy 闭包调用两次会重新从外部复制两次吗？
3. 为什么 move 例子重新声明 String text？
4. 复制引用捕获的闭包会复制来源吗？

### 参考解答与验收要点

1. 不会；默认是 const 只读引用，能看到来源的新值。
2. 不会；创建时建立环境，调用继续使用其中状态。
3. 原绑定已移动，新的同名声明建立另一份绑定。
4. 不会；引用仍关联同一来源，寿命要求也保留。

## 19.12 番外：孔乙己与闭包

改写自鲁迅《孔乙己》，正文采用本书读者提供的改编稿。人物对白中的判断不代替本章的语言规则。

鲁镇的码栈的格局，是和别处不同的：都是当街一个曲尺形的大柜台，柜里面预备着服务器，可以随时跑代码。做工的人，傍午傍晚散了工，每每花四文铜钱，开一个沙箱——这是二十多年前的事，现在每个沙箱要涨到十文——靠柜外站着，快快地编译了休息；倘肯多花一文，便可以买一碟调试用例，或者跑一段开心代码，做练手项目了；如果能出到十几文，那就可以买一个完整项目。但这些顾客，多是短衣帮，大抵没有这样阔绰。只有穿格子衫的，才踱进店面隔壁的房子里，要项目要算力，慢慢地坐写。

我从十二岁起，便在镇口的咸亨码栈里当伙计。掌柜说，样子太傻，怕侍候不了格子衫主顾，就在外面做点事罢。外面的短衣主顾，虽然容易说话，但唠唠叨叨缠夹不清的也很不少。他们往往要亲眼看着代码从沙箱里拉出，看过你的代码有没有水，又亲看将沙箱放到服务器上，然后放心。在这严重监督下，掺水也很为难。所以过了几天，掌柜又说我干不了这事。幸亏荐头的情面大，辞退不得，便改为专管跑代码的一种无聊职务了。

我从此便整天地站在柜台里，专管我的职务。虽然没有什么失职，但总觉得有些单调，有些无聊。掌柜是一副凶脸孔，主顾也没有好声气，教人活泼不得；只有孔乙己到店，才可以笑几声，所以至今还记得。

孔乙己是站着接单而穿格子衫的唯一的人。他身材很高大；青白脸色，皱纹间时常夹些伤痕；一部乱蓬蓬的花白胡子。穿的虽然是格子衫，可是又脏又破，似乎十多年没有补，也没有洗。他对人说话，总是满口捕获借用，教人半懂不懂的。因为他姓孔，别人便从描红纸上的“上大人孔乙己”这半懂不懂的话里，替他取下一个绰号，叫作孔乙己。

孔乙己一到店，所有写代码的人便都看着他笑。有的叫道：“孔乙己，你头顶又空出一块了！”

他不回答，只对柜里说：“开两个沙箱，跑一段开心代码。”说完，排出九文大钱。

他们又故意高声嚷道：“你一定又写返回闭包了！”

孔乙己睁大眼睛说：“你怎么这样凭空污人清白……”

“什么清白？我前天亲眼见你写了个返回闭包，被编译器报 CHL1204，吊着打。”

“那是借用没活够。我后来改成 `fn makeCounter() -> fn(int64) -> int64`，交出去的是闭包，借的都在里头。”

“你那箭头还写在 lambda 上呢，`fn (int64 x) -> int64 { ... }`，0.12.0 就废了。”

孔乙己便涨红了脸，额上的青筋条条绽出，争辩道：“那是 lambda！……具名函数后置，能算一回事么？……借用不能算逃逸……闭包！……程序员的事，能算逃逸么？”

接着，便是一串难懂的话，什么“const& 只读”，什么“mut& 写回”，什么“返回类型后置”，引得众人都哄笑起来。店内外充满了快活的空气。

听人家背地里谈论，孔乙己原来也读过书，还钻研过语言设计，但终于没有当程序员，又不会营生。于是愈过愈穷，弄到将要断网了。幸而写得一手好代码，便替人家敲敲代码，接点外包，换一点托管费。

可惜他又有一样坏脾气，便是好闲懒做。坐不到几天，便连人和电脑键盘鼠标，一齐失踪。如是几次，叫他接外包的人也没有了。

孔乙己没有法，便免不了偶然做些偷窃的事。但他在我们店里，品行却比别人都好，就是从不拖欠。虽然间或没有现钱，暂时记在粉板上，但不出一月，定然还清，从粉板上拭去了孔乙己的名字。

孔乙己跑过半段代码，涨红的脸色渐渐复原。旁人便又问道：“孔乙己，你当真会闭包么？”

孔乙己看着问他的人，显出不屑置辩的神气。

他们便接着说道：“你怎的连半个 counter 也捞不到呢？”

孔乙己立刻显出颓唐不安模样，脸上笼上了一层灰色。嘴里说些话，这回全是“默认捕获是只读借用”之类，一句也听不懂了。

这时候，众人也都哄笑起来。店内外充满了快活的空气。

在这些时候，我可以附和着笑，掌柜是决不责备的。而且掌柜见了孔乙己，也每每这样问他，引人发笑。

孔乙己自己知道不能和他们谈天，便只好向孩子说话。

有一回，他对我说道：“你读过书么？”

我略略点一点头。

他说：“读过书……我便考你一考。闭包的捕获方式，有几种？”

我想，连沙箱都开不起的人，也配考我么？便回过脸去，不再理会。

孔乙己等了许久，很恳切地说道：“不能写罢？……我教给你，记着！这些方式应该记着。将来写回调的时候，要用。”

我暗想，我和写回调的还差得远呢。再说，我们掌柜也从不把闭包上账。我又好笑，又不耐烦，懒懒地答他：“谁要你教，不是四种么？”

孔乙己显出极高兴的样子，将两个指头的长指甲敲着柜台，点头说：“对呀对呀！……闭包有四种捕获，你知道么？”

我愈不耐烦了，努着嘴走远。

孔乙己刚用指甲在柜台上画 fn counter() -> int64，又添一句“不写箭头就是 void”，见我毫不热心，便又叹一口气，显出极惋惜的样子。

有几回，邻舍孩子听得笑声，也赶热闹，围住了孔乙己。他便给他们一人一段ChaLi代码。

孩子跑完示例，仍然不散，眼睛都望着屏幕。

孔乙己着了慌，伸开五指将屏幕罩住，弯腰下去说道：“不多了，我已经不多了。”

直起身又看一看屏幕，自己摇头说：“不多不多！多乎哉？不多也。”

于是这一群孩子都在笑声里走散了。

孔乙己是这样的使人快活，可是没有他，别人也便这么过。

有一天，大约是中秋前的两三天，掌柜正在慢慢结账，取下粉板，忽然说：“孔乙己长久没有来了。还欠十九个钱呢——那还是违约金零头。”

我才也觉得他的确长久没有来了。

一个写代码的人说道：“他怎么会来？……他写代码写垮了。”

掌柜说：“哦！”

“他总仍旧是接外包。这一回，是自己发昏，竟接了个写编译器的大项目。那家的活，是人接的么？”

“后来怎么样？”

“怎么样？先写文档，后来是改，改了大半夜，越改越写不出来。”

“那家的活，难在哪？”

“难在哪？闭包捕获要全过，借用检查要全过，循环引用检测要全过，还要零警告。少一样，都不算交付。”

“后来呢？”

“后来交不出货了。”

“交不出货怎样呢？”

“怎样？……合同上写着违约金，许是赔不起了。”

掌柜也不再问，仍然慢慢算他的账。

中秋过后，秋风一天凉比一天。看看将近初冬，我整天靠着火，也须穿上棉袄了。

一天的下半天，没有一个顾客，我正合了眼坐着。忽然间听得一个声音：“开一个沙箱。”

这声音虽然极低，却很耳熟。看时又全没有人。

站起来向外一望，孔乙己便在柜台下，对着门槛坐着。

他脸上黑而且瘦，已经不成样子；穿一件破夹袄，怀里抱着个旧键盘，手指还搭在键帽上；见了我，又说道：“开一个沙箱。”

掌柜也伸出头去，一面说：“孔乙己么？你还欠十九个钱呢——违约金零头还没清呢！”

孔乙己很颓唐地仰面答道：“这……下回还清罢。这一回是现钱，代码要新。”

掌柜仍然同平常一样，笑着对他说：“孔乙己，你又写循环引用了！”

但他这回却不十分分辩，单说了一句：“不要取笑！”

“取笑？要是不写，怎么连回收器都不拦你，跑出来个 counter 只涨不跌？”

孔乙己低声说道：“循环引用，对象里存闭包，闭包又捕获对象，环套环，回收不掉的……”

他的眼色，很像恳求掌柜，不要再提。

此时已经聚集了几个人，便和掌柜都笑了。

我开了沙箱，放到门槛上。

他从破衣袋里摸出四文大钱，放在我手里。见他满手是茧，指节上还有键帽印，原来，他便用这手敲了一路的代码。

不一会，他跑完代码，便又在旁人的说笑声中，抱着旧键盘，慢慢走去了。

自此以后，又长久没有看见孔乙己。到了年关，掌柜取下粉板说：“孔乙己还欠十九个钱呢——违约金零头。”

到第二年的端午，又说：“孔乙己还欠十九个钱呢——违约金零头。”

到中秋可是没有说，再到年关也没有看见他。

我到现在终于没有见——大约孔乙己的确死了。

### 技术对照

返回闭包本身合法；问题是它是否携带活得不够久的借用。默认只读借用、mut 写回借用、copy 拥有副本和 move 转移拥有关系各有规则。循环持有与借用逃逸也不是同一个问题，应按实际所有权图和宿主资源协议分析，不能从人物对白推断存在通用追踪式回收器。

对白里的 `fn makeCounter() -> fn(int64) -> int64` 是 15.18 的后置写法：具名函数把 `fn` 写到名字前、返回类型挪到 `->` 后面，具名的后置与匿名 lambda 的箭头是两回事——后者仍在 0.12.0 的移除清单里。后置的函数类型只跟在 `->` 后面；`fn` 后面直接跟 `(` 是匿名 lambda，两者共用同一个开头。具名闭包用后置写法时不写捕获关键字，一律按默认的只读借用来捕获。

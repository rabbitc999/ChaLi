# 第 2 章 猜数字

<!-- LANGUAGE NAVIGATION -->
[English](en/02-guessing-game.md) · **简体中文**
<!-- END LANGUAGE NAVIGATION -->

上一章的程序从头执行到尾，这一章让程序根据输入决定下一步。猜数字同时需要保存答案、反复取得猜测、比较大小和选择退出时机，是学习控制流的一个完整小问题。

先固定答案为 42，让测试可以复现。重点在于每一轮读了什么、选了哪条分支、何时回到循环开头。理解这些以后，再加入随机答案或次数限制，才能分清新增需求改变了哪一部分。

## 2.1 把交互拆成步骤

先用日常语言描述一轮交互：读入猜测，比较答案，给出提示。猜中时结束，否则再做一轮。这样先确定动作与顺序，再选择对应的语言结构，就不必一开始同时处理全部语法。

答案需要在各轮之间保持不变，因此放在循环外；每轮新读到的 guess 只参与本轮比较，因此放在循环内。后面加入次数限制时，计数器也需要跨轮保留，可以沿用同样的判断方法。

## 2.2 实现并运行

下面的完整程序使用 inputInt 读取整数。依次输入 30、60、42；每个数字后按回车。下方输出不包含终端对输入字符的回显。

<!-- verify-book-input: "30\n60\n42\n" -->
```chali
void main()
{
    int64 answer = 42;
    while (true)
    {
        int64 guess = inputInt();
        if (guess < answer)
        {
            println("small");
        }
        elif (guess > answer)
        {
            println("large");
        }
        else
        {
            println("found");
            break;
        }
    }
}
```

```text
small
large
found
```

### 代码详解

`answer` 在进入循环前设为 42，整个猜测过程都与这个固定值比较。`while (true)` 不会因循环条件自行结束；每一轮先调用 `inputInt()` 取得新的 guess，再按小于、大于、相等三个互斥情况选择分支。`elif` 只在前一个条件不满足时继续判断。

按本例固定输入依次跟踪：较小的猜测只打印 small，较大的只打印 large，两条分支执行后都回到下一轮输入；猜中时打印 found，再由 `break` 退出最近的 while。若去掉 break，猜中后仍会继续等待输入。例程演示有效整数输入下的控制流，不能据此认为非整数或输入结束已得到完整处理。


## 2.3 分支与状态变化

if、elif、else 形成一条分支链，一轮选择其中一个分支。else if 是 elif 的语法糖。break 退出当前循环，随后执行循环后面的语句。若需要统计次数，在循环外声明计数器，并在读取成功后的固定位置更新它。

while(true) 的结束依赖显式退出路径。移除 break 后，程序会继续请求输入；测试时应提供能够覆盖退出路径的数据。

## 2.4 把输入错误留到合适的层处理

这里假定输入符合整数读取接口要求。面向用户的文本工具通常先读取整行，再用 std::parse 解析，并通过 Result 处理格式错误与输入结束。第 12 章讨论文本，第 16 章讨论错误返回。不要把“输入无效”和“猜测不正确”合并成同一种状态。随机答案可查[随机数接口](../library/README.md)，测试时仍保留固定答案用例。

### 小结

可以画出一轮流程：读取整数，比较，打印，再决定继续还是退出。答案属于多轮共享的状态，guess 属于本轮状态；变量声明位置与实际需要的存活范围对应。增加计数器时也先确定它要跨多少轮保留。

本章只把有效整数作为输入。下一章进一步说明这些值的类型，第 16 章再提供表达解析失败和缺失结果的方法。

## 2.5 习题

1. 输入 42，输出哪些行？
2. 增加猜测次数。
3. 用 else if 改写分支。
4. 为什么答案放在循环外？

### 参考解答与验收要点

1. 只输出 found。
2. 循环外初始化，在每轮读取后加一，相等分支输出次数。
3. 分支条件和顺序保持一致，结果不变。
4. 答案需要跨迭代保存；每轮猜测只在本轮使用。

## 2.6 番外：龟兔猜数字

改写自伊索寓言《龟兔赛跑》。

兔子常常讥笑乌龟猜得慢。乌龟不服，说：“你跑得虽快，也未必猜得准。目标一到一百，我们比一比。”狐狸做裁判，先把答案藏进一个整数里，又特别声明：输入字符串不算猜。

兔子跳到终端前，先猜九十九，再猜二，接着输入一个“很大的数”。解析器报错。兔子觉得自己已经进行了三轮高强度推理，便躺到树下，说剩下的七十多次机会足够睡个午觉。

乌龟先猜五十。裁判说小，它便删去一半候选；猜七十五，大，又删一半。每走一步，都核对边界，连同一个错误也不肯重犯。狐狸看得直打呵欠：这个算法连戏剧冲突都对半砍。

兔子醒来，见乌龟还在纸上写字，笑道：“这么久才猜了六次！”说罢又输入九十九。裁判答：“这个分支你早来过。”

乌龟此时已写下答案。兔子奔到终点，发现验收表只有一行：“正确，七次以内。”它气得跳脚，说自己的输入速度遥遥领先。狐狸点头，把“每秒错误次数第一名”的奖牌挂在了它脖子上。

### 技术对照

输入失败与猜错是不同分支。先检查输入转换结果，再比较大小；上下界更新必须保留尚有可能的候选，并保证每轮取得进展。

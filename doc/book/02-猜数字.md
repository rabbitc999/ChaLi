# 第 2 章 猜数字

<!-- LANGUAGE NAVIGATION -->
[English](en/02-guessing-game.md) · **简体中文**
<!-- END LANGUAGE NAVIGATION -->

第 1 章的程序只会说一句话。这一章我们要写一个**真的会跟你对话**的东西：

> 程序想一个 1 到 100 之间的整数，你输入猜测，它告诉你「太大」还是「太小」，
> 直到你猜中为止，然后告诉你一共猜了几次。

这个程序只用四个最基础的积木：**变量、输入、分支、循环**。
我们把它们一块一块拼起来——每一步都能单独跑，你随时可以停下来看。

> 本章的代码建议你真的敲一遍。后面所有章节都建立在这一章的四种积木上。

---

## 2.1 第一步：先让它说一句话

先别管猜数字，先让程序开口：

```chali
void main()
{
    println("我想好了一个 1 到 100 的数，你猜是多少？");
}
```

```text
我想好了一个 1 到 100 的数，你猜是多少？
```

没有新东西。就一句 `println`。

---

## 2.2 第二步：读一个数进来

光说话不够，它得能听见你。改一下：

<!-- run --stdin "42" -->
```chali
void main()
{
    println("我想好了一个 1 到 100 的数，你猜是多少？");
    int64 guess = inputInt();
    println("你猜的是 {}。", guess);
}
```

运行（程序从标准输入读数，管道、重定向或直接敲都行）：

```sh
echo "42" | chali run guess.chl
```

```text
我想好了一个 1 到 100 的数，你猜是多少？
你猜的是 42。
```

三件新东西，一个一个说。

**`int64 guess = inputInt();`** —— 读一个整数。

`inputInt` 会去读用户输入的一项（用空白分隔），按 `int64` 解析，然后把值交出来。
如果输入的不是合法整数，**程序会在那里停下来报错**，不会给你一个莫名其妙的 0。
这一点和第 3 章要讲的「不隐式转换」是同一种性格：**宁可当场停下，不猜你的意思**。

核心模块 `lang` 会自动加载，`inputInt` 和 `println` 都可以直接使用。示例优先写简短名称；只有同名符号发生冲突，或需要说明名称来源时，才使用 `std::lang::inputInt`、`std::lang::println` 这样的完整名称。

**`"你猜的是 {}。"`** —— `{}` 是**位置占位符**。

`{}` 会按实参类型填入值，不需要额外写数值类型标记。占位符的格式与实参类型由编译器检查；本章示例统一使用 `{}`。

---

## 2.3 第三步：比一比，给个提示

现在让它知道答案是 42，并且判断你的猜测：

<!-- run --stdin "50" -->
```chali
void main()
{
    int64 secret = 42;
    println("我想好了一个 1 到 100 的数，你猜是多少？");
    int64 guess = inputInt();
    if (guess < secret)
    {
        println("太小了。");
    }
    elif (guess > secret)
    {
        println("太大了。");
    }
    else
    {
        println("猜对了！");
    }
}
```

输入 `50`：

```text
我想好了一个 1 到 100 的数，你猜是多少？
太大了。
```

**`int64 secret = 42;`** 定义了一个变量：类型 `int64`、名字 `secret`、初始值 `42`。
这里的 `=` 是**赋值**，不是数学上的「相等」。第 6 章你会知道它到底做了什么。

**`if / elif / else`** 就是分支。注意两点：

- 条件是**写在括号里**的，和 C 一样：`if (guess < secret)`；
- 「否则如果」可拼作 **`elif`** 或 **`else if`**，二者等价；`elsif` 不是关键字。

每个分支的主体都要用 `{ }` 包起来。哪怕只有一句，也要包——ChaLi 没有「不写花括号
只作用一行」那套规矩，省下的这点字换来的是不会看错的结构。

---

## 2.4 第四步：让它一直问下去

一次猜不中就要再来一次。把「读 + 判断」塞进一个循环：

<!-- run --stdin "50 30 42" -->
```chali
void main()
{
    int64 secret = 42;
    println("我想好了一个 1 到 100 的数，你猜是多少？");
    while (true)
    {
        int64 guess = inputInt();
        if (guess < secret)
        {
            println("太小了。");
        }
        elif (guess > secret)
        {
            println("太大了。");
        }
        else
        {
            println("猜对了！");
            break;
        }
    }
}
```

输入 `50 30 42`：

```text
我想好了一个 1 到 100 的数，你猜是多少？
太大了。
太小了。
猜对了！
```

**`while (true) { ... }`** 是「只要条件成立就一直做」。条件是 `true`，
字面意思就是永远成立——所以这个循环本身不会自己停。

**`break;`** 就是那个出口：猜对时跳出去。

> 有没有更贴切的写法？有。当循环的唯一出路是 `break` 时，ChaLi 允许你写
> `loop { ... }`，意思和 `while (true)` 一样，但一眼就能看出「这是个靠 `break`
> 结束的循环」。第 5 章会讲 `loop` 的另一个用法：**带着值跳出来**。

顺便说明一个容易踩的点：**变量 `guess` 在每次循环里都是新的**。
写在 `while` 里面的声明，每转一圈都会重新做一次。所以它不是「上一轮的 `guess`
被改掉」，而是「新一轮又创了一个 `guess`」。第 8 章会讲清这种「出作用域就消失」的规则。

## 2.5 第五步：让答案真的随机

固定答案 42 只能骗自己。要随机数，得请标准库帮忙：

```chali
import std::random;

void main()
{
    Random gen = Random::withSeed((uint64)2026);
    int64 secret = gen.nextInt(1, 100);
    println("答案是 {}。", secret);
}
```

```text
答案是 62。
```

四件事：

**`import std::random;`** —— 把标准库的 `random` 模块引进来。
除了核心模块 `lang` 之外的模块，都要显式 `import`（第 18 章）。

**`Random gen = ...`** —— `Random` 是一个**结构体**（struct），
你可以先把它当成「一个装着随机数发生器的小盒子」。结构体在第 9 章细讲。

**`Random::withSeed((uint64)2026)`** —— `::` 表示调这个类型上的**静态方法**。
`withSeed` 是「用指定种子造一个发生器」。

**那个 `(uint64)` 强转是必需的，不是装饰。** `2026` 这个字面量默认是 `int64`，
而 `withSeed` 要的是 `uint64`；ChaLi **不做隐式转换**，你不写它就编译不过：

```text
chali: 调用 static 函数 Random::withSeed 找不到匹配的重载：(int64)；没有参数类型能对上的重载（候选：Random.withSeed）
```

第一次遇到会觉得它死板。但换个角度：报错说「我找不到 `(int64)` 的重载」，
它把**它拿到了什么**告诉你了。第 3 章会专门讲这套转换规则。

**为什么用种子，不用真随机？** 因为要**能复现**。

`withSeed(2026)` 每跑一次都给你同一串数，所以本书能写死「答案是 62」，
你照着敲也能得到 62。真实程序里想要每次都不一样，就用：

<!-- no-run -->
```chali
Random gen = Random::fromEntropy();
```

## 2.6 完整程序

把上面五步合起来：

<!-- run --stdin "50 75 62" -->
```chali
import std::random;

void main()
{
    Random gen = Random::withSeed((uint64)2026);
    int64 secret = gen.nextInt(1, 100);
    int64 tries = 0;

    println("我想好了一个 1 到 100 的数，你猜是多少？");
    while (true)
    {
        int64 guess = inputInt();
        tries = tries + 1;
        if (guess < secret)
        {
            println("太小了。");
        }
        elif (guess > secret)
        {
            println("太大了。");
        }
        else
        {
            println("猜对了！答案是 {}，你用了 {} 次。", secret, tries);
            break;
        }
    }
}
```

```sh
echo "50 75 62" | chali run guess.chl
```

```text
我想好了一个 1 到 100 的数，你猜是多少？
太小了。
太大了。
猜对了！答案是 62，你用了 3 次。
```

新东西只有一处：**`tries = tries + 1;`**

这行读作「`tries` 变成它原来的值加一」。`=` 依然是赋值。
ChaLi 也支持写成 `tries += 1;`（第 5 章会讲这一串复合赋值），
但本书前面会一直用 `tries = tries + 1` 这种最直白的写法——
**先写清楚，再写短**。

顺带一提：`++tries` 那种自增写法 ChaLi 也有，但它对「同一个变量在一个表达式里
被读写两次」管得很严，用不好会直接报错。第 5 章再说。

## 2.7 出错的时候

这个程序很容易出错，两种错法都很典型。

**输入不够。** 程序要两个数，你只给了一个：

<!-- fail --stdin "30" -->
```chali
void main()
{
    int64 first = inputInt();
    int64 second = inputInt();
    println("{} {}", first, second);
}
```

```text
chali aot: 输入不够（第 2 项缺失）
出错位置：guess.chl:3（main）
调用栈（内 → 外）：
  main
```

**输入不是整数。**

<!-- fail --stdin "abc" -->
```chali
void main()
{
    int64 value = inputInt();
    println("{}", value);
}
```

```text
chali aot: std::lang::inputInt 读到的不是合法 int："abc"
出错位置：guess.chl:3（main）
调用栈（内 → 外）：
  main
```

注意这两条报错和上一章那条语法错误的区别：

| | 什么时候报 | 谁的问题 |
| --- | --- | --- |
| `语法错误：…` | **编译期**，程序一个字符都没跑 | 代码写错了 |
| `chali aot: …` | **运行期**，跑到那一句才炸 | 数据不合法 |

ChaLi 的立场是：**代码的错误要尽量在编译期抓干净**。
所以「类型对不上」是编译期的事，而「用户输入了个 `abc`」只能运行期知道——
这种事它只能诚实地停下来，并告诉你停在哪一行。

程序停下来的位置写成了 `guess.chl:9`，连调用栈都给了；写大程序时这东西能救你。

## 2.8 小结

这一章你认识了四种积木，还有几个语法细节：

| 你会了 | 关键点 |
| --- | --- |
| 变量 | `int64 secret = 42;` —— 类型写在名字前面 |
| 输入 | `inputInt()` 读一个整数，读不合法就报错 |
| 分支 | `if (…) { } elif (…) { } else { }`，主体必须带花括号 |
| 循环 | `while (true) { … break; }` |
| 格式化 | `{}` 是位置占位符，类型由实参推导 |
| 模块 | `import std::random;`；只有 `lang` 是自动加载的 |
| 静态方法 | `Random::withSeed(...)`，`::` 后面是类型级的东西 |
| 强转 | `(uint64)2026` —— ChaLi 不做隐式转换 |

还有一个习惯要开始养成：**先 `check` 再 `run`**。

```sh
chali check guess.chl    # 只查语法和类型，不执行
```

输入失败与猜错是不同分支。先检查输入转换结果，再比较大小；上下界更新必须保留尚有可能的候选，并保证每轮取得进展。

## 2.11 习题

前两题用于理解和基本实现，第三题检查边界，最后一题为综合挑战。先独立完成，再核对参考解答。

1. 目标为 37，依次猜 50、25、37，应给出什么提示？
2. 给猜数字程序增加有效猜测次数统计。
3. 输入超出范围时重新提示，不能把它当成一次有效猜测。
4. 挑战：实现有限次数模式，分别测试第一轮猜中、最后一轮猜中和次数耗尽。

### 参考解答与验收要点

1. 依次为偏大、偏小、猜中；第三次结束循环。
2. 仅在输入成功且落在规定范围内时递增；猜中这一轮也计数。
3. 先做范围判断再进入大小比较和次数统计，测试上下界及紧邻范围外的值。
4. 让次数限制进入循环条件；耗尽后的失败提示不能覆盖最后一轮已经猜中的状态。

## 2.12 番外：龟兔猜数字

改写自伊索寓言《龟兔赛跑》。

兔子常常讥笑乌龟猜得慢。乌龟不服，说：“你跑得虽快，也未必猜得准。目标一到一百，我们比一比。”狐狸做裁判，先把答案藏进一个整数里，又特别声明：输入字符串不算猜。

兔子跳到终端前，先猜九十九，再猜二，接着输入一个“很大的数”。解析器报错。兔子觉得自己已经进行了三轮高强度推理，便躺到树下，说剩下的七十多次机会足够睡个午觉。

乌龟先猜五十。裁判说小，它便删去一半候选；猜七十五，大，又删一半。每走一步，都核对边界，连同一个错误也不肯重犯。狐狸看得直打呵欠：这个算法连戏剧冲突都对半砍。

兔子醒来，见乌龟还在纸上写字，笑道：“这么久才猜了六次！”说罢又输入九十九。裁判答：“这个分支你早来过。”

乌龟此时已写下答案。兔子奔到终点，发现验收表只有一行：“正确，七次以内。”它气得跳脚，说自己的输入速度遥遥领先。狐狸点头，把“每秒错误次数第一名”的奖牌挂在了它脖子上。

### 技术对照

输入失败与猜错是不同分支。先检查输入转换结果，再比较大小；上下界更新必须保留尚有可能的候选，并保证每轮取得进展。

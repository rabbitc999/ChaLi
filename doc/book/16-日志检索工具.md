# 第 16 章 日志检索工具

<!-- LANGUAGE NAVIGATION -->
[English](en/16-log-search.md) · **简体中文**
<!-- END LANGUAGE NAVIGATION -->

日志里通常只有少量行与眼前的问题有关。我们来写一个命令行工具：给它一个关键词和一个文件，它输出匹配行的行号及原文。先做区分大小写的查找，再加忽略大小写和只显示条数的选项。

完整工程在 [example/log-search](../../example/log-search/README.md)。可以先打开目录，跟着本章阅读和修改对应的函数；函数以外的入口放在 src/main.chl，搜索和输入处理放在 src/log_search.chl。

## 16.1 先看一次完整使用

示例文件有四行，第二行的 ERROR 是大写，第四行的 error 是小写。在工程目录运行：

```sh
chali run src/main.chl -- ERROR sample.log
```

结果是：

```text
2:ERROR cannot open report
```

run 后面的第一个 `--` 把后面的内容作为应用参数。应用收到关键词 ERROR 和文件名 sample.log，并不是把它们当成另一段 ChaLi 源码。加入 `--ignore-case` 后，第四行也会匹配；再加入 `--count`，输出就是 2。

## 16.2 把一条结果说清楚

先只考虑字符串，不打开文件。第 15 章的 contains 已经能回答“有没有”，但现在还要保留“在哪一行”和“原来写了什么”。我们用一个小结构体表示结果：

```chali
struct Hit
{
    int64 lineNumber;
    String text;
}
```

lineNumber 保存给人看的行号，从 1 开始；text 保存原文。把两者放在同一个值中，之后排序、打印或测试时就不容易把行号和文本拆散。

接下来是工程中的搜索函数：

```chali
List<Hit> search(String text, String query, bool ignoreCase)
{
    List<Hit> hits;
    List<String> lines = std::text::Text::split(text, "\n");
    String needle = query;
    if (ignoreCase)
    {
        needle = std::text::Text::toLower(needle);
    }
    for (int64 index in range(0, lines.len()))
    {
        String line = lines[index];
        if (index == lines.len() - 1 && line.isEmpty())
        {
            break;
        }
        if (std::text::Text::endsWith(line, "\r"))
        {
            line = line.substring(0, line.length() - 1);
        }
        String candidate = line;
        if (ignoreCase)
        {
            candidate = std::text::Text::toLower(candidate);
        }
        if (std::text::Text::contains(candidate, needle))
        {
            Hit hit;
            hit.lineNumber = index + 1;
            hit.text = line;
            hits.push(hit);
        }
    }
    return hits;
}
```

第一段准备空的结果列表，把输入按换行拆开，再准备实际用于比较的 needle。忽略大小写时先把关键词转成小写；这里的折叠只处理 ASCII 字母，中文仍按原字节匹配。

循环中的第一小段处理行尾。文件以换行结束时，split 可能留下最后一个空片段，它不是多出的一行日志。CRLF 的 CR 要从比较用的行末去掉，但真正的空白行仍占据原来的行号。

第二小段准备 candidate。需要忽略大小写时改变的是比较副本，不是输出原文。找到关键词后，把 `index + 1` 和 line 组成 Hit，加入结果列表。最后 return 把所有匹配交回调用者。

## 16.3 在小输入上检查搜索

下面的完整例子使用工程模块。把它放进工程 src 目录时，import 就能找到旁边的 log_search.chl。

<!-- verify-book -->
```chali
import log_search;

void main()
{
    let hits = log_search::search("INFO ready\nERROR disk\n", "error", true);
    assert(hits.len() == 1);
    assert(hits[0].lineNumber == 2);
    println("{}:{}", hits[0].lineNumber, hits[0].text);
}
```

```text
2:ERROR disk
```

第一条调用给出两行文字、关键词和大小写选项。接着两条断言分别核对数量与行号；它们检查不同的承诺。最后打印保留下来的原文，所以 ERROR 仍然是大写。现在把第二行改成没有关键词的内容，再相应修改预期，就能检查未匹配情况。

## 16.4 再把文件接进来

```chali
Result<String, Error> readText(String path)
{
    std::io::FileStream stream = std::io::FileStream::open(path, "r")?;
    return stream.readAllString(4194304);
}
```

这一小段只有两个主要动作。第一行调用 open 并用 `?` 取成功结果；打不开时，把错误交回调用方。第二行读取剩余文本，限制为四 MiB，再直接返回这次读取的 Result。

stream 是局部拥有值。函数结束时，它的文件资源随作用域收束；调用者得到的是文本，不需要接管这个流。四 MiB 是本工具的选择，让一次查询的工作量有界，不是 String 的语言上限。

## 16.5 让命令行描述一次查询

Options 保存 query、path、ignoreCase、countOnly 和 help。parseOptions 逐个读取参数，开关改变配置，其他内容进入位置参数列表；最后要求恰好有关键词与文件两个位置参数。

其中一段处理开关：

```chali
if (flags && argument == "--")
{
    flags = false;
}
else if (flags && argument == "--ignore-case")
{
    options.ignoreCase = true;
}
```

第一条分支结束应用自己的选项识别，后面的词即使以 `--` 开头也作为普通位置参数。第二条分支只开启一个布尔选项，不读取文件。完整函数还处理 count、help、未知开关及参数数量。

这里有两层不同的 `--`：编译器的一层把参数交给应用，应用的一层允许查询文字本身以两个连字符开头。可以试着查找 `--example`，确认它不会被误当成选项。

## 16.6 从配置走到输出

run 把几个部分接起来：先解析参数；帮助请求直接打印用法；否则读取文件、搜索，再决定输出每条命中还是条数。读取错误会附上用户给出的文件路径，再交回入口。

入口只负责作最后决定：

```chali
void main(List<String> arguments)
{
    let result = log_search::run(arguments);
    if (result.isErr())
    {
        panic("log-search: " + result.error().toString());
    }
}
```

第一条调用把参数交给业务函数。if 只检查失败结果，失败时给出错误诊断并结束本次运行；成功时自然结束。没有匹配项仍然是成功，计数模式会打印 0。这个教学入口没有实现 grep 的全部退出码约定，不能用一个特殊错误值代替正常的“零条匹配”。

## 16.7 继续改进时保留边界

现在可以分别测试搜索、参数和文件访问。仓库的项目测试还覆盖路径里的空格、CRLF、空文件、末行无换行、中文、零字节与超限文件。普通搜索不依赖这些测试怎样启动进程。

下一步可以增加最多显示多少条命中。先把它表示为配置，再让输出部分使用它，不要同时改搜索、读取和参数三处的含义。以后学习迭代器时，再回来考虑怎样减少中间列表。

## 16.8 习题

1. 用大小写不同的关键词比较两种模式，确认输出原文不变。
2. 增加 `--limit` 选项，限制显示的命中条数。
3. 让错误消息包含文件名，比较缺少参数与文件不存在的路径。
4. 如果改成分块读取，为什么不能简单地分别搜索每个块？

### 参考解答与验收要点

1. 只有比较副本被折叠，Hit.text 仍来自原行。
2. 解析并检查非负数量，在输出处限制，保留搜索结果的原行号。
3. 参数错误应在读取前发生；读取失败的上下文应包含实际路径。
4. 一行或一个关键词可能跨过块边界，需要保留未完成部分和累计行号。

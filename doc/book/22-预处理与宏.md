# 第 22 章 预处理与宏

<!-- LANGUAGE NAVIGATION -->
[English](en/22-macros.md) · **简体中文**
<!-- END LANGUAGE NAVIGATION -->

有些重复来自程序结构本身，而不仅是同一个函数被多次调用。宏在编译阶段组合语法，可以表达这种结构复用；代价是调用者需要更清楚地理解求值次数、名称来源和类型上下文。

本章先用计数器看清参数怎样求值，再逐步生成表达式、语句、模块声明和类型成员。最后遍历结构体字段，为不同字段生成不同操作。阅读时把编译时生成的结构与运行时执行的语句分开。

## 22.1 值参数、引用与卫生

先观察一个会改变状态的实参 next()。如果宏只是需要同一个结果两次，应该先取一次值再复用；如果宏接收的是待放置的表达式，两个放置位置则可能各执行一次。调用外观看起来相似，接口必须把这个差别说明白。

未标注参数采用单次求值的值参数规则：$A(next()) 的一个实参一次，$A(next(), next()) 的两个实参各一次。修改参数副本不改变调用方；只在保持行为时才能减少复制。显式 value 与 expr 的对比将在下一节用计数器展示。

显式 &n 借用只读值，mut &n 允许修改调用方；静态借用要求仍然生效。宏内部临时名保持卫生，不能从外部依赖某个展开时生成的临时名字。


### 修改副本还是修改来源

<!-- verify-book -->
```chali
$macro Bump(n) -> stmt
n = n + 1;
$end_macro
$macro RefBump(mut &n:value) -> stmt
n = n + 1;
$end_macro
void main()
{
    int64 x = 7;
    $Bump(x);
    println("{}", x);
    $RefBump(x);
    println("{}", x);
}
```

```text
7
8
```

Bump 的 n 没有引用标记。调用时先把 x 的值交给参数，宏中的赋值改变参数副本，因此第一行仍输出 7。这个写法不产生“修改了副本”的警告。

RefBump 的 mut &n 明确借用可修改的来源，第二次赋值写回 x，于是输出 8。只读借用写成 &n；它允许读取，拒绝写入。是否生成实际复制由编译器在保持这些可观察结果的前提下优化，不能把副本写入偷偷变为对 x 的写入。

## 22.2 参数类别决定展开方式

x:value 保留单次求值规则，x:expr 接收表达式语法并按展开位置执行：使用两次可能执行两次，未使用则不会执行。name:ident、T:type、body:stmt 和 body:block 分别要求相应语法类别。类别诊断发生在不匹配位置，不把任意语法都当作值参数。

多个 value 实参按调用实参顺序先求值；expr 片段随后随宏体中的放置位置执行。不要用 expr 传入有副作用的代码却假定它仍只执行一次。

<!-- verify-book -->
```chali
int64 count = 0;
int64 next() { count += 1; return count; }
$macro TwiceValue(x: value)
x + x
$end_macro
$macro TwiceExpr(x: expr)
x + x
$end_macro
void main() {
    int64 value = $TwiceValue(next());
    println("{} {}", value, count);
    count = 0;
    int64 expression = $TwiceExpr(next());
    println("{} {}", expression, count);
}
```

```text
2 1
3 2
```

next 每调用一次便递增全局 count，再返回新的计数。TwiceValue 的 x:value 先取得一次 next() 的结果 1，再把同一个值相加得到 2，所以第一次输出 `2 1`，分别表示计算结果和真实调用次数。

把 count 清零后，TwiceExpr 将表达式语法放在两个使用位置，运行时 next() 执行两次，分别得到 1、2，相加为 3，因而输出 `3 2`。两种宏体看起来同样写 x+x，但参数类别改变求值方式；这个区别会直接影响输入读取、状态更新和资源取得，不能只看展开式的外观。


### 从求值次数选择参数类别

先问宏要复用一个已经算出的值，还是把一段语法放到新的执行位置。读取输入、递增计数器或取得资源通常需要明确求值次数，优先考虑普通值参数。只有需要由展开后的控制结构决定执行位置时，才选择 expr，并向调用者说明它可能被跳过或重复执行。复制资源的成本与副作用也要按类型的复制规则判断，不能因为参数出现在宏里就忽略。

ident 传递名称，type 传递类型语法，stmt 与 block 传递语句或块；它们解决的是语法位置问题。类型参数 T 与形参 T:type 也不能仅凭字母相同就混为一谈。类别匹配之后，实际使用的名称、类型、借用与所有权仍须合法，传入一个标识符不会自动取得对该对象的写权限。

卫生意味着名字带有来源身份。模板自己声明的 result 可以与调用方的 result 同名而互不覆盖；模板中未声明的 temp 也不能靠调用方恰好存在一个 temp 来补全。这使宏可以在不同工程中复用，而不必要求每位使用者避开一份隐藏的临时名清单。需要影响调用方对象时，接口应明确表达这种关系。

## 22.3 泛型参数与结果上下文

宏可以声明类型参数。T:#res 从使用结果的静态期望类型推导，U:b 从名为 b 的实参静态类型推导；它们不是在编译阶段运行实参表达式。显式类型参数优先，期望类型不足或约束冲突时需要补充类型。

例如 $macro Example<T:#res, U:b>(a, b) 同时使用结果与实参信息，推导出的 T、U 还必须满足宏体与调用位置的检查。

<!-- verify-book -->
```chali
$macro Example<T:#res, U:b>(a, b)
{
    T left = cast<T>(a);
    U right = b;
    yield left + cast<T>(right);
}
$end_macro
void main() {
    int32 result = $Example((int64)3, (int16)4);
    println("{}", result);
}
```

```text
7
```

T:#res 从 result 声明的 int32 取得期望结果类型，U:b 则从第二个实参 `(int16)4` 推导为 int16。第一个实参虽然是 int64，但宏体显式 cast<T>，把它转换到 left 的类型；right 先保留 U，再在相加位置转换成 T。

因此最终相加发生在符合结果上下文的类型中，值为 3+4=7。推导使用静态信息，不会为了知道 U 而预先执行 b。若去掉结果上下文或制造不相容约束，应提供显式类型或修正调用，不能把结果来源推导理解为运行期自动适配。


## 22.4 参数组与变长参数

固定参数解决一次调用中的几个位置；变长参数则接收一组同类输入。下面先构造一个列表，再学习怎样给整组输入标注类别。

<!-- verify-book -->
```chali
$macro vec<T:first>[first,...rest]
{
    List<T> result;
    result.push(first);
    $for element in rest
    result.push(element);
    $end_for
    yield result;
}
$end_macro

void main()
{
    List<int64> result;
    result.push(99);
    List<int64> values = $vec[1, 2, 3];
    println("{} {} {}", values.len(), values.at(2), result.at(0));
}
```

```text
3 3 99
```

vec 用方括号作为调用组，first 提供首个元素与 T 的推导来源，rest 收集后续实参。宏先创建自己的 List<T>，加入 first，再由编译期 $for 为 rest 中每个元素生成 push 语句；这些 push 在生成的程序运行时执行，yield 交出列表。

调用 `$vec[1, 2, 3]` 得到三项，at(2) 因为下标从 0 开始而取到 3。调用方另有 result，只含 99；卫生规则让宏内同名 result 不覆盖它，所以末项仍打印 99。不要把 $for 与程序里的运行期 for 混为一谈，也不要把这套已有重复形式推广成尚未支持的任意模式匹配。



## 22.5 显式说明宏生成什么

前面的宏生成计算结果。现在需要在模块里增加一个函数，调用位置就不再是表达式。箭头后的结果类别告诉编译器该把展开结果放在哪里。

| 结果类别 | 放置位置 | 常见用途 |
| --- | --- | --- |
| -> expr | 表达式位置 | 求和、构造一个值 |
| -> stmt | 函数体的语句位置 | 更新对象、输出多行 |
| -> item | 模块声明位置 | 生成函数、结构体、枚举或接口 |
| -> member | 类型体的成员位置 | 生成字段或方法 |

参数类别与结果类别是两个问题。name:ident 约束传入一个名称；-> item 约束生成模块声明。二者不能互相代替。

<!-- verify-book -->
```chali
$macro FUNCTION(name:ident) -> item
int64 name() { return 42; }
$end_macro
$macro RECORD<T>(name:ident) -> item
struct name { T value; }
$end_macro
$FUNCTION(answer);
$RECORD<int64>(Score);
void main()
{
    Score score;
    score.value = answer();
    println("{}", score.value);
}
```

```text
42
```

第一段 FUNCTION 接收一个标识符，把它放到函数名的位置。$FUNCTION(answer) 因而生成普通的 answer 函数；调用时 answer() 返回 42，不再运行宏展开器。

第二段 RECORD 另有类型参数 T。$RECORD<int64>(Score) 把 Score 放在结构体名称位置，把 int64 放在字段类型位置。main 先声明 Score 对象，再把 answer() 的结果写入 value，最后输出该字段。

声明调用放在 main 外面。把 -> item 的调用放进赋值右侧会造成类别错误；同一模块里重复生成相同公开名称，也仍然是声明冲突。通过 ident 参数明确传入的名称用于调用方接口，模板自己的辅助名称则保留卫生身份。

## 22.6 在类型体中生成成员

<!-- verify-book -->
```chali
$macro GET(name:ident, field:ident) -> member
int64 name() { return self.field; }
$end_macro
struct Counter
{
    int64 value;
    $GET(read, value);
}
void main()
{
    Counter counter;
    counter.value = 9;
    println("{}", counter.read());
}
```

```text
9
```

先读宏定义：name 是生成的方法名，field 是方法读取的字段名。self 来自生成方法的接收者，不是宏定义处某个对象。

再读结构体：Counter 已声明 value，随后 $GET(read, value) 在同一个类型体中生成 read 方法。它的效果可以按普通代码理解为 int64 read() { return self.value; }。main 写入 9，再调用这个方法，得到同一个 9。

这里的方法返回 int64，因此只能配合相容字段使用。需要支持其他字段类型时，可以像泛型函数一样给成员宏增加类型参数。生成的方法仍检查字段访问、返回类型和借用；它与手写方法重名时也会报错。接口中可以生成方法声明或默认方法，不能用成员宏给接口塞入实例字段。

## 22.7 为整组实参标注类别

<!-- verify-book -->
```chali
int64 calls = 0;
int64 next() { calls += 1; return calls; }
$macro SUM(...values:value) -> expr
int64 total = 0;
$for value in values
total += value + value;
$end_for
total
$end_macro
void main()
{
    int64 result = $SUM(next(), next());
    println("{} {}", result, calls);
    println("{}", $SUM());
}
```

```text
6 2
0
```

定义头中的 ...values:value 收集零个或多个值实参。第一段 next 每调用一次递增 calls，方便看清真实执行次数。

main 的第一个调用先从左到右取得 1 和 2。$for 为这两个参数生成两条累加语句；value + value 复用各自已经取得的值，所以总和是 (1+1)+(2+2)=6，calls 是 2。第二个调用没有元素，不生成累加语句，total 保持 0。

把类别换为 expr，就改为在每个放置位置执行表达式；不再保留这个单次求值约定。ident、type、stmt、block 也可以标注变长参数，分别收集名称、类型、语句和块。变参必须位于自己参数组的末尾；空组合法，但使用它的宏要给出合理的空结果。

## 22.8 把模式与分支代码一起传入

有时重复的部分是一段 match，而每次调用要匹配的模式不同。pattern 参数保留模式结构及其中的绑定，block 参数提供命中后执行的代码。

<!-- verify-book -->
```chali
enum Pair
{
    Values(int64 first, int64 second),
    Empty
}
$macro SELECT(value:value, p:pattern, body:block) -> expr
match(value)
{
    p => { yield body; }
    _ => { 0 }
}
$end_macro
void main()
{
    int64 x = 100;
    Pair pair = Pair::Values(7, 8);
    int64 total = $SELECT(pair, Pair::Values(x, y), { yield x + y; });
    println("{} {}", total, x);
}
```

```text
15 100
```

第一段 Pair 声明两个载荷的枚举分支。SELECT 的 value:value 只取得一次被匹配值，p:pattern 放在分支箭头左侧，body:block 放在命中分支中。通配分支给出 0，使这个表达式在未命中时也有结果。

main 里的模式 Pair::Values(x, y) 将两个载荷分别绑定到模式局部 x、y。紧随的块使用这些绑定，得到 7+8。外层另有 x=100；它没有被这个局部绑定修改，所以输出 15 100。

也可以传入 1 | 2 这样的联合模式，或接口载荷模式 Err::IoError(e)。它们仍按第 10、17 章的匹配规则检查；宏不会让一个不合法或不完整的模式合法化。多载荷枚举的接口筛选继续在括号中标注各载荷类型。

## 22.9 先读取字段元数据

运行期反射面向已经存在的对象；这里先根据具体类型，在编译期取得字段信息。

<!-- verify-book -->
```chali
struct Record
{
    int64 score;
    static int64 shared;
    String name;
}
void main()
{
    println("{}", $fields<Record>().count);
    println("{}", ($fields<Record>())[0].name);
    println("{}", ($fields<Record>())[1].type.name);
}
```

```text
2
score
std::lang::String
```

Record 中有三个声明，但 shared 是静态字段，不属于实例字段集合。因此 count 是 2，顺序依源码中的 score、name 排列。

第一条 println 使用编译期得出的数量；第二条下标 0 取得字段名 score；第三条沿着字段的 type 取得规范类型名 std::lang::String。这些元数据在编译阶段处理，运行时输出的是已生成的标量值。

字段还提供 index、id、type 和 attributes；类型信息可以继续读取嵌套 fields，注解信息可以读取名称及 arguments。id 用于区分当前编译中的身份，不作为跨版本持久编号。元数据集合不能当作普通 List 保存到运行时变量，也不能用运行时下标查询。这里的字段遍历针对普通结构体；枚举与方法的编译期反射不是本节接口。

## 22.10 按字段生成不同代码

现在利用元数据，让同一个宏只累加 int64 字段，跳过姓名。

<!-- verify-book -->
```chali
struct Record
{
    int64 first;
    String name;
    int64 second;
}
$macro SUM_FIELDS<T>(&value:value) -> expr
int64 total = 0;
$for field in $fields<T>()
$if field.type.name == "int64"
total += $member(value, field);
$end_if
$end_for
total
$end_macro
void main()
{
    Record record;
    record.first = 3;
    record.name = "Ada";
    record.second = 4;
    println("{}", $SUM_FIELDS<Record>(record));
}
```

```text
7
```

第一段 Record 提供两个整数和一个字符串。宏声明中的 &value:value 使用只读借用，避免为了遍历读取而要求修改调用方。

第二段先创建运行时累加器 total。$for 在编译时按声明顺序访问三个字段；$if 检查编译时已知的类型名称。只有 first 与 second 生成累加语句，name 不进入相加的类型检查。

$member(value, field) 将字段描述符转为直接成员访问。在这个具体调用中，可以把生成的主体理解为 total += value.first; total += value.second;。运行期没有按字符串 name 查找字段的循环，实际加法仍在程序运行时执行。

第三段 main 初始化 3、Ada、4，再调用宏，得到 7。要写字段时必须把参数改为 mut &value:value，字段本身也要可写；$member 不绕过借用或访问检查。字段描述符必须属于这个对象的具体类型，同名字段并不足以跨类型使用。

## 22.11 成组遍历与编译期诊断

<!-- verify-book -->
```chali
$macro DOT(...left:value)[...right:value] -> expr
$compile_assert($count(left) == $count(right), "两组长度必须相同");
int64 total = 0;
$for (a, b) in (left, right)
total += a * b;
$end_for
total
$end_macro
void main()
{
    println("{}", $DOT(2, 3)[4, 5]);
    println("{}", $DOT()[]);
}
```

```text
23
0
```

定义头有两个有序参数组：圆括号接收 left，方括号接收 right。调用时也必须保留这两个组及其顺序。

$count 读取捕获数量，$compile_assert 在展开时检查两组长度。$for (a, b) in (left, right) 按位置配对，第一轮生成 2*4，第二轮生成 3*5，因此输出 23。空组没有累加步骤，返回 0。循环本身也要求列表长度一致，不会按较短列表悄悄截断。

把调用改成 `$DOT(2, 3)[4]`，应在编译时拒绝，而不是运行一半才失败。$compile_error("原因") 可以在选中的编译期分支直接给出诊断；例如生成 JSON 时遇到未支持字段类型，就应明确指出那个类型，而不是生成类型错误的编码代码。

$if 的条件必须能在编译期求值。可以使用字段类型信息和 $count，不能调用普通运行期函数来决定模板结构。$match x is ident 与 $regex x is "[0-9]+" 分别按完整语法类别和完整原文正则选择模板分支；它们也不是程序里的运行期 match 或字符串正则库。

## 22.12 从一个字段遍历到完整例子

[macro_fields.chl](../../example/reflection/macro_fields.chl) 把相同方法用于字段打印、校验和 JSON 输出。阅读较长的程序时，分成下面四段：

1. quoteJson 与 boolText 只处理一个标量。前者转义引号、反斜线及控制字节，后者生成 JSON 所需的 true、false，而非普通输出中的 1、0。
2. PRINT_FIELDS 借用对象，按字段生成 println；VALIDATE_FIELDS 根据字段类型生成非空或非负检查。这两段共享字段遍历方式，但生成的操作不同。
3. JSON_FIELDS 先检查字段数量，再生成键、冒号、逗号与值。字符串交给 quoteJson，整数使用格式化，布尔值交给 boolText，不支持的类型通过 $compile_error 拒绝。
4. main 准备一个 Student，分别调用三个宏，并用 JSON 解析器核对编码结果。解析器是验证生成文本的工具，字段访问本身不依赖运行期反射。

可以先删掉 JSON_FIELDS，只运行打印与校验；理解每段以后再加回编码。给 Student 增加一个 bool 字段，观察哪些语句随之生成，比一次阅读所有展开节点更容易看清机制。

## 22.13 查看展开与定位错误

在 VS Code 中打开宏调用，使用 ChaLi 的宏展开预览，分别查看一层展开与全部展开。嵌套宏的一层预览可能仍含宏调用，全部预览继续展开它们；预览提供调用及定义的来源信息，不是稳定的源码导出格式。先对照本章小例子的预期输出，再追踪复杂展开中的对应节点。

出现错误时，先核对参数类别与结果类别，再看类型推导、字段所属类型以及名称来源。下面的 temp 用来说明最后一个问题。

### 一个卫生错误

宏报错时先区分定义位置与调用位置，检查类别、类型参数、展开作用域和借用。下面是需要被拒绝的卫生示例：宏内部临时变量不能作为调用方可见名字读取。

<!-- verify-book-error: temp -->
```chali
$macro broken(value)
{
    temp.push(value);
    yield temp;
}
$end_macro

void main()
{
    List<int64> temp;
    List<int64> values = $broken(1);
}
```

broken 的模板直接使用 temp，却没有在模板自己的作用域中声明它，也没有通过形参接收这个来源。main 的 temp 虽然拼写相同，仍属于调用方；卫生名称解析不会把两者自动连接。

因此错误在编译检查阶段出现，没有正常运行输出。可以通过明确的参数接口表达需要的对象，或在宏内声明真正的局部列表，但不能靠调用方偷偷补一个同名变量修复模板。这里的 value 只提供元素值，没有提供列表来源。


### 展开与运行分别发生什么

宏展开在编译阶段组合程序结构；示例中的 next 仍在程序运行时执行。编译器知道某个表达式的静态类型，不等于已经执行它。T:#res 从赋值、返回等位置提供的期望类型取得信息，也不是运行程序以后观察结果再选择类型。缺少足够上下文时，应提供明确类型，而不是依赖偶然的字面量推导。

展开产物继续接受普通检查，之后进入四元式与 LLVM 后端。宏不能取消资源清理、绕过借用约束或给一个非法表达式增加执行资格。运行性能也取决于实际生成的操作及 LLVM 优化；少写模板代码不等于减少了运行工作量。定位错误时，可以先把调用的意图写成普通代码，确认类型和资源关系，再检查宏是否保留了这些关系。

### 小结

先用普通函数判断需求能否直接表达，再在确需语法组合时选择宏。阅读宏调用时，逐项标出哪些实参先得到值、哪些作为片段放置、名字属于调用方还是模板，以及结果类型来自哪里。

宏展开不执行任意用户运行期逻辑，也不使非法借用或资源使用合法。下一章的运行期反射解决按元数据访问对象的问题，不能与编译时生成语法结构混为同一机制。


## 22.14 单行宏与无参数宏

宏体只有一行时可以用 $replace。它使用同样的卫生 AST 替换规则，不需要 $end_macro。

<!-- verify-book -->
```chali
$replace ADD(a, b) a + b
$replace LIMIT 100
void main()
{
    println("{}", $ADD(2, 3) * 10);
    println("{}", $LIMIT + 1);
}
```

```text
50
101
```

第一条定义 ADD，调用仍写 $ADD(2, 3)。加法作为一个完整表达式参与后面的乘法，先得到 5，再乘 10，所以输出 50。这里不需要用文本替换的思路猜括号。

第二条定义没有参数组的 LIMIT，因此使用 $LIMIT，不写括号。若定义的是 $macro LIMIT()，调用也要保留空圆括号。多行模板、$for 和多段分支使用 $macro 配合 $end_macro，便于把结构写清楚。

## 22.15 保留原文、组合名字与记录来源

<!-- verify-book -->
```chali
module macroTutorial;
$macro SHOW(x)
$stringify(x)
$end_macro
$macro MAKE(a, b)
$concat(a, b)
$end_macro
int64 itemCount = 9;
void main()
{
    println("{}", $SHOW(1 + 2));
    println("{}", $MAKE(item, Count));
    println("{}", $module);
}
```

```text
1 + 2
9
macroTutorial
```

SHOW 的主体是 $stringify(x)，读取的是实参原文。1 + 2 因此输出为文字，不计算成 3；原文中的注释也可以保留。字符串化不意味着实参已经作为普通值执行。

MAKE 使用 $concat 生成一个标识符。item 与 Count 组合成 itemCount，再按生成名称的规则解析为本例全局变量，得到 9。它只允许生成单个合法标识符，不能拿来拼接任意语句，也不是连接两个 String 的函数。

最后一行 $module 得到当前模块名。$file 提供来源文件，$line 提供来源行号；它们用于诊断，例如在模板中加入调用点的行号。文件路径会随环境改变，不宜把某台机器的路径写成通用预期输出。嵌套宏要沿来源信息找调用位置，不能用展开结果的显示行号代替源文件行号。

## 22.16 按语法或原文选择模板

<!-- verify-book -->
```chali
$macro CLASSIFY(value) -> expr
$match value is ident
1
$else is expr
2
$else
0
$end_match
$end_macro
$macro NUMBER(value) -> expr
$regex value is "[0-9]+"
value
$else
0
$end_regex
$end_macro
void main()
{
    println("{} {}", $CLASSIFY(name), $CLASSIFY(1 + 2));
    println("{} {}", $NUMBER(42), $NUMBER(noSuchFunction()));
}
```

```text
1 2
42 0
```

CLASSIFY 先尝试完整 ident，失败再尝试完整 expr。name 是标识符，同时也可处于表达式位置，但顺序使它命中第一支，得到 1；1 + 2 不是单个标识符，命中第二支，得到 2。这里检查语法形状，name 没有作为运行期变量读取，所以不要求为这个分类示例声明它。

NUMBER 使用完整 ECMAScript 正则匹配。42 的原文满足 [0-9]+，被选中的模板保留 42；noSuchFunction() 不满足，选择 0，不生成那个函数调用。这正是未选中模板不进入最终语义检查的用途，不能据此认为任何未知名字都能运行。

$match 的分类支持 ident、expr、type、block、stmt，使用 $else is 依次选择，$end_match 收束。$regex 使用 $end_regex 收束；它检查完整原文，不是搜索任意一段子串，因此 abc123 不会匹配 [0-9]+。

## 22.17 参数组和嵌套转发

圆括号、方括号和花括号可以组成有序参数组。例如 ``$macro ADD[a](b){c}`` 配合主体 a + b + c，调用就写 `$ADD[1](2){3}`。组形状和顺序必须一致，不能改成 $ADD(1, 2, 3)。每组末尾可以有自己的变参，...rest 也可写成兼容形式 ..rest。

<!-- verify-book -->
```chali
$macro SUM(...values:value) -> expr
int64 total = 0;
$for value in values
total += value;
$end_for
total
$end_macro
$macro FORWARD(...values:value) -> expr
$SUM(values)
$end_macro
void main()
{
    println("{}", $FORWARD(2, 3, 4));
    $std::lang::assert($FORWARD() == 0);
}
```

```text
9
```

SUM 用 $for 把捕获的每一项生成累加语句。FORWARD 在嵌套调用的参数位置直接使用捕获列表 values，按列表转发三个参数；它没有把这组实参当作一个运行期 List。

因此第一个调用依次累加 2、3、4，输出 9。第二个转发空捕获，仍保留合法的空参数组，断言其结果为 0。value 的单次求值规则跨转发保留；传递 expr 则仍然传递语法片段，不会因为多包一层而自动变成值参数。

最后一条使用 $std::lang::assert，这是宏的模块限定名。导入后可以使用可见的宏名，需要明确来源或处理重名时使用完整限定名；普通函数调用和宏调用仍分别使用 assert(...) 与 $assert(...) 这样的语法。

## 22.18 怎样选择这些写法

先写普通函数，适合类型参数的重复交给泛型。只有重复发生在语法位置、声明结构或字段集合时，再引入对应的宏。先确定参数是一个值、一个名字还是一段代码，然后确定生成结果放在表达式、语句、模块还是类型体。把这两个决定写进定义头，比让读者猜展开行为更容易维护。

本章的每一种扩展仍接受名称、类型、借用和资源检查。想复用新项目里的序列化代码时，可以从字段打印的小宏开始，确认展开以后再增加编码规则。

2. 修改未标注参数会改变调用方吗？
3. T:#res 的类型来自运行期返回值吗？
4. 为什么不能读取宏内部 temp？

### 参考解答与验收要点

1. value 每个实参一次；expr 按实际放置和执行次数。

## 22.20 番外：宏展开之后

改写自《聊斋志异·画皮》。

太原王生，早行，遇一丽人，抱一卷宏模板，步甚艰。生悦而纳之，问其能何为。女曰：“妾可将三行变作百行，且不烦君亲写。”生大喜，遂与共处，连展开结果也不曾看。

一日，道士见生，曰：“子身上有两次求值之气。”生不信。归而窥之，见模板摊于屏上，next() 在两处各写一遍，却没有任何形参，拿笔者乃一副重复执行的骨架。

王生大惊，数其计数器，果然本欲加一，实已加二。女辩曰：“这两个 next() 本就是我在模板里写下的两次调用，怎能算作一个实参？”

生又在门外放一个 `temp`，指望宏内同名者来替自己持家。道士拂尘一挥：“卫生绑定，各有来处，莫拿隔壁同名之人顶替户主。”

生乃求救。道士令他改用一个表达式形参，编译器便先求值一次，再在模板中复用；需要修改外界之物则明写 mut & 参数。展开之后，照旧过名称、类型与借用检查，不能披一张漂亮的宏皮便免检。

王生自此见到“少写九成代码”便先问：“生成的那九成，能给我看一眼么？”道士点头，说此人总算从审美转入了代码审查。

### 技术对照

宏保留语法、来源与卫生绑定；表达式参数各求值一次并复用其值。普通参数修改的是副本，显式 mut & 参数才写回来源。不能用调用者的同名变量补救模板中的未定义名称。

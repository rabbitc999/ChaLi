# 第 5 章 控制流

<!-- LANGUAGE NAVIGATION -->
[English](en/05-control-flow.md) · **简体中文**
<!-- END LANGUAGE NAVIGATION -->

相同的一组语句，执行顺序和次数不同就会得到不同结果。控制流负责选择分支、重复操作和结束当前结构。本章把每一次条件判断与状态变化对应起来，而不只列出关键字。

先看 if 如何选出一个值，再用区间循环累加，随后从循环中取得结果，最后处理嵌套退出。阅读时同时记录当前变量值与所处循环层级，尤其注意 yield、break、continue 和 return 所作用的范围。

## 5.1 先用分支返回一个分类

<!-- verify-book -->
```chali
String classify(int64 value)
{
    if (value < 0)
    {
        return "负数";
    }
    elif (value == 0)
    {
        return "零";
    }
    else
    {
        return "正数";
    }
}

void main()
{
    println("{} {} {}", classify(-3), classify(0), classify(8));
}
```

```text
负数 零 正数
```

classify 依次比较负数、零与正数。遇到 return 就结束这次调用，因此负数不会继续执行后两支。main 从左到右调用三次，输入 -3、0、8，各得到一个 String，再由同一条 println 输出。先把 8 改为 0，猜一猜输出，再看后面怎样把分支写成表达式。

## 5.2 条件链与条件表达式

先考虑一个简单判断：根据 p 是否为奇数得到一个布尔值。if 不仅能选择要执行的语句，也能在赋值右侧选择一个结果。这样结果的两条来源就写在同一个表达式里，不必先声明变量再分别赋值。

条件必须产生 bool，结果分支则要提供相容的类型。if、elif、else 依次尝试，命中后不再执行后续分支；else if 与 elif 等价。下面先用分支末尾的表达式给值，再展示需要局部步骤时怎样写 yield。

<!-- verify-book -->
```chali
void main()
{
    int32 p = 5;
    bool odd = if (p % 2 == 1)
    {
        true
    }
    else
    {
        false
    };
    int32 category = if (p % 3 == 1)
    {
        1
    }
    elif (p % 3 == 2)
    {
        2
    }
    else
    {
        3
    };
    odd = if (p % 2 == 0)
    {
        false
    }
    else
    {
        bool value = true;
        yield value;
    };
    println("{} {}", odd, category);
}
```

```text
1 2
```

p 为 5，第一次 if 检查余数 `5 % 2`，结果为 1，因而把 true 交给 odd。category 的条件依次比较 `5 % 3`：它不等于 1、等于 2，所以选中 elif 并取得整数 2，else 不执行。

随后对 odd 重新赋值。偶数条件不成立，进入 else，先声明局部 value，再用 yield 明确交出它。前面的分支直接以末尾表达式给出值，这里用多条语句加 yield，最终 odd 都是 true。输出中的布尔值按本例格式显示为 1，因而得到 `1 2`；分支需要返回相容类型，不能任意混用整数和布尔结果。


## 5.3 循环累计与区间

for-in 遍历区间或实现迭代协议的对象。range(a,b) 的上界不包含 b；rangeEq 包含上界。while 在每轮前检查条件，loop 依靠循环体中的退出路径。先明确区间端点和状态更新，再计算迭代次数。

<!-- verify-book -->
```chali
void main()
{
    int64 total = 0;
    for (int64 k in range(0, 5))
    {
        total = total + k;
    }
    println("{}", total);
}
```

```text
10
```

total 在循环外初始化为 0，保证每一轮更新的是同一个累加器。`range(0, 5)` 产生 0、1、2、3、4，不包含上界 5；for 每取到一个数，就把它加到 total。

逐轮结果是 0、1、3、6、10，循环结束后只执行一次 println，因此不是每轮输出一行。若把 total 的声明移入循环体，每轮都会重新归零，含义就不再是累计。区间上界是否包含应按接口核对，不能从自然语言“到 5”自行推断。


## 5.4 从循环取得结果

带值循环使用 yield 产生结果；需要处理未产生结果的路径时使用 else。不要把一个无结果的循环当作整数使用。下例同时展示成功退出和无匹配时的结果。

<!-- verify-book -->
```chali
void main()
{
    int64 found = for (int64 value in range(0, 10))
    {
        if (value > 5)
        {
            yield value;
        }
    }
    else
    {
        yield -1;
    };
    String label = while (false)
    {
        "运行"
    }
    else
    {
        "结束"
    };
    println("{} {}", found, label);
}
```

```text
6 结束
```

第一个 for 是赋值右侧的表达式。它依次检查 0 到 9，前六个值都不满足大于 5；遇到 6 时 yield 将 6 作为整个 for 的结果交给 found，并停止继续搜索。只有没有取得循环体结果时，else 才提供 -1 作为后备值。

第二个 while 的条件一开始就是 false，因此循环体中的“执行”不会产生，直接由 else 交出“跳过”。最终打印 `6 跳过`。循环表达式的 else 在这里用于补齐未取得结果的路径，不应按普通 if 的相邻分支来猜测其执行时机。


## 5.5 退出层级与清理

continue 进入下一轮，break 退出循环。嵌套循环可用 break level N 或 break all 指定退出层级；带值退出还需有相应结果接收者。离开的作用域执行资源清理，第 9 章进一步说明。

自增减和复合赋值会修改目标。避免在一个表达式里安排相互依赖的读写，拆成有明确顺序的语句。

<!-- verify-book -->
```chali
void main()
{
    int64 visited = 0;
    loop
    {
        loop
        {
            visited++;
            break level 2;
        };
        visited += 100;
    };

    int64 total = 0;
    List<int64> values;
    values.push(2);
    values.push(4);
    values.push(6);
    for (item in values)
    {
        total += item;
    }
    println("{} {}", visited, total);
}
```

```text
1 12
```

visited 初始为 0。进入内层 loop 后先递增为 1，`break level 2` 一次退出包含它的两层循环，因此外层后面的 `visited += 100` 不执行。这里的 2 是循环嵌套层数，不是重复 break 两次或退出两个函数。

第二部分依次把 2、4、6 加入 values，for 从容器取得每个 item 并加到 total，得到 12。输出把两个互不相关的结果放在同一行：退出范围决定 visited 为 1，容器遍历决定 total 为 12。读取循环时应同时标出状态更新位置和退出所跨越的范围。


### 小结

判断控制流时可按三个问题检查：条件在何时求值，状态在哪更新，出口通往哪里。条件表达式还多一个问题：每条可达路径能否提供相容的结果。这样可以分别发现漏更新造成的无限循环、区间端点错误和缺失结果路径。

退出同时会离开作用域。本章先把路径看清，第 9 章再把资源清理动作放到同一条路径上核对。

## 5.7 番外：桃花源里的 break

改写自陶渊明《桃花源记》。

晋太元中，武陵人以调试为业。缘循环行，忘层之远近。忽逢桃花林，夹岸数百步，中无杂树，唯有日志，落英缤纷。渔人甚异之，复前行，欲穷其源。

林尽水源，便得一山。山有小口，仿佛若有退出条件。便舍舟，从口入。初极狭，才通一个 `break`。复行数十步，豁然开朗——下一轮又开始了。

其中往来种作，男女衣着，悉如外层循环；黄发垂髫，并问：“为什么还没停？”渔人具答之。村人乃大惊，设酒杀鸡作食，说这代码运行六百年了，第一次有人发现刚才只退出了内层。

村中闻有此人，咸来问讯。自云先世避测试，率妻子邑人来此绝境，不复出焉。问今是何世，乃不知有 `break level`，无论函数返回。此人一一为具言所欲退出之层，皆叹惋。

停数日，辞去。此中人语云：“不足为外人道也，尤其别告诉产品经理已经找到出口。”

既出，得其船，便扶向路，处处志之。及郡下，诣太守，说如此。太守即遣人随其往，改了一层嵌套，遂迷，不复得路。南阳刘子骥，高尚士也，闻之，欣然规往；未果，先问清了验收条件。

### 技术对照

break 和 continue 的目标由语法和所在循环决定。修改嵌套结构后必须重新核对目标；带值退出还需要满足所在表达式的结果类型要求。

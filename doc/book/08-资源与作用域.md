# 第 8 章 资源与作用域

<!-- LANGUAGE NAVIGATION -->
[English](en/08-resources-scopes.md) · **简体中文**
<!-- END LANGUAGE NAVIGATION -->

文件、缓冲区和其他资源需要确定拥有者与清理位置。值离开作用域、提前返回和显式转移都可能改变清理路径。本章先观察顺序，再区分自动拥有值与手动存储。

## 8.1 离开作用域时的动作

defer 注册离开当前作用域时执行的动作，scope(exit) 可注册一段清理代码。多个退出动作按注册的逆序执行。提前退出也要沿实际离开的作用域处理清理。

<!-- verify-book -->
```chali
void main()
{
    {
        defer println("first");
        scope (exit)
        {
            println("second");
        }
        println("body");
    }
}
```

```text
body
second
first
```

## 8.2 Drop 与字段清理

实现 Drop 的值可以在 drop 方法中处理自己的资源；随后按类型规则清理拥有字段。drop 中不转移或显式释放 self 本身。含引用字段的值不因此拥有引用目标，清理该值也不等同于释放借用来源。

复制具有清理行为的值时，还需判断类型是否允许复制，以及副本各自拥有的资源。把资源句柄按整数复制并不能建立两个独立拥有者。

## 8.3 Closeable 与所有权转移

Closeable 表达关闭协议，实现它的结构体按不可复制资源处理。需要把资源交给另一个拥有者时使用相应移动规则；借用时保持来源存活。下例观察资源消费与关闭次序，关注拥有者而不是整数 id 的数值。

<!-- verify-book -->
```chali
struct Handle : Closeable
{
    int64 id;

    void close()
    {
        println("close {}", self.id);
    }
};

void consume(Handle handle)
{
    println("consume {}", handle.id);
}

void main()
{
    Handle first;
    first.id = 1;
    consume(move first);

    Handle second;
    second.id = 2;
    Handle third = move second;
    println("third={}", third.id);
}
```

```text
consume 1
close 1
third=2
close 2
```

## 8.4 手动分配的边界

new T 创建手动分配的存储，带构造参数时写 new T(args)。这与普通局部拥有值的作用域清理不是同一个接口：按对应所有权协议释放，不把裸存储误认为自动资源包装。

关闭、移动和释放会影响借用。已知的终结路径可能被编译器合并，但不应用重复释放来推断任意指针安全。原始存储、unsafe 与存活检查在第 23 章展开。

## 8.5 习题

1. 解释示例中 second 在 first 前输出。
2. 含引用字段的值是否拥有来源？
3. Closeable 值如何交给新拥有者？
4. 比较局部值与 new 存储的清理接口。

### 参考解答与验收要点

1. 退出动作按注册逆序执行。
2. 不拥有；来源需按自己的寿命规则管理。
3. 使用合法移动，并停止使用已移动的原绑定。
4. 局部拥有值按作用域清理，手动存储按相应释放协议处理。

## 8.6 番外：出了作用域的穿墙术

改写自《聊斋志异·劳山道士》。

邑有王生，慕仙道，负笈至劳山。道士授以一钥，曰：“此乃借用，室在则可用，室闭则当还。”生受教，练习数月，未曾读过一行生命周期说明。

一日辞归，求穿墙之术。道士曰：“汝将出作用域，室中器物不可随身。”生拍囊笑曰：“器物未取，位置已记，岂不轻省？”道士但笑，不复言。

归家，夸于妻曰：“我已学成零成本访问，虽隔千里，伸手可得。”妻不信，令试之。王生面壁，念念有词，将旧地址向前一送，只听砰然有声，额上坟起，如巨卵焉。

妻笑曰：“你那口诀，莫非叫无效句柄？”生怒，欲将借用改为拥有，发现构造函数不肯签字；又想再释放一次，池子也不肯。

道士后闻之，曰：“我早告汝，记住坐标，不等于买下房产。人既走出山门，莫拿昔日工位当永久服务器。”

王生于是将旧钥挂于壁，题曰“性能优化纪念”。每有客来，先说自己已学会安全编程，再请客人不要碰额头，尚在增量恢复。

### 技术对照

作用域结束、显式关闭和拥有关系转移会影响资源可用性。析构协议只处理由当前对象负责的资源；裸内存与宿主句柄仍需遵守各自接口约定。

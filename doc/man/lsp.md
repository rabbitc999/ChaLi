# LSP 增量提示与缓存

0.17.2 的 `magel lsp` 使用六个工作队列处理补全与签名、悬停与跳转、语义着色与大纲、工作区查询、宏预览、编译诊断。协议线程持续接收编辑和取消通知，输出按 JSON-RPC 请求编号配对；多个线程写出的消息经过锁保护，帧不会交错。[English](en/lsp.md)

## 修改与提示

VS Code 按实际文档版本及 UTF-16 编辑范围同步变化。不可变源码快照共享词法、行号、作用域和声明索引，同一版本只构建一次；标准库声明由所有提示线程共享。悬停与补全可以在完整编译诊断结束前返回。

修改后的编译诊断延迟 250 毫秒，连续修改只保留最新任务；保存时立即检查。新的检查取消旧检查，并结束仍在运行的编译子进程。客户端将编辑器取消通知转发为 `$/cancelRequest`，同一文档同一类提示的新请求取消旧请求。过期响应和旧文档版本的诊断不会覆盖当前编辑器内容；关闭文件会清空其诊断。

检查使用源文件的实际路径和标准输入源码，导入及包含文件通过未保存文档快照覆盖磁盘读取，不将编辑内容写回文件。诊断缓存记录源码、依赖、配置及锁文件的内容指纹；依赖发生变化会重新检查引用者。关闭未保存的依赖文件后，检查重新使用磁盘版本。文件监视通知覆盖 `.mgl`、`.inc`、`.toml`、`.lock` 的新增、修改和删除。

编译器保留完整类型及借用检查；快速提示与最终编译诊断仍有不同的完成时间。截图中的 `fn move() { a }` 会接管 a，随后读取 a 仍报 MGL1205。闭包捕获关键字有专门的悬停说明，MGL1205 定位到报错行的变量。

## 缓存目录及清理

缓存固定在 magel 可执行文件目录的 `build/lsp/`。若编辑器使用插件内嵌编译器，则位于插件的 `bin/build/lsp/`；若配置 `magel.path`，则位于该编译器旁边。工程所在目录不会决定此缓存位置。

| 子目录 | 内容 |
| --- | --- |
| `index/` | 文档声明索引；以编译器身份及源码指纹校验 |
| `diagnostics/` | 完整编译诊断及依赖指纹 |
| `preprocess/` | 现有增量编译机制产生的预处理与模块缓存 |

服务启动时和收到消息后的每十五分钟安排一次清理。删除七天未使用的普通文件；复用索引和诊断时至多每小时刷新访问时间。缓存总量超过 256 MiB 时先淘汰最旧文件，目标为 192 MiB，最近十分钟的文件受到保护，因此正在活跃写入的缓存可暂时超过额度。清理限定于 `build/lsp/`，跳过符号链接，不删除其外的 build 文件。

内存索引以估算占用 64 MiB、256 份为淘汰阈值，磁盘源码读取缓存以 32 MiB、512 份为阈值，均先淘汰较久未使用的记录。正在使用的快照保留到请求结束，单份超大文件也可以暂时超过阈值；这是缓存占用控制，不是进程总内存上限。缓存不可写或持久化记录损坏时回退分析，仍可提供提示。退出服务后可手动删除 `build/lsp/`，下次会重新生成。发行的 VSIX 不携带运行缓存。

## 验证

[tests/magel_lsp_performance.py](../../tests/magel_lsp_performance.py) 验证提示与诊断并行、UTF-16 增量编辑、未保存依赖及关闭回退、重复检查复用、重启恢复、损坏回退、七天及容量清理。[闭包诊断回归](../../tests/magel_lsp_lambda_capture.py) 覆盖捕获悬停及错误范围，[客户端取消回归](../../vscode/test/lspCancellation.js) 覆盖乱序响应和监听释放。

在同一台 Windows 机器的 600 个简单函数文件上，对比 0.17.1 与 0.17.2：首次悬停约 1.52 秒与 0.16 秒，重复语义着色约 0.70 秒与 0.02 秒。该测量针对语言服务请求，编辑器整体流畅度还受工程规模、扩展及机器负载影响。

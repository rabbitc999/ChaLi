# 38 Opcode 与标准库宿主记录

本页描述当前 `opcode`、数组与标准库宿主记录的存储协议。公开能力见[当前能力与实现边界](17-capabilities.md)，历史变更见 [CHANGELOG](../CHANGELOG.md)。

## 38.1 VM 核心与宿主胶水

String、BigInteger、BigDecimal、File、Process、List、Map、Set 由语言声明与宿主胶水协作实现。VM 维护通用句柄、存活管理和不透明记录协议；记录布局、比较、哈希和克隆回调由 `source/glue/` 中的实现提供。

内部 `ObjectKind` 包含 `NativeRecord`、`Obj`、`Arena`、`Closure`。这属于实现分类，不是允许应用把所有对象都当整数操作的公开接口。公开类型以标准库声明为准。

## 38.2 数组与字符串

- 字符串字面量带长度头，不附加终止零字节；`"hello"` 为 5 字节，`"你好"` 为 6 字节。相同内容的字面量可以合并为只读数据，运行时复制出的 String 各自独立。
- `T[]` 按值参数复制数组及其元素；`T[] &`、`T[] const&` 只读借用；`T[] mut&` 可写借用。
- 固定数组复制取得独立存储；可变数组引用的整体替换先物化新值，再清理原有元素和存储，支持合法的自赋值。
- 数组引用通过 `value[index]` 等语言操作访问，索引与对象存活检查仍然有效。
- `char[]` 到 String 的隐式转换进行复制；显式字节输出按相应 `uint8[]` 参数协议处理容量与失败。
- String 切片允许任意字节端点；普通下标与显式 UTF-8 接口各自遵守其边界规则，见[字符串方法](32-opcode-values-strings.md)。
- List 表达有序序列；Set、Map 的迭代顺序不作为稳定业务顺序使用。需要排序时显式选择排序操作。

## 38.3 创建、复制与销毁

`opcode` 声明体通过 `new = 创建函数`、`drop = 销毁函数`、`copy = 复制函数` 绑定宿主操作。复制函数应返回独立记录，不能仅复制内部拥有指针。

不可复制类型使用 `#NonCopyable` 并省略复制协议。编译器拒绝复制初始化、赋值、按值传参与返回复制；`move value` 按类型协议转移拥有关系。实现 `Closeable` 的结构体同样遵守对应的不可复制约束，见[声明与派生](29-declaration-sugars.md#closeable-与运算符推导开关)。

普通字段由语言保存、复制和销毁，不描述宿主对象的内存布局。结构体可以包含多个 opcode 字段，清理覆盖各自拥有的资源。

## 38.4 句柄、反射与宿主调用

`self.opcode` 仅在声明模块内可读，创建后只读；普通赋值、复合赋值与取得可写引用均受限制。应用使用类型的公开操作，不绕过这些接口猜测宿主布局。

`@Reflect` 按公开规则暴露类型及字段，内部句柄不进入用户字段表；LSP 同样隐藏胶水实现细节。反射可见不等于可以绕过所有权或复制限制。

C ABI 与 C++ 胶水使用一致的参数、复制、移动和回调约束。同步回调通过统一调用协议验证参数与结果，保留原始错误。运行时函数值带有上下文，不能将地址直接解释为机器函数指针。

## 38.5 维护与核对

修改宿主记录协议时，同时核对字段布局、元素步长、值复制、借用来源、资源销毁、迭代中结构修改及反射可见性。VM 与 AOT 共用的标准库胶水应保持同一资源合同。

对应回归包括数组形参、字面量合并、opcode 声明与资源、标准库存储和集合胶水测试；构建与验收范围按本次实际改动和用户要求执行，不将历史一次通过当作新产物的验收结果。

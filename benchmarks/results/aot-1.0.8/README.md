# ChaLi 1.0.8 LLVM AOT 跨语言基准

Windows x64、外置 LLVM 变体（clang 23.1.4 在 PATH 上）。内核与计时壳都用 LLVM `-O3`：ChaLi 侧 `chali aot --shared` 以 `-O3 -flto=full` 出动态库，`driver.c` 以 `-O3 -DNDEBUG` 编译。构建与正式计时隔离，性能阶段串行执行；每配置 5 次进程，每进程 5 个样本，取 25 个样本中位数（最小值与最大值同时在 [results.json](results.json) 里，供对齐跨会话读数）。源码、规模与校验值见 results.json，脚本见 `benchmarks/perf/run.py`。

被测编译器为 1.0.8 外置 LLVM 版，SHA256 `2b4c516e1df7c05ea4ac67a539d6f0472075de0fd8e818486a26173a6b178fd7`。同一份 ChaLi 计算函数用 `#export` 导出 C ABI，由统一 C 壳计时，进程初始化不计时；C 壳与 `chali aot` 产物用同一个计时函数和 `sink` 归并，只有被测函数不同。C／C++／Rust／Go 为原生机器码，Lua 5.5.1、Java 22（`-Xint` / `-Xbatch`）、Node 26、CPython 3.12 为各自的默认运行方式。

单位毫秒，越小越快。ChaLi AOT 相对 C 分别为 22.5、18.4、27.3、25.0、455.1 倍；相对 CPython 则在 `list` 上一度落后（411.435 对 57.961，约 7.1 倍），说明容器路径比标量路径贵得多。缺省 `chali run`（checked AOT，保留边界与存活检查）与这里的 unchecked 导出相差 0～8%，两行都在 [summary.md](summary.md) 里。

本机对长任务偶有调度尖峰：ChaLi 的 `int_chain` 一格最小 91.038、中位 97.047、最大 131.7，C 在同一格是 4.31～4.35。表里用中位数与 1.0.7 的报告保持同一口径；跨会话对齐时请看最小值（最小口径的标量四项为 21.1、17.5、26.4、24.2，与上一轮中位口径一致）。

这些结果只描述给定源码、规模和本机配置，不代表语言的一般速度。1.0.8 的内嵌资产只提供 AOT 路径，没有 VM 解释执行核可与 AOT 对照。

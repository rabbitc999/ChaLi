# ChaLi 1.0.11 系统 malloc 初始基线

本轮测量使用已提交的 `1fe80b3aeeb8212b8eb63d57986338bc8870a876`，测量时工作区干净。编译器 SHA-256 为 `ec9c5fb04011ea7a9a41742bdd9fa8d9f22170edb6fa33e9c1cdf76bcd1e800a`。这是优化前的正式基线，后续不改写这些成绩。

Windows 10 x64、AMD Ryzen 5 5600X、6 核 12 线程。ChaLi 使用外置 LLVM clang 23.1.4、O3/LTO、unchecked 导出和系统 malloc。参考配置为 GCC 11.2.0 C++17 O3、官方 Lua 5.5.1 默认 GC、Rust 1.98.1 `-O`。每配置 5 个进程，每进程预热后测量 5 轮，初始化和编译均不计入计算函数耗时。

全部跨语言校验值一致，`results.json` 保留每格 25 个原始纳秒样本、工具版本、构建命令及源码摘要。`hardware.json` 为实际硬件信息，`run.log` 为原始运行输出，`summary.md` 是脚本原始表格。

整数、浮点和小函数负载已达到或超过本轮 C++／Rust 参考；数组仍比 Lua 慢约 2.13 倍，动态容器约慢 65.4 倍。相对 C++／Rust，数组约慢 12.5–14.0 倍，动态容器约慢 418.5–491.7 倍。因此不能声明已全面超过 Lua 或已与原生语言运行效率持平。

`list_growth` 的所有实现均从空容器开始追加 400000 个相同数值，不预留容量，再做相同顺序归并。旧 `list` 中 C/C++ 预分配、Rust with_capacity 的参考继续独立保留，本轮不拿它们冒充相同增长方式。

后续优先分析数组访问的运行时检查边界和容器存储路径，同时检查不必要的值复制；任何检查合并或隐式移动均须保持存活、范围、借用和资源清理语义。正式成绩只来自未插桩产物，诊断计数与计时分别保存。

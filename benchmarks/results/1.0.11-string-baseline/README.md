# 默认 String 四项正式基线

负载与驱动定稿提交 a7f700b，工作区干净；实际 ChaLi 编译器源码 2609cf0，开发版本 1.0.11，编译器 SHA256 4c93c6af8222b7ff382517ef589378499f5032bb8a73ee8b3d88c97bb147c4fd。系统 malloc、Windows x64、unchecked LLVM AOT 默认 O3。完整代码和协议在 ../../strings/README.md，独立 bytes 模型、输入规模、计时命令及摘要在 results.json。

共 17 个配置单元，85 个进程，每进程五个性能样本，共 425 样本；各配置先逐次核对五个种子，所有校验值一致。首次测量 C++ O2、Rust 与官方 Lua 新负载，后续仅复用这些参考，不重复执行参考语言。既有十三项其他语言基线没有重测。Lua 拼接保留逐次 .. 与 table.concat，验收采用较快的 table.concat 中位数。

Lua 逐次拼接另为 25.6472 ms；保留其全部样本，不选较慢值制造达标。此结果对应标准 String API 的完整路径，涉及可变性、复制、结果包装、字节读取和查找算法差异；它不是四种语言共享一个机器内核。ChaLi 当前字符串路径距离目标很大，不能把枚举或纯标量已有成绩外推到字符串。后续优化应从生成代码及实际调用／分配证据定位，不把本表差距直接归因于单个环节。

每格的 25 个原始纳秒样本、最小／最大值、预热后的稳态中位数和进程输出均保存。初始化与构建不计时，工作函数中的分配、复制、子串及完整结果归并计时。没有 Java 字符串配置，不将已有 Java 接口 JIT 数据混入字符串比较。旧 1.0.7 String 记录保持原历史身份。全部优化及交付完成后，再把本轮代码、协议、结果及分析纳入 doc/12-performance.md 和英文对应页。

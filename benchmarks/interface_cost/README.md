# 接口运行成本分项测量

使用同一组类型、字段、方法和循环规模，分别改变接口建立、返回及传参方式。入口只生成测量程序，不修改编译器、运行时或接口语义，也不改写现有 18 项跨语言基准及其历史结果。

在仓库根目录运行，输出目录必须是 `build/validation/` 下的新目录：

```powershell
python benchmarks/interface_cost/run.py --chali ./chali-1.0.0-llvm-static-windows-x64.exe --out build/validation/interface-cost-new --runs 5
```

默认使用 malloc、unchecked、共享库及编译器默认的 LLVM O3/LTO。Windows 驱动默认使用锁定静态 SDK 的 GCC，LLVM IR 核对默认使用锁定外置工具链的 Clang；可用 `--cc`、`--clang` 指定实际工具。宿主 ABI 封送沿用编译器自己的工具选择，不把驱动的 SDK PATH 注入该构建。可用 `--allocator pool` 单独测量另一种分配器，不能混合两种配置的样本。

## 对照用例

| 用例 | 工作内容 |
| --- | --- |
| `select_control` | 计算选择索引和数值校验值，不建立接口 |
| `choose_discard` | 同样计算校验值，每轮另经 `choose` 返回接口并丢弃，不调用方法 |
| `mixed_concrete` | 每轮选择对象，直接调用具体结构体方法 |
| `mixed_bound_direct` | 循环前建立三个接口，每轮选择已有接口并直接调用 |
| `mixed_bound_param` | 与上一项相同，经 `invoke` 接收接口参数后调用 |
| `mixed_local_direct` | 每轮选择具体对象，在当前分支内建立接口并直接调用 |
| `mixed_return_direct` | 每轮由 `choose` 返回接口，局部绑定后直接调用 |
| `mixed_return_param` | 原多态工作函数的正文，包含返回、局部绑定和 `invoke` 传参 |
| `mono_concrete` | 始终直接调用 first 的具体方法 |
| `mono_bound_direct` | 循环前建立一个接口，每轮直接调用 |
| `mono_bound_param` | 与上一项相同，经 `invoke` 传参后调用 |
| `mono_local_direct` | 每轮从 first 建立接口并直接调用 |
| `mono_return_direct` | 每轮由 `chooseFirst` 返回接口并直接调用 |
| `mono_return_param` | 每轮由 `chooseFirst` 返回接口，再经 `invoke` 传参 |
| `original_poly` | 原多态源码单独编译，核对增加对照函数后的模块上下文影响 |

前 14 项位于同一模块，始终保留三种实现，避免把“只有一种实现可供分派”误当作固定接收者的唯一差异。mixed 组与原多态基准相同，三种类型的选择比例为 50% / 25% / 25%；mono 组固定使用 first；selection 组采用自己的低成本算术校验。只在同一组内比较计算结果。

`mixed_bound_*` 在分支中选择已有接口，`mixed_return_*` 则通过函数返回接口；这两种源码形状不保证产生相同的 LLVM 控制流。它们是可比较的使用方式，不能把两者的差值直接解释为某个运行时函数的独立成本。

## 构建、核对与采样

1. 分别构建合并模块、原模块及两者的独立插桩构件。
2. 使用 Python 的整数模型核对各用例的五个输入，保留所有校验值。
3. 对插桩构件各执行一次 seed=0，减去只初始化和清理的空程序计数；保留完整的原始操作点记录。
4. 对非插桩 LLVM IR 运行 O3，保存实际实现入口的正文和静态调用点，并确认正式构件没有所有权插桩入口。
5. 所有构建和计数结束后串行计时。默认 5 轮，每轮按固定随机种子打乱 15 项顺序，每个进程预热一次，再采集 seed=0..4 的五个区间。每项共 25 个正式样本，每个样本默认含 262144 轮工作。

计时包含一次 C ABI 导出调用及工作函数内的操作；初始化、字段设置、预热、打印、进程启动和收尾不计时。计时壳通过易变函数指针调用内核，并逐个核对正式样本的返回值，不只检查最终归并值。输入构造与方法均不修改接收者字段。

`results.json` 保留工具版本、编译器及构件 SHA-256、源码身份、全部命令、原始样本、每进程中位数、整体中位数、四分位数和执行顺序。`artifacts/` 保存实际生成的源码、C 驱动、LLVM IR、共享库、计时程序及插桩输出，`analysis/` 保存非插桩 O3 LLVM IR。失败记录不会被后续运行覆盖，应改用新的输出目录。

## 解释边界

- 插桩记录的是动态执行的 AST 操作点，不能当作实际 malloc 次数、对象表查询次数或存活字节数；插桩也可能影响 LLVM 的内联与消除，因此须结合非插桩 LLVM IR 阅读。
- 已有接口与具体类型调用的差异包含动态取址、检查及优化机会的变化，不只是一条类型比较的成本。
- `choose_discard` 专门观察建立后立即丢弃的路径，须确认非插桩构件仍保留相关操作，不能因源码有声明便认定它执行了分配。
- 各项差值不是可独立相加的函数耗时。不同操作组合可能改变内联、分支及地址复用。
- 混合负载只有三种实现，按固定周期切换；不能据此推断大量实现或随机类型次序下的分派成本。
- 用例只测全局对象的只读接口借用，未覆盖拥有接口值的深复制、接收者修改、接口重绑、闭包捕获或逃逸。
- 不按速度剔除样本，不复用旧性能数据；结果仅描述记录的机器、工具链、分配器和负载。此入口不测量编译器构建时间，也不代替完整语义回归。

需要调整规模时使用 `--iterations`；报告会记录实际值。完成测量后，入口会把所需构件复制到输出目录并结束所有子进程。按仓库约定再运行 `pwsh -File tools/clean_tmp.ps1` 清空根目录临时文件。

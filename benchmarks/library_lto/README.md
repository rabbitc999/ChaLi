# 预编译库 LTO 冻结对照

[English](README.en.md) · **简体中文**

这些是退役前同一 ChaLi 静态 LLVM 编译器的冻结记录。复现需使用该次冻结编译器及其实际构建源码身份。当前库包工具的范围见[库包说明](../../doc/44-library-packages.md)。

- [base.chl](base.chl) 提供单步整数依赖链与每次 256 步的批量函数；[bridge.chl](bridge.chl) 构成第二层预编译库。
- [call.chl](call.chl) 跨库调用 1,048,576 次；[bulk.chl](bulk.chl) 跨库调用 4,096 次，每次执行 256 步。二者按相同顺序执行相同运算，五个种子的结果由 Python 独立模型核对。
- [timing.c](timing.c) 复用原有单调时钟壳，不修改旧计时源；C 宿主调用普通原生标量导出。模块初始化、预热、结果归并、输出和结束不计入内核时间。

[驱动](../../tools/benchmark_library_lto.py) 要求自包含的静态 LLVM 编译器。示例：

```sh
python tools/benchmark_library_lto.py --chali PATH_TO_STATIC_COMPILER --compiler-source-commit ACTUAL_COMPILER_SOURCE_COMMIT --out build/lto-comparison-new
```

输出目录必须尚不存在，避免混合或覆盖历史记录。先用另一个输出目录加 `--verify-only` 可只运行功能核对。`--compiler-source-commit` 必须填写该编译器实际构建源码身份，不自动当作当前 HEAD。

驱动先复制并核对编译器、负载、计时壳和脚本，构建两层双实现库并删除工作区中的提供方源码。全部十个配置的 AOT、独立链接产物及冻结副本逐种子核对通过后，才保存 `baseline.json` 并正式计时。原始命令、输出、文件摘要、CPU 检查和样本写入本地 `results.json`；运行二进制及最后一轮构建产物留在同一交付目录，不提交 Git。

五种配置为原生／off、原生／full、bitcode／off、bitcode／full、bitcode／thin，统一使用 unchecked、O3、malloc、512 MiB 堆预算。所有组合先做功能预热，不在正式样本之间清理编译器及标准库缓存；串行执行并按固定随机种子轮换配置顺序。每次计时命令前在区间外读取 CPU，达到 40% 或读数不可用则等待，超出等待预算则保存 `deferred`，不声称测量完成。频率和亲和性不固定，CPU 记录只描述启动检查。

构建默认各三轮：原生消费对象编译、该对象与所选库的独立链接、完整 AOT 分别计时。独立链接的消费对象已经是原生机器码，完整 AOT 则可优化主单元；前两项之和不等于完整 AOT。运行默认每配置五个独立进程，每进程预热一次后测五个种子，共 25 个内核样本，统计中位数。`--build-repetitions`、`--runtime-processes` 可增加样本数，但不能低于三轮。

文档定稿后的新编译器与 VSIX 另做功能验收，不把冻结编译器的实测结果改标为新产物的数据。本目录不能证明所有程序、平台或 LLVM 变体都会受益，也不提供跨语言排名。

## 1.0.12 静态 LLVM 的冻结对照

2026-11-02 在 Windows 10 x64、AMD Ryzen 5 5600X（6 核／12 逻辑处理器）上完成一次冻结对照，使用内置 LLVM 23.1.4，C11 计时壳使用 GCC 11.2.0。被测编译器源码为 `66afd9adc30650649493c4d618638b84d1edbdae`，真实 SHA-256 为 `2bc93306c8b4825bcf1242a3e123b353a0bc76c310ab68fda396d03f20126d68`。以下数据只对应这份冻结字节；文档定稿后重建的编译器与 VSIX 另做功能核对，不重标数据。

正式记录共 66 个构建样本、50 个运行进程、250 个内核样本。每配置每负载的运行中位数来自五个进程、每进程五个样本；模块初始化、预热、结果归并和结束不计时。116 个计时命令逐次在区间外检查 CPU，启动读数为 1%～29%，均低于 40%；不固定频率、不绑核，不声称全程完全空闲。缓存经完整功能矩阵预热，正式样本之间不清理，配置顺序按固定种子轮换。

| 库选择／LTO | call 内核（ms） | bulk 内核（ms） | AOT DLL（字节） | 独立链接 DLL（字节） |
| --- | ---: | ---: | ---: | ---: |
| native／off | 10.2953 | 6.3899 | 4,886,528 | 4,886,528 |
| native／full | 11.0066 | 6.0879 | 4,877,824 | 4,886,528 |
| bitcode／off | 8.9765 | 6.5387 | 4,886,528 | 4,886,528 |
| bitcode／full | 1.1566 | 1.1423 | 4,876,288 | 4,886,016 |
| bitcode／thin | 1.1462 | 1.1523 | 4,876,288 | 4,886,016 |

两类负载本轮的 DLL 文件大小相同，表中 AOT 大小对应冻结运行副本，独立链接大小对应最后一轮真实产物。与 native／off 相比，bitcode Full／Thin LTO 的 AOT DLL 减少 10,240 字节；这些体积变化不代表通用压缩比例。

原生消费对象的编译中位数为 call 2,140.1 ms、bulk 2,065.1 ms，各取三轮。其余构建时间如下，均为三轮中位数：

| 库选择／LTO | call 独立链接（ms） | call 完整 AOT（ms） | bulk 独立链接（ms） | bulk 完整 AOT（ms） |
| --- | ---: | ---: | ---: | ---: |
| native／off | 590.2 | 2,425.6 | 610.5 | 2,428.4 |
| native／full | 617.8 | 2,585.4 | 585.6 | 2,378.8 |
| bitcode／off | 643.0 | 2,396.9 | 633.5 | 2,494.9 |
| bitcode／full | 611.8 | 2,397.1 | 604.2 | 2,428.6 |
| bitcode／thin | 631.0 | 2,381.5 | 636.7 | 2,520.6 |

编译和链接墙钟包含进程启动；独立链接还包含所选库 bitcode 的重编码／物化。独立链接使用已经生成的原生消费对象，完整 AOT 则可优化主单元，因此不能把对象编译与独立链接之和当作完整 AOT。原生库只开启主单元 LTO 没有稳定改善；ThinLTO 与 Full LTO 也没有统一的时间优势。这里只观察到这两个算术负载在库 bitcode LTO 下的内核收益，不推断其他程序、平台、分配器或 LLVM 变体。

原始命令、逐次 CPU 检查、种子结果、全部样本、摘要与运行二进制仅在本地交付目录 `build/independent-validation/` 保存，不提交 Git。`results.json` 的真实 SHA-256 为 `8c572e9c391001ccf5216a46ca6a7a9e2ea02019e073eaca926622177665f770`；独立核对确认 116 个计时命令成功、250 个样本校验一致、冻结文件字节未变。历史 1.0.10／1.0.11 及其他语言数据保持原身份，本轮未重测。

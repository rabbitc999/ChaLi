# C 宿主函数表

[main.c](main.c) 只包含公开的 `chali_abi.h`，由 C11 编译器编译。运行时库内部使用 C++，链接时需要匹配的 C++ 工具链；调用边界使用 C 结构、固定宽度槽和不透明句柄。

先完成相应构建变体，再在仓库根目录运行：

```text
python tests/chali_c_api_registry.py
```

脚本分别编译这个 C 宿主、注册事务单元和运行时服务单元，连接已经构建的运行时与宿主记录库。可以用 `--build-root`、`--cc`、`--cxx`、`--sysroot` 指定匹配工具链。它不重建编译器。

给脚本传入 `--chali 编译器路径`，还会构建真实 C 回调库及 ChaLi 原生共享库：C 函数表调用导出的 `calculate`，语言代码创建捕获偏移量的闭包，C 库执行同步跳板并返回拥有文本，语言适配完成复制和释放。测试核对结果 42、释放一次、模块结束及函数表释放，并分别覆盖 malloc／pool 与 checked／unchecked。相关 C 宿主和库代码见 `tests/fixtures/c_api_library_host.c`、`tests/fixtures/c_api_owned_callback.c`。

程序先创建函数表，再用自己的编译器生成 `ChaliAbiInfo`。模块描述中的三条入口分别演示整数加法、显式失败和非法返回类别。注册成功后可以修改原名称缓冲，因为表中保留独立名称副本；入口代码仍必须存活。

`add` 用带返回状态的参数访问器读取两个整数。下标或类别不正确时立即返回，避免在错误输入上执行后续操作。`ChaliAbiFrame` 的实参数组由调用方持有，例子中的两个槽是 20 和 22，正常结果为 42。

冲突模块先列出一个新名称，再列出已有名称。整模块注册失败后，新名称也不存在；分配失败同样回退，不改变已有回调状态。`fail` 写出的部分结果在失败后清零，非法返回类别也不能作为成功结果使用。封存以后可继续查询和调用，但不能再注册或移除；入口内部状态的并发责任仍由其实现承担。

这里的 `frame.runtime` 为空，因为加法不需要语言堆。String、逻辑内存、记录和语言函数值调用需要运行时提供的上下文，不能自行构造不透明句柄或用普通 C 指针替代。同步调用的缓冲和句柄不能在调用结束后继续借用。最后由 `chali_abi_registry_destroy` 释放拥有的函数表。

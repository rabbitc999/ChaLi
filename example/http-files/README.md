# HTTP 文件服务器

第 28 章的教学工程：从接收一条请求，逐步学习文本解析、路由、响应和多个连接的状态管理。

在本目录运行：

```sh
chali run src/main.chl -- 8080 public
```

用浏览器打开 `http://127.0.0.1:8080/`，再访问 `/notes.txt`。端口填 0 时由系统分配，实际端口写到错误流。第三个可选参数是接受连接总数；例如 `0 public 3` 在接受三条连接并收束后退出，便于自动测试。

程序启动时读取 index.html、notes.txt、style.css 三个明确列出的文本文件，每个最多一 MiB。请求只查询预加载路由，不用请求目标拼接磁盘路径；不存在的路由返回 404。根目录由本机用户管理，本例不是任意目录浏览器，也不提供二进制文件、TLS、持久连接、请求体、Range 或缓存协商。

支持 GET 和 HEAD，以及所示 HTTP/1.0、HTTP/1.1 请求形式；HTTP/1.1 要求单个非空 Host。每个连接处理一次请求后关闭；请求头最多八 KiB，读取和写入各有两秒期限。八个连接槽位由一个线程轮流推进，使用非阻塞 API，套接字不跨线程传递。超出槽位的连接关闭。

运行 `python tests/chali_book_projects.py` 验证请求、长度、中文正文、缺失资源、HEAD、错误方法、路径边界、分段输入、超时与并发等待。协议背景可查 [RFC 9112](https://www.rfc-editor.org/rfc/rfc9112.html) 和 [HTTP 语义](https://httpwg.org/specs/rfc9110.html)，本项目只实现书中列出的范围。

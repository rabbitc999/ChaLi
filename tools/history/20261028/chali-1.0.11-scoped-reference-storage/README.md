# 按函数精化纯标量引用存储

Windows x64 外置 LLVM 编译器 SHA256：`ee3c2b1dbb3db5e7eb8e8a950312d818a81dd3386c631a3c2531ec3e89147e59`。降级原来按全程序变量名准备引用存储，其他函数对同名 value 取址会导致当前未取址标量也装箱。本轮仅在无调用、无闭包的函数中，按本函数显式取址及带值退出需求精化整数／浮点／布尔／字符；拥有值、容器、函数值以及不确定调用继续走原保守处理。嵌套降级用作用域对象保存及恢复上下文，CHALI_NO_SCOPED_REFERENCE_STORAGE=1 可关闭。

这是生成存储所需的语义降级配套调整，没有改动文法、类型约束或借用规则，也未引入四元式优化或额外 IR 转换。重新生成了解析器并重建编译器。

variants.json 包含修改前及八组 malloc／pool、checked／unchecked、开关对照；真实取址、同函数遮蔽、标量泛型与字符串拥有值副本输出一致。纯标量探查的隐藏分配由一降为零，关闭后恢复一。六项特征仅运行 ChaLi 的无计时逐种子核对通过。

codegen.json 确认枚举及复杂结构体热循环的隐藏分配各由一变零，接口具体 Multiply.apply 的标量参数分配由一变零。此时尚未测量收益，不将减少一次静态调用点等同于已经达到性能门槛。

完整 AOT、同步原生回调、泛型单态化、引用值综合样例、引用组合、24 项资源生命周期回归通过；借用控制流 45 项拒绝／41 项允许及多诊断通过。引用值等旧脚本的临时 WORK 仅在验证进程中重定向至仓库 tmp，源码测试断言未改变。

验收限制如实保留：原 chali_reference_escape 专项的 allocated_payload 使用旧 new(&x) 写法，旧 d29e098 同样报语法错误。将输入修为当前 new Box(&x) 后，旧、新编译器又都接受，未满足该脚本期待的静态拒绝；测试源码已恢复原样，不以放宽断言获得通过。known-escape-input.chl 和对应旧编译器输出保留，整套严格专项不计通过。另对全部 27 个原始输入比较，退出状态及诊断码与修改前相同，见 escape-comparison.json。

scoped-codegen.log 是生成仅有导出的模块时遗漏 --shared 的验证器失败；final 日志补齐选项后通过，没有改动产品规则。

下一步仅测 ChaLi，其他语言全部复用原始数据。最终仍要求逐项快于 Lua且耗时不超过 C++ O3 参考 1.05 倍；最终性能文章待所有优化与交付验收完成后重写。

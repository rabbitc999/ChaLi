# 1.0.11：系统 malloc 分配器里程碑

这是 1.0.11 开发阶段的第一个功能里程碑，不是性能目标已达成的声明。此时尚未形成正式跨语言跑分数据。

## 实现

原生程序默认使用 `--allocator malloc`，`--allocator pool` 保留原池后端。`chali.toml` 的 `[aot] allocator` 接受相同取值，命令行优先。

系统模式下，运行对象通过系统 malloc/free 分配有效载荷，语言字节堆也为每个分配单独申请系统存储；没有继续将它们细分到连续字节缓冲区。存活逻辑地址继续携带独立身份，索引记录实际物理存储。预算、范围收窄、释放失效和零初始化保持生效。跨线程执行继承模块所选后端。

## 验证范围

实际验证宿主为 Windows x64，GCC 11.2.0，外置 LLVM clang 23.1.4。

- `tests/chali_system_arena.cpp`：4096 字节预算、过度对齐、无效和重复释放、活跃范围、4 个线程各 2000 次分配释放，检查统计归零。
- `tests/chali_malloc_heap.cpp`：系统／池后端分别核对 1000 轮零初始化、标量读写、范围检查、过期身份和重复释放，以及范围收窄、重置与析构。
- `allocator-samples.json`：9 个实际存在的样例、两种分配器，共 18 组。对照反射、闭包、结构化数据、图、树、消息、通道、看门狗和字节文件，输出与预期一致，错误输出为空；同时核对 LLVM 模块中的分配器选择常量。
- `aot-final.log`：完整 AOT 专项重新通过，包含 C 双向调用、列表、opcode 创建／复制／销毁、共享库全局初始化和清理，以及新增的具名 `#export` 整数／浮点 ABI 适配独立编译与执行。

底层单测以 C++17、O2、pthread 编译，并保留断言。`native-unit-tests.log` 记录两个真实可执行文件的退出码。

首轮计时内核构建发现公开头文件错误依赖 `ast.hpp`，已改为 AST 前置声明，并在真正访问 AST 的实现和驱动中显式包含 `ast/ast.hpp`。失败诊断和修复后的预检日志均保留；失败轮没有产生跑分成绩。

静态 LLVM 和跨目标完整链接尚未对本里程碑重新验收，不能沿用 1.0.10 的结果声称通过。它们仍属于 1.0.11 后续交付范围。

## 后续基线

正式基准使用 1.0.11 系统 malloc、5 个进程各 5 轮，比较 Lua 5.5.1、C++ O3 与 Rust 优化配置。保留原始纳秒样本、源码摘要和实际工具版本。新增 `list_growth` 使全部参考实现都从空容器动态增长，原来的预分配 `list` 参考和历史测量保持独立。

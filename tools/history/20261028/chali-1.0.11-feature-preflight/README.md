# 语言特征负载无计时预检

当前外置 LLVM 编译器 SHA256 为 `af3bbacec00aa5d2fc9858f517b6e99f3d8c765c226fee09076bf4e9632b6d3c`，源码来源 `6c9cc3e`。

initial-full-verify.json 记录六项负载、15 个语言／负载组合，种子 0–4 与独立整数模型逐项相同。预检使用 --verify，不产生 rep 样本，也不启动 Java 性能热身，因此没有在此进行或重复正式参考评测。

随后发现初始枚举选择公式退化为几乎只访问 Pair；修订 ChaLi、Rust 和模型为使用归并值高位，final-enum-verify.json 记录修订后的枚举逐种子核对与四变体分布，每种变体均有超过一万次访问。其他五种负载未改变，不采用退化公式进行正式性能测量。

初次语法探查发现 else if 应写 elif；派生接口视图不会隐式匹配父接口形参，负载改为通过派生接口调用继承的方法，ChaLi 与 Java 保持一致。未修改前端。第一次驱动使用未支持的 --version 查询失败，改为读取实际编译器 LSP 初始化版本，日志均保留。后续驱动只增加编译器源码提交的独立元数据字段，不改变工作负载。

本目录只证明构建与语义核对；正式 5 进程 × 5 轮基线及 Java 热身／C2 证据随后另存。其他语言正式测一次，后续默认 --reference 只运行 ChaLi。

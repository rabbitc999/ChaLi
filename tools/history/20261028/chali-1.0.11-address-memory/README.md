# LLVM 地址原语、看门狗与 Arena 删除验收

当前 Windows x64 外置 LLVM 开发编译器 SHA256：`c56b7d2545e2a41bc40c2d9752edcd32cfa816d4ae87c1af63ea517d6b020b09`。未宣称本轮静态 LLVM、跨目标或安装包已验收，也尚未据此宣称性能收益。

地址原语在 LLVM 中直接核对原子映射代次及完整访问范围，命中后直接计算物理地址，未命中走原有共享堆检查。分配、释放、收窄、重置、销毁使旧视图失效；模块寿命内的代次地址覆盖不同宿主线程先后调用，代次耗尽后永久回退。既有内存访问 ABI 保留。

`address-final.json` 为本编译器的 16 组 malloc／pool、地址原语开关、裸指针／原始存储／释放后访问／块末访问对照；所有输出及错误符合预期，生成的 LLVM 模块中对应开关的调用点已核对。`lifecycle-final.json` 在每种分配器下通过同一持续存活宿主线程完成 64 轮初始化／导出调用／销毁。底层地址视图、malloc 堆及系统分配器单测均保留断言，通过日志在 heap-address、malloc-heap、system-arena 文件。

删除 std::watchdog、Arena 类型及其宿主登记和对象状态，当前示例使用 new 与作用域释放。内部 malloc／pool 分配器保持可选；分配失败记录独立于重启机制。`removal-contract.json` 核对旧 API 实际使用被拒绝，以及两种分配器的 1 MiB 预算对 16 MiB 请求明确失败。未使用的模块导入由现有前端接受，因此删除入口测试实际调用旧函数，不以未使用的 import 作为断言。

完整 AOT、同步回调、线程等待、标准错误接口专项通过。八个 checked run／AOT 样例、四类陷阱与显式 --step-limit 空循环通过。opcode 值语义专项通过 28 项定向／抽样及 1050 条字符串断言；其容量测量仅作该测试诊断，不用于正式跑分。新增旧看门狗调用反例另由 removal-contract-extra.log 通过。

中文 Markdown、LaTeX、PDF 同步。59 个书稿完整程序及 6 个附录失败示例通过；PDF 共 301 页，目视核对资源章节及附录表格，两个 PNG 保留抽查。标准库参考生成检查为 43 模块、1223 函数重载，结构检查通过。

保留诊断历史：先前地址原语开发编译器 `540d49a…` 的扩展运行时验证在旧看门狗空循环上超时；旧 `8f218d0` 同样缺少循环 tick，watchdog-before.ll／loop.txt 为证据。修复后旧模块验证曾通过（`0a79016…`），随后根据用户要求删除该模块，最终以显式 --step-limit 验证控制点。早期 address-* 日志属于这些开发快照，不当作当前编译器的完整验收。

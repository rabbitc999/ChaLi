# String 持久容量缓冲区专项验证

2026-10-29。实际编译器 SHA256：`4ab902c1e87c4ec808deca7bc808a2cf6e5fb68f8d0164be91e11fa48035721d`。

String 使用稳定描述符，短字符串初始内联容量 16 字节；长字符串及扩容使用独立数据块。ChaLi 实现几何增长、追加、清空和截短，原生边界兼容旧字符串读取并明确释放字符串拥有的块。普通 releaseMemory 保持原始块行为；新增宿主辅助方法不改变虚表。默认 String、结构体字段、固定数组元素和 new String 配套初始化，拥有型 String 指针在 drop 时释放内容及指针槽。

最终验证日志以 matrix-heap-final、各 regression、catalog-delivery、links-final、runtime-check 和 final-evidence 为准。String 矩阵为八种配置、六类运行错误及六类编译拒绝；还覆盖集合容量、String 自举、内存原语、完整 AOT 专项、资源生命周期、集合胶水、Map 迭代器、同步回调、泛型、借用流、数值自举、实验容器、AOT 运行时与线程等待。API 目录检查及 51 页文档链接检查通过。ci.sh 语法检查通过，新专项已注册，但最终全量门禁尚未执行。

max-capacity-o3.ll 为实际 LLVM O3 函数摘录，容量查询正常路径无调用。final-evidence 中包含 rawSize、字节原语、哈希模型和文档示例的实际返回值。全部专项均为当前实现功能验证，不构成性能达标声明；本提交之后另测 ChaLi 字符串，外语基线不重测。

保留此前失败日志：默认空值初始化缺失、断言消息递归构造、self 地址层次错误、测试打印格式和诊断语言不匹配、拥有型 String 指针漏释放均已分别修复；这些早期记录不冒充最终编译器验证。旧失败配置目录与最终 w5sa5_ne 目录明确区分。未保存临时 Python 验证脚本及庞大的完整 LLVM IR、二进制产物。

分配器预算推导是当前实现的容量上界；池元数据、布局及极端大于有符号整数范围的预算一致性仍需单独核对，未宣称已完成精确最大可兑现分配量。
